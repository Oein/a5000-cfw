### RE 완료 → 기기 복귀 시 적용 대기 (2026-11-19)
- **cached-mapping (Recipe A, 구현·커밋됨 `e10d1e0`, opt-in)**: OSD 버퍼를 `/dev/mem`(strongly-ordered 8MB/s) → **`/dev/stream`(write-combining)** + present당 `__sync_synchronize()` 1회. ⚠️교정: "캐시드"가 아니라 **write-buffered**, dcache-clean/GRM lock 불필요(`docs/RE/display/0006`). 마커 `/android/a5k/vdf_stream`로 활성 → 기기 A/B 후 기본 전환.
- **MENU 안 뜸 + OSD 비촬영모드 노출 = 같은 뿌리** (`docs/RE/display/0005`): 순정 MENU/DISP(23)/재생(21)은 **FbContainer 레코드(BMP@+28)** 로 ch53 제출 → 우리 swap(SenserIf +20 전용)이 no-op. 수정: ①passthrough에서 **DISP 소비**해 funcMode 23 진입 차단 ②보강 `mgr+100`=1로 위젯 present만 끔. → **기기서 funcMode-23 hook 계측 1회로 +28/+16 확정 후 적용.**
- **행별 dirty present (배포됨, v5·sweep복구 e10d1e0)**: 보완재. 단독으론 DRAM 스캔 20ms floor 못 넘음 → cached-mapping이 본 해결.
- **imaging 아키텍처 확정** (`docs/RE/imaging/`): av-cam.bin이 영상 전담, Linux는 OSD(ch53)만. **route-b가 천장**(Sony 이미징 재구현 비현실). custom-OS/GPU 방향 종결.
