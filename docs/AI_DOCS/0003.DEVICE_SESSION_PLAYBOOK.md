# 0003. DEVICE SESSION PLAYBOOK — 기기 복귀 시 1회 세션으로 걷어낼 것

> 기기가 없을 때 쌓은 RE의 **실기 종속 미확정**과 **RAM-only 적용 항목**을 한 세션에 효율적으로 처리하기 위한 체크리스트. 모든 작업은 **벽돌 위험 0**(플래시 미기록, `/android/a5k` tmpfs, 가역). 상태 변경 전 사용자 확인.
>
> 운영 제약: 라이브뷰/AF 진입 시 Wi-Fi(telnet/adb) 끊김 → **로그는 tmpfs에 쌓고 비-라이브뷰 복귀 후 수집**([network 0001](../RE/network/0001.%20af-wifi-drop.md)). 배포: a5kinproc.so+a5kinject를 `/android/a5k/`에 push → `a5kinject <im.elf pid> <so> c37cc`. 리부트 시 tmpfs 소실→재배치.

최종 업데이트: 2026-11-21 (읽기-전용 실기 세션 반영)

> **실기 접속 레시피(검증됨, 2026-11-21):** Mac 인터넷공유(`bridge100=192.168.2.1`)에 카메라가 붙으면 `192.168.2.12` 할당, telnet:23 OPEN. 명령: `CAM_HOST=192.168.2.12 python3 -I packages/tools/scripts/cam.py '<cmd>'`. (주의: 아이폰 핫스팟이면 Mac=USB테더(192.0.0.x)·카메라=Wi-Fi(172.20.10.x)가 **브리지 안 됨** → 둘을 같은 세그먼트로.) busybox 매우 최소(ps/awk/head/free/top/chrt 없음 → `/proc` 직접 읽기).

## A. 바로 적용 (RAM-only, 저위험, 즉시 가치)

1. **RAM — im.elf 보호 + 회수** ([memory 0001](../RE/memory/0001.%20ram-footprint-and-trim.md), [[ram-oom-structure]]):
   - 주입 직후 `echo -17 > /proc/<im.elf pid>/oom_adj` (OOM 시 카메라가 먼저 죽는 구조 방지 — 최우선).
   - 주입 직후 `rm /android/a5k/a5kinject` (−0.45MB).
   - 주입 직전·MENU 진입 직전 `sync; echo 3 > /proc/sys/vm/drop_caches` (+48~52MB, direct-reclaim stall 완화).
2. **present 반응성 — Recipe A A/B** ([display 0006](../RE/display/0006.%20cached-osd-mapping-recipe.md)):
   - `/android/a5k/vdf_stream` 마커 켜고 `/dev/stream`(write-combining) 경로 측정. 전체프레임 ~75ms→수ms 기대. 양호하면 기본 전환. (GPU는 불필요 — [display 0007](../RE/display/0007.%20gpu-render-manager-handoff.md) §5.)
3. **모니터 밝기 배선** ([settings 0001](../RE/settings/0001.%20monitor-brightness-apply.md)): `cvpdmGroupWrite(120, raw)` — 현재 AM_LOCAL(앱전용) 버그 수정.

## B. 선-계측 후 적용 (측정 1회 → 수정)

4. **MENU 안 뜸(funcMode 23) 근본원인 재확정** ([display 0005 정정](../RE/display/0005.%20osd-submit-paths-per-view.md), [display 0007 §7](../RE/display/0007.%20gpu-render-manager-handoff.md)):
   - "+28 vs +20" 가설 폐기됨(경로 B도 phys가 +20). 기존 hook instrument로 **funcMode 23의 OSD 제출 레코드 덤프**(지오메트리/개수/isPanel/bpp/더블버퍼 latch) → 후보 (i)(ii)(iii) 중 확정.
   - 수정(원인 무관 유효): passthrough 입력훅에서 **DISP 소비**로 funcMode 23 진입 차단 + 보강 `mgr+100`=1. DISP 소비는 표시보조 DISP 사이클([display 0008](../RE/display/0008.%20metering-and-display-aids.md))과도 연결.
5. **AF→Wi-Fi 기아 확정 후 완화** ([network 0001 §7](../RE/network/0001.%20af-wifi-drop.md)):
   - tmpfs에 100ms 주기 로깅(mmc1 CPU별 IRQ·ath0 RX/TX·ksdioirqd/kworker·MemFree·dmesg·wpa_cli), 메뉴→라이브뷰→AF×3→메뉴. mmc1 IRQ 증가+ath0 RX 정지면 기아 확정.
   - 확정 시: mmc1 IRQ `smp_affinity`→CPU3, ksdioirqd FIFO 50~60 승격(chrt 정적 헬퍼), telnetd/adbd FIFO 2~5, `min_free_kbytes` 1024~2048. 효과 A/B.

## D. 관통 결론 (전 기능 RE, 아키텍처)

- **직접 구동 예외**: 스마트폰 리모트(orb-server Camera Remote API :10000, 심볼=공개 SDK 스펙) ([connectivity 0001](../RE/connectivity/0001.%20wifi-nfc-usb-apps.md)).
- **유일한 근본 한계**: 새 룩/이펙트 주입 불가 — Creative Style·Picture Effect·BeautyEffect·RAW현상이 Artfilter/ColorMode 룩테이블 + av-cam ISP Sony 독점(ZV-E10의 FL/VV 한계와 동일 범주).

## E. 읽기-전용 세션 로그 (2026-11-21, 사용자 부재·실기 무접촉)

사용자 "실기 안 건드림, 나 없이 가능한 것만"에 따라 **순수 `/proc` 읽기만**(주입·쓰기·모드변경·라이브뷰 진입 전부 회피). 완료:

- **✅ B5 정적 절반 (AF→Wi-Fi 기아)** — [network 0001 §9](../RE/network/0001.%20af-wifi-drop.md). 4코어, im.elf SCHED_RR 71개(6~123) > ksdioirqd FIFO1 > ath6kl/htc_rx NORMAL, WiFi IRQ221=CPU0(이미징 IRQ215 150만회 동거). 기아 기구 하드웨어 확정. **남은 B5 = 라이브뷰 부하 동적 A/B**(접속 끊김 → tmpfs 로거 자기완결 기록 후 사후 회수, 대면 세션).
- **✅ C-RAM 일부 (OOM 구조)** — [memory 0001 §9](../RE/memory/0001.%20ram-footprint-and-trim.md). MemTotal 175.8MB, im.elf RSS 47MB·oom_adj=0(유일 비보호), Android 전부 −16. OOM 1순위=카메라 확정. nmemories.tweak 21.5MB 상주.
- **✅ 부팅 cmdline 실증** — [boot 0005 부록](../RE/boot/0005.%20warm-boot-restore.md). `console=ttynull`·`warm.mode=2`·`wbi_memclr=0x800210e8`·`pm.resume=0x80021054`·carve-out·`manage.irqd=129`·`page_alloc.minkb=256` 전부 보고서와 일치.
- **현재 실기 상태**: warm 재개 구동, **a5kinproc 미주입(순정)**, OpenMemories Tweak만 상주. 원시 덤프 `packages/data/re/device/`.

**다음 대면 세션에서 바로**: A(즉시적용) 전부 + B4/B5 동적 + C 나머지(GetParameters 덤프, 쓰기 수반). 쓰기·주입·라이브뷰는 사용자 입회 시에만(끊김 시 물리 재부팅 필요).

### E.1 디스플레이/HDMI 제어표면 + autostart 상태 (2026-11-21 실기, 읽기전용)

- **/dev 디스플레이 노드**: `stream`/`stream2`(패널 OSD/비디오 쓰기), **`hdmi`·`hdmi_external_tx`(HDMI 출력 TX)·`hdmi_input`**, `cec`, `backup`, `console`/`ttycons`/`vcs4-6`. → VPH가 **패널(/dev/stream)과 HDMI(/dev/hdmi_external_tx)를 분리된 ioctl 노드로 구동**(HDMI+LCD 동시성 RE의 제어표면 — [display 0009] 참조).
- **모듈**: `hdmi`(117KB, cec 참조)·`cec`(53KB)·`grm_gles`·`grm_ma`·`dmm`(2.4MB)·`stream`/`stream2`·`liro`(50KB).
- **autostart 미무장 확정**: `/setting/mode` 비어있음(dmode 없음), `/setting/env.txt` 없음 → **LD_PRELOAD 자동실행 미설정**. im.elf에 a5kinproc 미주입 = **순정 구동**(+ OpenMemories Tweak 상주). [[clean-boot-autostart]].
- **우리 UI 에셋 영속 확인**: `/setting/a5k/assets` = font_ui 7종 **~5.64MB** + icons 838KB + font_osd 159KB ≈ **6.6MB**([memory 0001] 트림 타깃 = 풀사이즈 UI 폰트 7종, 실파일로 확증).
- HDMI 물리연결 불가(사용자) → "HDMI 연결됨" 실기 관측은 향후 세션 과제. 원시: `packages/data/re/device/display_hdmi_setting_probe.txt`.
