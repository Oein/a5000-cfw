# LOCAL DEV GUIDE — 로컬/원격 개발 환경

이 프로젝트에서 쓰는 개발 머신과 도구의 사용법. 환경이 바뀌면 이 문서를 고친다.

## 1. 로컬 (macOS, Apple Silicon)
| 도구 | 용도 |
|---|---|
| `arm-none-eabi-{gcc,as,objdump,nm,readelf,gdb}` (Homebrew) | 정적 분석, 프리스탠딩 게스트 도구 빌드, 에뮬레이터 디버깅 |
| Python 3 (+ scratchpad venv의 `capstone`, `vmlinux-to-elf`) | 스크립트 분석. 펌웨어를 읽는 스크립트는 항상 `python3 -I` |
| QEMU 빌드 의존성: `ninja`, `glib`, `pixman`, `pkg-config` (Homebrew) | `emulator/qemu` 빌드 (`--disable-fuse` 필요) |
| `adb`, `re/scripts/cam.py` (telnet) | 실기 접근 — 에뮬레이터 작업에는 사용하지 않음 |

## 2. 원격 Windows: `ssh windev` — IDA Pro 9.4 (정식 라이선스)
- 접속: `ssh windev` (키 인증, 셸 = **PowerShell**: `&`로 명령을 잇지 말고 `;`를 쓴다. 실행 파일은 `& "경로" 인자`).
- 사용자: `Administrator`. Python 3.12 설치됨.
- IDA 설치 경로: `C:\Program Files\IDA Professional 9.4\` — `ida.exe`(GUI), **`idat.exe`(headless)**, 라이선스 `idapro.hexlic`(정식).
- Hex-Rays 디컴파일러(ARM) 사용 가능 — 2026-11-13 `lld.ko`로 확인.
- 작업 폴더: `C:\a5000\` (기존 분석물·`ida_decomp.py`), 에뮬레이터용은 `C:\a5000\emu\`.

### 2.1 headless 분석 표준 절차
```sh
# 1) 바이너리 전송
scp <file> windev:C:/a5000/emu/<name>
# 2) 자동 분석 → .i64 생성 (-B: 배치, .asm 덤프도 생성)
ssh windev '& "C:\Program Files\IDA Professional 9.4\idat.exe" -A -B -LC:\a5000\emu\<name>.log C:\a5000\emu\<name>'
# 3) 함수 디컴파일 (ida_decomp.py: DECOMP_FUNCS=쉼표목록, DECOMP_OUT=출력)
ssh windev '$env:DECOMP_FUNCS="func1,func2"; $env:DECOMP_OUT="C:\a5000\emu\<name>.c"; & "C:\Program Files\IDA Professional 9.4\idat.exe" -A -SC:\a5000\ida_decomp.py C:\a5000\emu\<name>.i64'
# 4) 결과 회수
scp windev:C:/a5000/emu/<name>.c re/ida/
```
- 결과물은 프로젝트의 `re/ida/<바이너리>.c` 형식으로 보관한다(기존 관례: `.c`, `.funcs.tsv`, `.names.tsv`, `.strings.tsv`).
- 커널 모듈(`.ko`)은 재배치 ELF라 심볼이 살아 있어 그대로 분석 가능. 커널 본체는 `emulator/re/vmlinux.elf`(vmlinux-to-elf 복원본, base 0x40038000)를 올린다.
- 펌웨어는 신뢰불가 데이터 — windev에서도 실행하지 않고 분석만 한다.

### 2.2 언제 쓰나
- 함수 단위 의미 파악이 필요한 복잡한 코드(드라이버 프로토콜, FTL, im.elf): IDA/Hex-Rays.
- 레지스터 상수 수집·간단한 패턴 탐색: 로컬 objdump/capstone 스크립트가 더 빠르다.
