# 0001. 초점 시스템 — 센서에서 OSD까지, 그리고 route-b 통합

- 상태: **derived**(viewUnified/libObj/libScalarDaemon 정적 RE + SDCom 표) + **observed**(일부 route-b 실기/에뮬) + **inferred**(엔진 내부 동작 순서).
- 좌표/근거: SDCom 표 `packages/data/re/scalar/`, PARAMID/Wrapper 심볼 `packages/data/re/ida/{viewUnified*,libObj.so}.*`, route-b 배선 `packages/custom-binary-app/platform/a5000-inproc/camera_inproc.cpp`. 모두 gitignore 원본. 본 문서는 **동작·id·오프셋만**.

세 개의 번호 네임스페이스를 끝까지 구분한다([sdcom/0003 §4](../sdcom/0003.%20camera-parameters-and-shift-commands.md)):
1. **SDCom param id**(256~388) / **SDCom message id**(0x10xx) — 외부 휘발 제어면.
2. **CVPDM eventId** — `CmnViewProcessDataMgr` 그룹 번호(순정 Wrapper getter/setter가 쓰는 뷰 모델 슬롯). 메뉴 트리 `13=`과 1:1.
3. **엔진 PARAMID**(`PARAMID_*`, libObj MWF ObjMsg) — av-cam/MWF 내부. SDCom/CVPDM에 안 뜨는 것들(피킹·MF어시스트·포커스확대 좌표).

## 0. 한 줄 지도

```
외부 제어면                뷰 모델면                      엔진면                          출력
SDCom 0x1003 param265 ─┐   WrapperFocusMode             PARAMID_FOCUS_MODE          콘트라스트 AF
ChangeAfMf 0x1025      ├─▶ (CVPDM eventId 13) ───────▶  PARAMID_FOCUS_MODE_ACT  ──▶  렌즈 모터 구동     ─┐
메뉴노드 FocusMode  ───┘   getFocusMode/setFocusMode                                   (lens communicator) │
                                                                                                           ▼
반셔터 S1(0x1F1) / AutoFocus 0x1006 ─────────────────▶  AF 통계(RC 이전 추출) ─▶ FocusDone 0x1301/0x2001 ─▶ 엔진 OSD 초점프레임(합초)
                                                                                      │
피킹: PARAMID_PEAKING_* ─▶ ObjRenderer SetPeaking ─▶ OSAL VDF 서비스 ─────────────────┴─▶ 영상평면에 에지(엔진 렌더, ch53 아님)
```

**핵심 구조 결론**: 초점의 *데이터 평면*(AF 구동·합초 판정·확대 영상·피킹 에지)은 전부 **엔진(av-cam/VDF)** 이 소유한다. 뷰/앱은 **모드·영역을 지시하고 상태를 읽어 아이콘/프레임을 그릴 뿐**이다. 이는 [imaging/0003 §3](../imaging/0003.%20sdcom-imaging-control.md)의 "외부는 영상 위에 OSD만 올린다" 모델과 일치하고, route-b의 OSD-passthrough 아키텍처(memory `route-b-stock-osd-passthrough`)의 초점판 근거다.

## 1. AF 모드 전환 (AF-S / AF-C / DMF / MF)

### 제어 id
- **CVPDM eventId 13**(메뉴 트리 `14=`)이 정규 경로. raw enum: `0=AF-S 1=AF-A 2=AF-C 3=AF-Z(adv.cont) 4=DMF 5=SemiManual 6=MF`. 실기 PROVEN: MF=raw 6([route-b-device-findings](../../AI_DOCS) memory).
- 순정 setter/getter: `WrapperFocusMode::setFocusMode / getFocusMode`(viewUnified2; raw→wrapper 변환 `sub_21F666`). 메뉴노드 `cmnViewSettingNodeRootFocusMode`.
- SDCom 대체면: `CameraSetParameters 0x1003` param **265 focusMode**, 그리고 AF↔MF 전용 `CameraChangeAfMf 0x1025`(param 38). 단, SDCom set은 엔진에 바로 가는 게 아니라 뷰/엔진 상태와 레이스가 있어([camera/0002]) 정규 경로는 CVPDM group13.
- 엔진 PARAMID: `PARAMID_FOCUS_MODE`, `PARAMID_FOCUS_MODE_ACT`(실행 확정), `PARAMID_PUSH_AUTO_FOCUS_MODE`(DMF 중 반셔터 AF). `PARAMID_HYBRID_AF_MODE`도 존재하나 a5000은 콘트라스트 전용이라 비활성 추정.

### 엔진 메커니즘
- **AF-S**: 반셔터 시 콘트라스트 AF 한 번 수렴→락. **AF-C**: 수렴 후에도 피사체 추종으로 렌즈 재구동. **DMF**: AF-S 합초 후 링 수동 미세조정 허용(합초 상태에서 MF 전환). **MF**: AF 미구동, 렌즈 위치는 링→lens communicator 보고만.
- 모드는 av-cam 측 AF 통계 사용 여부/루프 지속 여부를 바꾼다. AF 통계는 RC 리사이즈 **이전** 단계에서 추출되므로 ch51 라이브뷰 버퍼와 독립([imaging/0001 §2]).

### OSD 경로
- `ACT_IconFocus`(엔진 OSD 위젯 accessor)가 모델을 읽어 좌상단 초점모드 아이콘을 그린다.

### route-b 판정 — ✅ 읽기 + 설정
- **읽기**: `cvpdmGroupRead(eventId 13)` → raw → UI. 실기 PROVEN(MF=6). 단, 모델 읽기는 라이브뷰 활성(camModelReadable) 게이트에 묶임([camera/0002]).
- **설정**: 다른 half(af-s/af-c vs mode)를 보존하려 현재 raw를 읽어 recombine 후 `groupSetChecked(13, raw)` + read-back. 에뮬 round-trip 검증, 실기 apply는 device-seal(코드 배선 완료, camera_inproc.cpp `setSetting`).

## 2. AF 영역 (Wide / Zone / Center / Flexible Spot)

### 제어 id
- **CVPDM eventId 187** = AF영역 **타입**. raw: `0=Wide 1=Zone 2=Center 3=FlexSpot`(+4~6 expand/semi 변형). 순정 `WrapperFocusArea::getFocusArea`(vtable[3] read) / `setFocusArea`(vtable[14] set). 메뉴노드 `cmnViewSettingNodeRootFocusArea`.
- 플렉시블 전용: `CmnViewFocus::requestModelExecuteSetAfAreaModeFlex(int,int,bool)`, `PAS_FocusWindow::setFocusAreaMode(FocusAreaMode)`.
- 엔진 PARAMID: `PARAMID_FOCUS_AREA_MODE`, `PARAMID_FOCUS_AREA_ALT`, `PARAMID_FOCUS_AREA_LOCAL_NUM`, `PARAMID_FOCUS_AREA_LOCAL_SEMIWIDE`, `PARAMID_FOCUS_AREA_SEMIWIDE_NUM`.
- SDCom 대체면: param **271 afAreaModeAlt**, **370 afAreaFlexibleSpotSize**. 조회 `CameraGetFocusAreaInfo 0x1029`(param 70).

### 엔진 메커니즘
- 영역 타입은 AF 통계 적분 창(전체/존/중앙/점)을 선택한다. AF 통계는 av-cam ISP 단계에서 영역 마스크로 수집→콘트라스트 피크 탐색.

### OSD 경로
- AF 영역 프레임은 엔진 OSD `PAS_FocusWindow`가 그리고, 아이콘은 `ACT_IconAfArea`.

### route-b 판정 — ✅ 타입 읽기+설정 / ⚠️ 라벨 device-seal
- 읽기/설정 모두 group187로 배선(camera_inproc.cpp `wrapFocusArea`/`focusAreaUiToRaw`). 에뮬 round-trip 가능. raw↔라벨(Wide vs Multi 등)은 실기 미확정 `[?]`.

## 3. 플렉시블 스팟 위치(좌표 이동)

### 제어 id
- 좌표 읽기 슬롯: **CVPDM eventId 188**(getFocusArea의 좌표 경로; 타입 경로 187과 분리). 변환식 별도.
- 엔진 PARAMID: `PARAMID_AF_AREA_POINT_CTRL`(포인트 제어), 좌표 중심 `PARAMID_EXPANDED_FOCUS_AREA_CENTER_X/Y`(확대/스팟 공용 좌표).
- SDCom: param **317 focusPoint `[x,y]`**(기준 덤프 `[2,2]`).

### 엔진 메커니즘 / OSD
- 좌표는 OSD 좌표계로 입력되고 엔진이 YUV 좌표로 변환(`calcCoordOsdToYuv`, §5 좌표매니저 공용)해 AF 창을 옮긴다. 스팟 박스는 엔진 OSD 렌더.

### route-b 판정 — ⚠️ 가능, 미배선
- group188(또는 PARAMID 포인트) 쓰기로 좌표 이동 가능하나 **미배선·미검증**(현재 route-b는 영역 타입만, 좌표는 OSD 타입 표시에 불필요하다고 주석). 좌표계/범위 실기 확정 필요.

## 4. AF 트리거 + 합초(focused) 결과

### 제어 id (트리거)
- **물리 반셔터 S1**(hw keycode 0x1F1)이 정규 트리거. a5000은 부팅 시 셔터가 전기적으로 눌린 상태라 createEvent에 0x02/0x25/0x2b로 분산 방출됨([route-b-real-device] memory).
- SDCom 명령면: `CameraAutoFocus 0x1006`(param 66) → `CameraCancelAutoFocus 0x1007`(param 66). 캡처 시퀀스는 0x1006 → `TakePicture 0x1008` → `StopTakePicture 0x1027`.
- 뷰 상태 훅: `InputService::changeLancFocusStatus(int)`(반셔터/LANC 초점 상태).
- AF 보조 파라미터: `PARAMID_AF_DRIVE_SPEED`, `PARAMID_AF_KEY_TYPE`, `PARAMID_PRE_AF_MODE`(사전 AF, 렌즈 `uc_PreAF_Support` 게이트), `PARAMID_AF_RANGE_LIMIT_*`(포커스 레인지 리밋).

### 엔진 메커니즘
- 콘트라스트 AF: av-cam가 AF 통계(RC 이전 추출, [imaging/0001 §2])로 콘트라스트 피크를 찾아 lens communicator로 렌즈 모터를 구동. a5000은 위상차 화소 없음 → 순수 콘트라스트.

### 합초 이벤트(완료 신호)
- 내부 이벤트 리스트(`packages/data/re/scalar/event_tables.tsv`):
  - `CameraEventFocusDoneEventList = {0x1301, 0x2001}` (합초 완료)
  - `CameraEventFocusStartParamList = {0x1301, 0x1e01}` (AF 시작)
  - `CameraEventAutoFocusAreaParamList = {0x1234, 0x123c}` (합초 영역 좌표)
  - `CameraEventFocusAreaInfoParamList = {0x12e8,0x12e5,0x1234,0x123c,0x12a0,0x1313,0x1600,...}` (영역 info)
  - `CameraEventAeLockParamList = {0x12bb}` (AE 락), `CameraEventAutoFocusLightEventList = {0x131a}` (AF 보조광)
- 클라이언트 수신 분기(libcamera `onEventReceived_thread`, `event_dispatch.tsv`): **msgId 0x200A·0x200C·0x200D·0x200E·0x200F → handleFocusDoneEvent**, **0x2001·0x2002·0x2004 → handleSTDFocusEvent**. 즉 내부번호(0x1301/0x2001)↔수신 SDCom msgId(0x200x) 왕복은 **실기 캡처로 확정 필요**([sdcom/0004]).

### OSD 경로
- 합초 프레임(녹색 등)은 엔진 OSD(`PAS_FocusWindow` + handleFocusDone 결과)가 그린다. `ACT_IconFocus`는 모드 아이콘.

### route-b 판정 — 🔶 트리거=순정 통과(설계) / 상태읽기=이벤트 구독 가능·미검증
- route-b는 반셔터 S1(0x02/0x25/0x2b)을 **의도적으로 매핑하지 않아** 순정 엔진이 AF/캡처를 그대로 수행한다(input_createevent.cpp). 이게 설계: 촬영은 순정 OSD passthrough.
- 합초 **상태 읽기**가 필요하면 in-proc SDCom 클라이언트(이미 `sdcom_inproc.cpp` 존재, 0x1003 검증됨)로 `RegisterEvent`에 FocusDone 리스트를 넣고 수신 0x200x를 받는 경로가 **가능**하나 미검증. AF-start 명령(0x1006)도 in-proc SDCom으로 호출 가능하지만, 순정 통과가 더 안전하므로 불필요.

## 5. 포커스 확대 (Focus Magnifier / focus zoom)

### 제어 id
- SDCom: `CameraStartPreviewMagnification 0x1032` / `CameraStopPreviewMagnification 0x1033` / `CameraGetPreviewMagnificationRatio 0x1036`(reply param 106).
- 엔진 PARAMID(요청측 `_REQ`): `PARAMID_CAM_EXPAND_FOCUS_MODE(_REQ)`, `PARAMID_CAM_EXPAND_FOCUS_AREA_CENTER_X/Y(_REQ)`, `PARAMID_CAM_EXPAND_FOCUS_ACT`, `PARAMID_CAM_EXPAND_FOCUS_AREA_ASPECT`, `PARAMID_CAM_EXPAND_FOCUS_SPINAL_MODE`.
- OSD 렌더측(ObjRenderer read): `PARAMID_EXPANDED_FOCUS_ON / _OUTSET / _LINEOUT / _MAGNIFICATION_RATIO / _AREA_CENTER_X/Y / _EXCLUSION_ZOOM / _EXCLUSION_S1 / _EXCLUSION_STILL_CAP`.
- 뷰 좌표 매니저: `CmnViewFocusMagnificationCoordinateMgr` — `setPos(x,y)`, `move(dir)`, `getCoordX/Y`, `isTop/Bottom/Left/Right`, `calcCoordOsdToYuv/YuvToOsd`, `checkAPSC`, zoom 레이아웃 치수. 메뉴노드 `cmnViewSettingNodeRootFocusMagnifier`, 시간 `cmnViewSettingNodeRootFocusMagnificationTime`(확대 유지시간).

### 엔진 메커니즘 / OSD 경로
- 확대 영상은 **엔진이 라이브 YUV를 디지털 확대**해 영상 평면에 내보낸다(우리 OSD가 아니다). 확대 전 선택 박스(outset/lineout)도 **엔진 OSD**가 그린다. ObjRenderer가 EXPANDED_FOCUS_* PARAMID를 읽어 렌더.
- `_EXCLUSION_S1/_STILL_CAP`: 반셔터·정지캡처 중엔 확대 해제되는 게이트.

### route-b 판정 — ⚠️ SDCom으로 명령 가능, 렌더는 엔진 소유
- in-proc SDCom으로 0x1032/0x1033 트리거 + 좌표 PARAMID로 이동이 **가능**하나 **미배선**. 확대 영상·박스는 엔진이 그리므로 우리 UI는 명령만 하고 그리지 않는다(passthrough와 정합). "확대 시간" 메뉴 토글은 Track A에서 app-local로 구현한 바 있음(memory `settings-impl-state`).

## 6. MF 어시스트 + MF 초점거리 + Pre-AF

### MF 어시스트 (링 회전 시 자동 확대)
- 제어 id: 메뉴노드 `cmnViewSettingNodeRootMFAssist`, 엔진 `PARAMID_MF_ASSIST_MODE`, 내부 명령 `MSGID_SET_MF_ASSIST_MODE_CMD`(MWF ObjMsg, **비-SDCom**), 액션 `pvt_ActionSetMfAssistMode`. 알림 `MSGID_NOTIFY_MF_ASSIST_MODE_EVT`.
- 메커니즘: MF/DMF에서 링을 돌리면 §5 포커스 확대 경로를 자동 기동. → OSD/영상도 엔진 소유.
- route-b: 토글은 비-SDCom이라 **W1 group route 또는 메뉴-입력 주입**으로만. 미배선.

### MF 초점거리 값/스케일
- 값은 im.elf `ModelCamera +148 mm`(memory `mf-focus-distance`, focusmem 헬퍼로 실기 PROVEN). CameraEx/SDCom엔 없음.
- 거리 바 OSD: `ACT_BarFocus_MF` / `ACT_FocusDistance` / `ACT_FocusRange`가 `PARAMID_FOCUS_DISTANCE_SCALE_TABLE_SIZE`, `_SCALE1..5`, `PARAMID_FOCUS_MOVABLE_DIR`를 읽어 디옵터식 바를 그린다.
- route-b: **읽기 ✅**(Track A에서 focusmem로 NEAR/FAR 바 구현). 네이티브 OSD도 동일 값 사용 가능.

### Pre-AF
- `PARAMID_PRE_AF_MODE`, `MSGID_SET_PRE_AF_CMD`, 렌즈 `NID_LENS_INFORMATION uc_PreAF_Support` 게이트. 비-SDCom. 렌즈 지원 여부 실기 확정 필요.

## 7. 피킹 (Focus Peaking)

### 제어 id — SDCom 불가
- 피킹은 **SDCom으로 set 불가**(camera param 표에 키 없음; 제브라와 동일 구조, [backup/0003](../backup/0003.%20zebra-live-apply-path.md)).
- 엔진 PARAMID: `PARAMID_PEAKING_ON`, `PARAMID_PEAKING_LEVEL`, `PARAMID_PEAKING_COLOR_Y/Cb/Cr/COLORIMETRY`, `PARAMID_PEAKING_OUT_DISP`, `PARAMID_DATA_PEAKING`. 이벤트 `MSGID_PEAK_LEVEL_EVT`.
- 적용 체인: `ObjRenderer SetPeaking` → OSAL **VDF 서비스 메시지**(`MSG_ID_VDF_SRVC_SET_PEAKING`, 제브라 `0x59000E`와 동형). 페이로드: `{sel, onoff, level, C, Y, Cb, Cr}` + `m_magnificationRatio`(확대 중 피킹 조정).
- 영속(Backup propId, 실측): 피킹 **레벨 0x01070352**(고0/중1/저2/끔3), **색상 0x01070360**(토글 관찰 노랑↔흰=2↔0). 메뉴노드 레벨 54 / 색 55.

### 엔진 메커니즘 / OSD 경로
- 피킹 에지는 **엔진 VDF가 영상 평면에 직접 그린다**(우리 ch53 OSD가 아니다). 확대 중엔 비율 보정.

### route-b 판정 — ⚠️ SDCom 불가, 엔진 전용
- 옵션: (b) Backup prop 쓰기 = 영속되나 **재부팅 후 적용**(화이트리스트 안전), (d) **in-proc OSAL VDF 메시지 직접 주입** = route-b가 im.elf 안이라 엔진 컨텍스트 접근 가능(제브라 라이브적용과 같은 벡터, [backup/0003] (d)) — 미검증, (c) 메뉴-입력 주입. 라이브 토글이 필요하면 (d)가 유력.

## 9. route-b 통합 모델 (권고)

1. **AF 모드·AF 영역 타입** — 우리 네이티브 MENU/퀵바에서 **CVPDM group route(13/187)** 로 읽고 쓴다. 이미 배선·에뮬 검증; 벽돌0(RAM, read-back 가드). 실기 apply만 1패스 봉인.
2. **AF 트리거/합초/캡처** — **순정에 위임**(반셔터 S1 passthrough, 엔진 OSD 초점 프레임). route-b는 매핑하지 않음. 합초 상태를 우리 OSD에 쓰려면 in-proc SDCom으로 FocusDone(0x200x) 구독 추가(선택).
3. **플렉시블 스팟 좌표** — 우리 UI의 방향키/다이얼로 좌표를 받아 group188/PARAMID 포인트로 이동(미배선). 좌표계 실기 확정 후 배선.
4. **포커스 확대·MF 어시스트** — in-proc SDCom 0x1032/0x1033 트리거 + 좌표 PARAMID. 단 영상·박스는 엔진 렌더이므로 우리는 **명령만**. 확대 유지시간은 app-local.
5. **피킹** — 라이브 토글은 **in-proc OSAL VDF 주입**(제브라와 공용 벡터) 또는 **Backup 영속**. 엔진이 영상에 직접 그리므로 우리 ch53로는 못 그린다.
6. **MF 거리 바** — focusmem(+148) 읽기 유지, 네이티브 OSD에 디옵터 바로 재사용.

전체적으로 초점은 **"엔진 소유 + 뷰 지시"** 모델이라, route-b는 *모드/영역/좌표를 지시*하고 *상태를 읽어 OSD를 그리되*, *AF 구동·확대 영상·피킹 에지는 엔진이 그대로 처리*하게 두는 것이 최소 침습·벽돌0에 맞는다(memory `minimal-sony-footprint`).
