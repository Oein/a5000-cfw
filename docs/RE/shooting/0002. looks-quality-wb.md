# 0002. 화질/룩/화이트밸런스 — RAW·JPEG·크기·비율 · 크리에이티브 스타일 · 픽처이펙트 · DRO/HDR · 컬러스페이스 · WB

> 상태: **derived**(SDCom param/메시지 표) + **observed**(GetParameters 실측) + 엔진 심볼(libObj.so, OBJEFFECT/MPR). 좌표: `packages/data/re/scalar/` (gitignore).
> **핵심 구분**: "어떤 룩을 쓸지 **선택**"(param)과 "그 룩을 실제로 **계산**"(엔진 독점)을 섞지 말 것. 우리는 전자만 한다.

---

## 1. 화질 / 크기 / 비율 — 파일이 어디에 어떻게 쓰이나

| param id | 이름 | 역할 | 실측 |
|---|---|---|---|
| **257** | stillFormatType | RAW/JPEG/RAW+JPEG 선택(enum) | 4 |
| **330** | pictureStorageFormat | 저장 포맷(enum, RAW/JPEG/RAW+J 보조) | 2 |
| 259 | stillFormatQuality | JPEG 압축(Fine/Std) | 50 |
| 256 | stillFormatSize | 픽셀 크기 (읽기) | [5456,3064] |
| **351** | imageSize | 이미지 크기 L/M/S | 2 |
| **352** | imageAspectRatio | 비율 3:2 / 16:9 | 2 |
| 350 | apscMode | APS-C 크롭 | 1 |
| 289 | imageType | — | 0 |
| 388 | longExposureNR | 장노출 NR | 1 |
| 336 | multiShotNR | 멀티샷 NR | 0 |

- stillFormatType/pictureStorageFormat enum 수치는 런타임 값표 → RAW/JPEG/RAW+J의 정확한 매핑은 **메뉴 토글+덤프로 확정**(device-only). 둘 다 camera 키 표에 있어 `0x1003` set 가능.
- **파일 쓰기 = 엔진(av-cam + MPR) 소유, 전부 Sony 독점.**
  - RAW 현상/디모자이크/JPEG 인코딩은 **av-cam.bin(µITRON)** 이미징 코어가 수행(imaging/0001·0002). 외부에서 호출하는 "JPEG 인코더 API"나 "RAW 패커 API"는 없다 — 캡처 시퀀스(`TakePicture 0x1008` → `CamseqSetRawCapture 0x0120` → `CamseqStoreImage 0x0122`)가 엔진에 지시하면 엔진이 센서 RAW→(현상)→파일을 만든다.
  - 파일 **네이밍/디렉터리(DCIM)·파일 오브젝트**는 MPR의 DCF 계층: `MprIf::SetDcfCompositeConfig`, `PreRegisterDcfContentSync`, `GetDcfFileInfo`, `GetDcfObjectInfo`, `GetDcfContentExtent…`. RAW 현상 지원 여부는 `MprCtrl::IsStillRawDevelopmentSupport`, 단건 현상 경로 `MprIf::PlayStillSingle(..., RawDevelopInfo*)`.
  - **.ARW 생성 = av-cam이 센서 RAW를 Sony 포맷으로 패킹**. 우리가 재구현할 수 없고(독점 센서 보정·결함 테이블 ZIT ConvZ1C 포함, imaging/0003 §3), 할 필요도 없다.

**route-b 판정**: RAW/JPEG/RAW+J·크기·비율·품질은 **param으로 선택 → 순정 엔진이 파일 생성**. 우리 UI는 설정만, 쓰기는 100% 순정.

## 2. 크리에이티브 스타일 (Creative Style = 엔진 "ColorMode")

| param id | 이름 | 역할 | 실측 |
|---|---|---|---|
| **261/282** | colorModeType / colorModeType2 | 스타일 선택(Standard/Vivid/Portrait/Landscape/B&W…) | 0 / 1 |
| 283 | contrastLevel | 대비 ±3 | 0 |
| 284 | saturetionLevel | 채도 ±3 | 0 |
| 285 | sharpnessLevel | 샤프니스 ±3 | 0 |

- 엔진 심볼: `ProColorModeSet/Act`, `ColorModeSetChange/ActChange`, `PvtColorModeParam`, `ColorModeMemory`. ColorMode는 **엔진 현상 파이프라인의 톤/채도/컬러 매트릭스 프리셋 선택**이다.
- **재현성**: 스타일 **선택(enum)과 ±조정(contrast/sat/sharp)** 은 평범한 param → set 가능. 각 스타일의 실제 커브/매트릭스("룩")는 Sony 테이블이지만 **엔진이 적용**하므로 우리가 테이블을 몰라도 "순정 Vivid를 켜라"는 100% 된다. 우리가 **자체 커스텀 룩을 주입하는 것**은 불가(테이블 독점).

## 3. 픽처 이펙트 (Picture Effect = 엔진 "Artfilter") — ⚠️ 룩 재현 한계 지점

| param id | 이름 | 실측 |
|---|---|---|
| **286** | pictureEffect | 0 |
| 287~300 | 효과별 레벨(toyCameraLevel, posterizationLevel, partColorLevel, roughMonochromeLevel, softFocusLevel, miniatureEffectArea, watercolorLevel, illustrationLevel, softHighKeyLevel, toyCameraTuning, hdrArtLevel 등) | 대부분 0/2 |

- 엔진 심볼: **`OBJEFFECT::SequenceAppExecArtfilterCmd`, `SequenceFactoryComponentArtfilter`, `SequencePinDeliverStartArtfilterCmd`, `SequencePinRequestDeliverArtfilterCmd`**, 검출측 `DetectCh::artfilterDetection`/`beautyEffectDetection`. 즉 픽처 이펙트는 **별도 Artfilter 처리 시퀀스/파이프라인**을 타고 계산된다.
- **재현성(중요)**: pictureEffect enum과 레벨 param은 set **가능**(순정 효과를 켜는 건 됨). 그러나 효과의 **실제 픽셀 처리는 Artfilter 파이프라인 + 룩테이블로 Sony 독점** — 이것이 ZV-E10 Astra가 "FL/VV를 못 엮었다"고 한 한계와 **동일 범주**다. 우리는 **순정 이펙트를 선택**할 수 있을 뿐, **새 이펙트/룩을 재현·주입할 수 없다**.

## 4. DRO / 오토 HDR

| param id | 이름 | 실측 |
|---|---|---|
| **272/273** | droLevel / droLevel2 | 1 / 1 |
| **274/275** | hdrLevel / hdrLevel2 | 0 / 1 |
| 291 | hdrArtLevel | 2 |

- DRO(D-Range Optimizer)·Auto HDR는 **엔진의 톤/다이내믹레인지 처리 단계**(DRO=단일 노출 로컬 톤, Auto HDR=다중 노출 합성). 레벨 param은 set **가능**, 처리 자체는 엔진 독점.
- Auto HDR은 다중 노출이므로 **드라이브/릴리즈 시퀀스와 엮임**(브래킷 유사, 엔진이 합성) → 트리거는 순정에 맡긴다.

## 5. 컬러스페이스 (sRGB / AdobeRGB)

| param id | 이름 | 실측 |
|---|---|---|
| **356** | colorSpace | 1 |
| 377 | rgbMatrixMode | 0 |
| 378~384 | rgbMatrix / colorDepth* | — |

- 엔진 심볼: `ColormodeScsSRgb`/`ColormodeScsAdobe`(SCS = Still Color Space). 컬러스페이스는 **엔진 출력 매트릭스 선택** → param 356으로 set **가능**, 평범한 enum(룩테이블 아님). 재현성 문제 없음.

## 6. 화이트밸런스 (프리셋 · 커스텀 · 색온도/컬러필터)

| param id | 이름 | 역할 | 실측 |
|---|---|---|---|
| **260/279** | wbMode / wbMode2 | WB 모드(Auto/Daylight/Shade/Cloudy/Tungsten/Fluor/Flash/ColorTemp/Custom…) | 0 / 1 |
| **280** | wbColorTemperature | 색온도(K) | 4000 |
| 281 | wbAdjustCC | 컬러필터 G-M(CC) 미세조정 | 0 |
| 290 | wbAdjustLB | 컬러필터 A-B(LB) 미세조정 | 0 |
| 374/375/376 | whiteBalanceShiftMode/LB/CC | WB 시프트 | 0 |
| 305 | whiteBalanceLock | AWB 잠금 | 0 |

- 엔진 심볼: `pvt_ChangeWbModeParamApp2Obj/Obj2App`, `ActionSetWbMode`, `SetParamWbMode`, `ProcessNotifyWbModeEvt`.
- **프리셋/색온도/CC-LB 미세조정**: 전부 평범한 param → `0x1003` set **가능**. wbMode enum 수치는 런타임 값표(device 덤프로 확정).
- **커스텀 WB 세트(측정)** 는 전용 CameraEx 메시지 3단계:
  1. **`CameraStandbyCustomWBCapture 0x101b`**(request param id 5 = Int, 채널/인덱스) — 측정 대기 진입.
  2. **`CameraCaptureCustomWB 0x101c`** — 흰 피사체 측정(릴리즈).
  3. **`CameraSaveCustomWB 0x101d`**(param id 5) — 측정값 슬롯 저장.
  - 엔진측 액션: `ActionExeCustomWbStby` → `ActionObjectCustomWbCmp`(CustomWbCapture changed) → `ActionObjectCustomWbSaveCmp`(CustomWbSave changed), 보조 `pvt_getCustomWbChannelNumber`, `RequestCustomWbData`, 이벤트 `ProcessNotifyCustomWbEvt`(필드: CustomWB Index / isInRange / colorTemp / colorFilter).
  - **측정 계산(그레이 밸런스 산출)은 엔진 독점**이지만, 우리는 **standby→capture→save 3메시지로 순정 측정 플로를 그대로 구동**할 수 있다. isInRange/colorTemp/colorFilter는 이벤트로 받아 OSD 피드백.

**route-b 판정(WB)**: 프리셋·색온도·컬러필터·시프트는 param set, 커스텀WB는 0x101b/c/d 플로로 전부 구동 **가능**. 측정 알고리즘만 엔진.

## 7. route-b 통합 요약 (룩/화질/WB)

| 기능 | 제어 | set 가능? | 룩 재현 |
|---|---|---|---|
| RAW/JPEG/RAW+J, 크기, 비율, 품질 | param 257/330/351/352/259 | ✅ | 파일생성=엔진(독점) |
| 크리에이티브 스타일 + 대비/채도/샤프 | param 261/282/283/284/285 | ✅(선택) | 커브=Sony테이블, 적용은 엔진. 자체룩 ❌ |
| 픽처 이펙트 | param 286 + 287~300 | ✅(선택) | **Artfilter 룩 재현 ❌(Astra 한계)** |
| DRO / 오토HDR | param 272~275/291 | ✅ | 처리=엔진 독점 |
| 컬러스페이스 | param 356 | ✅ | 평범한 enum, 문제없음 |
| WB 프리셋/색온도/CC-LB/시프트 | param 260/279/280/281/290/374~376 | ✅ | 평범, 문제없음 |
| 커스텀 WB 측정 | msg 0x101b→0x101c→0x101d | ✅(플로 구동) | 측정 산출=엔진 |

**권장 모델**: 룩/화질/WB **설정은 route-b 메뉴에서 param/메시지로 지시**, **실제 현상·이펙트·파일생성은 순정 엔진**. 우리가 **새 룩을 만들 수는 없으나 순정 전 기능을 켤 수는 있다**. 픽처이펙트/크리에이티브 스타일의 "모양"을 우리가 재설계하는 것은 불가 — UI는 순정 룩의 "선택·미세조정" 레이어로 한정.

## 8. device-only 미확정

1. stillFormatType/pictureStorageFormat/wbMode/colorModeType/pictureEffect **enum 수치**(런타임 .bss) — 메뉴 토글+GetParameters 덤프.
2. 커스텀WB **이벤트 id**(colorTemp/colorFilter/isInRange 알림) — event 카테고리 교차 확인.
3. RAW+JPEG 동시 저장 시 MPR DCF 오브젝트 구성(파일 2개 묶음) 실측.
4. bracketStepEV·wbAdjust 단위 스케일(×10 추정) 실측 확인.
