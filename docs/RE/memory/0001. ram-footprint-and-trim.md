# 0001. RAM 사용처와 안전 트림 목록 (a5000 / route-b 주입 상태)

> 상태: **observed (에뮬레이터, 순정 1.10 콜드 부팅, SD 없음)** + derived(정적: cmdline, ELF 섹션, libIMDB 테이블).
> 실기 확인 필요 항목은 §8. 원시 캡처(`/proc/meminfo`, `smaps`, `vmstat`, `slabinfo` 등)는 `packages/data/re/memory/`(gitignore).

## 0. 요약
- DDR 512 MiB 중 **Linux가 쓰는 건 MemTotal 175.8 MB뿐**. 나머지 ~336 MB는 cmdline `memrsv`로 빠진 **av-cam/영상 carve-out**(Linux 페이지 할당자 밖)이라 Linux 쪽 "RAM 부족"과 무관하고 건드릴 수도 없다.
- 순정 상태에서 `MemFree`가 ~6 MB로 낮아 보이지만 **회수 가능한 cold page cache가 ~48 MB**(drop_caches로 실측) 있다. 진짜 고정 사용량은 anon 39 MB + 커널 ~33 MB 정도다.
- **Linux RAM을 가장 많이 쓰는 건 Android**(PSS ~51 MB, `stop zygote` 시 즉시 +30 MB 해제). 다음이 im.elf(Linux RAM PSS ~31 MB, 대부분 공유 라이브러리 코드).
- **우리 주입 UI가 ~9.8 MB를 더 쓴다**: tmpfs(shmem) +7.3 MB(그중 asset 6.6 MB), im.elf anon +2.5 MB(canvas와 shadow를 RGBA8888로 따로 둠). 이 상태에서 커널 reclaim이 시작되고 direct reclaim 스톨(`allocstall`)이 처음 관측됐다.
- **OOM 위험 구조**: Android 프로세스는 전부 `oom_adj=-16`, im.elf만 `0`이다. 스왑이 없고 `overcommit_memory=1`이라 OOM이 나면 **im.elf(=카메라)가 1순위 희생자**다.
- ZV-E10식 libIMDB mode-mask 트림은 a5000에서 효과가 **< 1 MB**다. 대상 대부분(gps/geo/compass/Lanc/HdmiInput/EyeFi/sata/msen)이 a5000 `/usr`에 아예 없어 이미 로드되지 않는다. 게다가 `/usr` 영구 수정이라 **비권장**.

- 메모: smaps의 `/dev/stream` Rss(im.elf 34 MB, system_server 24.6 MB)는 **carve-out PFN 매핑**이다. `VmRSS`·`MemTotal`에 포함되지 않으므로 Linux RAM 계산에서는 빼야 한다(im.elf smaps Rss 65.4 MB ↔ VmRSS 28.7 MB의 차이가 이것).
- `tmonitor.addr=0x82000000 size=0x500000 mask=0`은 memrsv 밖에 있다. mask=0이라 비활성으로 추정 **[?]**.
- carve-out을 Linux에 돌려주려면 cmdline(`kemco`)의 memrsv/wbimem을 바꿔야 한다. 이것은 영구 부트 설정 수정이고, av-cam의 고정 메모리 맵도 모르므로 **금지(벽돌)**.

### 2.1 drop_caches 실측 (주입 상태)
`sync; echo 1 > drop_caches`: MemFree 2.3 → **54.8 MB**(+52 MB). Cached 100.1 → 52.1 MB, Buffers 4.3 → 0.1 MB. `echo 3`을 하면 slab이 추가로 ~0.8 MB 줄어든다. 남은 Cached 52 MB는 Mapped 46.5 MB와 Shmem 7.5 MB(서로 겹침)다. 직후 major fault는 829 → 853(+24)에 그쳤다. 즉 버린 ~48 MB는 **부팅 때 읽고 다시 쓰지 않는 cold 캐시**였다.

### 2.3 스레드 스택 (정적 크기 대비 실제 상주)
- im.elf: 2 MB 스택(+4 KB guard) × 152 = **VSZ 304 MB, 상주 1.28 MB**(스레드당 ~8 KB). system_server: 1 MB × 46 = VSZ 46 MB, 상주 256 KB.
- im.elf 스레드 구성: `I-InputEvent` 26개, IMM 5, uipc_proxy 4, THREAD_INFRA 4, IFsys 4, ObjMedia 4 … `gps_main_thread`, `HotshoeResource`, `I-HotshoeRecv`, `I-LancMain`, `WlanResource_Ma`, `NetServiceMainT`, HDMI/CEC 스레드 각 1개.
- 커널 스택은 태스크당 8 KB 고정(462개 = 3.7 MB)이다. **스택 크기 축소는 RAM 이득이 ~0이다**(VSZ만 줄어든다).

- IMDB 등록 라이브러리 중 매핑된 것의 상주 합계는 6.5 MB다. 그중 libmpr 2.7 MB와 libScalarDaemon 1.0 MB는 필수다. **a5000에 실제로 없는 하드웨어용으로 끌 수 있는 건 합계 < 0.2 MB.**
- 결론: `/usr`(nflasha15)를 수정하면 WBI 스냅샷과 불일치가 생긴다([boot/0002](../boot/0002.%20wbi-warm-snapshot.md)). 영구 수정이라 벽돌 위험이 있고 얻는 RAM은 1 MB 미만이므로 **하지 않는다**.

## 7. 트림하면 안 되는 것
- **carve-out 전체**(av-cam 이미지 0x83541000~, 영상 풀, stream 풀 0x8D7A0000 32 MB, OSD 버퍼): Linux RAM도 아니고 영상 파이프라인 그 자체다.
- 커널 모듈 `liro`(av-cam 호스트), `dmm`, `upm`, `stream`/`stream2`, `nand`/`lld`, `grm_*`, `backup`, `osal_*`: 참조 카운트가 있고 영상·저장·백업 경로가 의존한다.
- im.elf와 그 라이브러리(libObj, viewUnified*, libmpr, CautionConfig, libScalarDaemon…), `liro-kliro_*` 커널 스레드(av-cam 태스크), `bootin.elf`.
- 렌즈/센서/디스플레이 관련 im.elf 스레드: 개별 스레드 정지 수단도 없고 시도하지 않는다.
- `/sys/power/state` 쓰기(WBI 캡처 경로), `ud_wbi_drop`.
- `/android/data/data`·`/android/data/system`(ram8/ram9 ext2, 각 ~1 MB/256 KB): Android 상태 저장소다.

## 8. 실기 확인이 필요한 것
1. **warm 재개(WBI)**: 실기는 공장 스냅샷(RAM 127 MB)에서 재개한다. 에뮬은 콜드 부팅이었으므로 재개 직후 page cache 구성과 MemFree가 다를 수 있다.
2. **SD 카드와 실제 촬영·재생**: 촬영 중 FuFsys(fuse)와 JPEG 처리, 재생 썸네일 때문에 page cache와 anon이 얼마나 늘어나는지.
3. **Wi-Fi 활성 상태**: wpa_supplicant(680 KB 바이너리)와 network 스크립트의 메모리. 에뮬에는 Wi-Fi 모델이 없다.
4. 설치된 Android 앱(OpenMemories Tweak 등)의 상주량과 Android cgroup max_usage.
5. **`stop zygote` 후 telnetd/adbd 생존 여부** → 원격 접근이 사라지면 물리 전원 재부팅밖에 없다(사용자 대면 필수).
6. oom_adj -17과 min_free_kbytes 4096을 적용했을 때 카메라 동작(특히 동영상 기록과 연사).
7. 실기 `MemFree`, `allocstall`, `pgmajfault`를 시간에 따라 추적해 "RAM 부족 다운"의 실제 원인을 확정할 것: OOM 킬인지, direct reclaim 랙인지, 다른 원인인지.

## 9. 방법 (재현)
- 에뮬: `A5K_FW=<repo>/packages/data/firmware A5K_NAND=<clone> A5K_SHELL=<port> packages/emulator/run.sh -display none -monitor tcp:...`. 유휴 5분 전원 사이클은 HMP `sendkey s 300`(반셔터)를 45초마다 보내 방지했다.
- 캡처 스크립트: busybox 최소 applet만 사용(`cat`, `grep`, `sed`). 결과는 `/android/a5k`에 쓰고 a5kshell `pull`로 가져온 뒤 호스트에서 파싱(PSS 집계, `/dev/stream` 분리). 스크립트와 파서는 `packages/data/re/memory/`에 있다.
- 주입: `a5kinject <im.elf pid> /android/a5k/a5kinproc.so c37cc`. MENU 진입 후 우리 UI가 그려지는 것을 확인하고 캡처했다.
- Android 정지/복귀, 개별 앱 kill, drop_caches는 에뮬에서만 수행했다.
