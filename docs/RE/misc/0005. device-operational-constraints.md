# 0005. 실기 운영 제약 (Wi-Fi 끊김 등)

> 상태: **observed** (2026-11-19, 실기).

## 라이브뷰 진입 시 Wi-Fi 끊김
- 증상: telnet(:23)/adb(:5555)가 세팅·메뉴·유휴 상태에서는 열려 있다가 반누름/라이브뷰 진입 후 반복적으로 끊긴다. ping은 평소에도 필터될 수 있어 **포트 도달성(예: nc -z :23)** 으로 판단할 것. 기기 IP/서브넷은 자주 바뀐다.
- 원인(유력): 카메라가 라이브뷰/촬영 엔진을 켤 때 Wi-Fi를 내린다. 우리 주입 `.so` 탓이 아니라 카메라 고유 동작(순정 촬영도 라이브뷰라 동일하게 내려갈 수 있음).
- 함의/워크어라운드:
  - 로그는 tmpfs(`/android/a5k/ui.log`)에 남으므로 라이브뷰에서 조작 → 빠져나와(MENU/재생/유휴) Wi-Fi 복귀 → 로그 읽기 순으로 **사후 수집**.
  - 원격 배포/주입은 **비-라이브뷰** 상태에서.
  - 촬영 화면은 순정 OSD를 그대로 쓰고 우리 UI는 MENU에서만 쓰는 passthrough 아키텍처는 우리 UI가 라이브뷰를 상시 붙들지 않는다는 점에서 유리.
- 프로세스 확인 팁: `/proc/uptime`은 커널 기준(프로세스 재시작 아님). 주입 `.so` 로드 여부는 `im.elf`의 `/proc/<pid>/maps`에서 확인.

## 메모리
RAM 총량 약 172MB, 여유 약 20MB(앱 실행 중 수 MB까지 하락). OOM이 hang/리셋의 주 원인 — APK 설치가 유일한 큰 RAM 위험([0003](0003.%20device-access-and-native-test-workflow.md)).

## 기타
- 앱 크래시가 기기 리셋으로 이어질 수 있다(앱 시작 시 onPause에서 Wi-Fi off 함정 등). 로그를 먼저 읽을 것.
- 카메라 크래시 = 물리 전원 재부팅 필요(원격 복구 불가).
