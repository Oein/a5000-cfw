# 0003. 기기 접근과 네이티브 테스트 워크플로 (RE 도구 관점)

> 상태: **observed**(2026-11-12~13 실기 확립). 개발 환경 상세는 프로젝트 개발 가이드(`docs/AI_DOCS/`)를 참조.

## 접속
- telnet 루트 셸(OpenMemories-Tweak telnetd, 무인증)과 adb(:5555). adb shell은 `/android` chroot 내부라 네이티브 `/setting`이 보이지 않는다. 파일 pull은 telnet로 `cp <네이티브 파일> /android/mnt/sdcard/<8.3 이름>` 후 adb pull.
- busybox 최소 구성: `head/tail/df/nohup/nc` 없음(`busybox <applet>`으로 호출), dd/md5sum/tar/ftpput/taskset은 있음. 셸 제약: printf 없음, 줄 편집 1024자.
- telnetd는 Wi-Fi 모드 변경 시 종료된다. 또 라이브뷰/촬영 진입 시 Wi-Fi가 내려가 telnet/adb가 끊기는 것은 카메라 고유 동작이다([0005](0005.%20device-operational-constraints.md)).

## 테스트 바이너리 실행 (NAND 무수정)
- 빌드: 정적 musl(`zig cc -target arm-linux-musleabi -mcpu=cortex_a9 -static`)도 동작하며, glibc 호환이 필요하면 Docker 크로스 툴체인(Ubuntu 12.04 `arm-linux-gnueabi` GCC 4.6.3)에 카메라 펌웨어의 glibc 2.11.2·libstdc++ 6.0.14·libsdcom·libosal_uipc를 sysroot로 사용. 옵션 `-march=armv7-a -mthumb -mfpu=vfpv3-d16 -mfloat-abi=softfp -nodefaultlibs`. 카메라 ELF는 v7-A / Thumb-2 / VFPv3-D16 / softfp.
- Android 쪽 네이티브(bionic)는 NDK r10e(android-9, gcc 4.8)로 빌드하고 `busybox chroot /android ...`로 실행.
- 전송: telnet `echo -ne '\xHH'`(220B/줄, 줄마다 완료 대기, `busybox md5sum`으로 검증).
- 실행: SD(FuFsys)는 **noexec** → RAM tmpfs **`/android/a5k/`**로 복사 후 실행. `/tmp`는 NAND이므로 금지.
- 안전 규칙(SDCom 클라이언트)은 [sdcom 0005](../sdcom/0005.%20client-safety-rules-and-incident.md).

## APK 설치의 RAM 위험
설치(dexopt)가 RAM 스파이크 → OOM → 기기 hang(벽돌 아님, 배터리 리셋으로 복구). 절차: `drop_caches`로 캐시 확보 → 앱 프로세스 강제 kill 금지(엔진 불안정) → `adb install -r` → 직후 `/proc/uptime`으로 리셋 여부 확인.

## 그래픽 관찰 (요약; 상세는 display)
- `/dev/fb0`, `/dev/fb1`은 ENXIO(fbdev 드라이버 없음). 화면 경로는 `grm_gles.ko` + `/dev/dmpgles2`(GLES2). im.elf의 libObj는 자체 GPU 드라이버(`rm_reg_init`, `rm_rqueue_init`, `rm_kick_thread_init`)를 내장하고 EGL을 쓰지 않는다. OSD는 GRM → VDF(패널/EVF/HDMI) 출력.
- Android 2.3.7(API 10)의 SurfaceFlinger는 같은 GPU를 `/android/dev/dmpgles2`로 공유하며 Rigel 윈도우 서버의 클라이언트 하나다.
- 네이티브 SurfaceFlinger 클라이언트 시험: initCheck=0, 디스플레이 640x480 RGBA8888 30fps, EGL 1.4, GL_RENDERER=SMAPH-S30 / OpenGL ES 2.0. 단 클라이언트 `Surface::lock`의 dequeue/lockBuffer가 -22를 반환하고 GL swap이 큐잉되지 않아 이 경로는 실패 → Rigel 직접 경로가 정답.

## 입력 관찰 실험의 교훈
키 캡처는 앱이 전경 통지(ABT)를 했느냐에 따라 결과가 달랐다([input 0001](../input/0001.%20evdev-keymap-and-abt-key-ownership.md)). 실험 중 카메라가 1회 재부팅하면 RAM tmpfs(`/android/a5k`)가 초기화된다.

원시 캡처 로그(키 입력, dmesg, sdprobe/sftest 출력)는 `packages/data/re/captures/`에 보관(비공개).
