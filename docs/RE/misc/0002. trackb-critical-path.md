# 0002. 트랙 B 실행 가능성과 임계 경로

> 상태: 2026-11-13 정적 스코핑 종합(이후 route-b 실기 진전은 display/camera 카테고리 참조). 모든 "다음 단계"는 플래시 미기록, RAM tmpfs 실행, SDCom 휘발이라 **벽돌 위험 0**.

## 임계 경로 (standalone으로 성립하려면 순서대로)
1. **D2A/state 5 획득** — 가장 큰 미지수. 우리 프로세스가 앱 슬롯에 있을 때 엔진이 D2A를 발동하는지. 아니면 아키텍처 재검토.
2. **Rigel `UX_DEBUG_CLIENT` 창 표시** — 정적 확정도 최고(서버가 채널을 미리 만들어 두고 이름 필터가 없으며, 신규 클라이언트가 윈도우 리스트 tail에 붙어 순정 OSD 위에 그려짐).
3. **라이브뷰 합성** — OpenCamera 0x1000 → StartPreview 0x1004, GetVideoLayout으로 OSD 배치.
4. **ABT 전키 입력** — 메시지 완전 확정, 독립적으로 바로 시험 가능.

임계 경로 밖(병렬 가능): 키맵 재캡처, 네이티브 설정 메뉴 diff, 이벤트 왕복 확인.

## 트랙 A로는 영구 불가 → 트랙 B 전용
- 이미지 DB 복원 실행/진행률: in-process 주입만
- 피킹/제브라/AF 보조광 **라이브** 적용: SDCom 불가(엔진 PARAMID + Backup prop) — 영속은 Backup prop으로 가능(재부팅 적용)
- 정지영상 재생은 양 트랙 공통으로 SD 직접 디코드

## 실기에서만 확정되는 핵심 unknown 5
1. Rigel UX_DEBUG_CLIENT 창 수락과 라이브뷰 위 합성/투명
2. 프리뷰 프레임 취득 경로(StartPreview + CamseqGetPreviewFrame)
3. 이벤트 ID 실측
4. ABT 송신 후 전키 수신
5. WBI 콜드부트/스냅샷 재생성(교체 전환에서만)

## 벽돌 위험 정리
위 단계 전부 안전. **교체 전환(WBI + /usr 수정)** 만 진짜 위험이며 게이트 off. 업데이터 복구 리허설이 선행되어야 한다([boot 0004](../boot/0004.%20recovery-paths-and-invariant.md)).
