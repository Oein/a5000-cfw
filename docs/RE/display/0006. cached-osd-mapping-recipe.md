# 0006. cached(실제로는 non-cached write-buffered) OSD 매핑 레시피 — `/dev/mem` 느린 쓰기 대체

- 상태: 정적 RE 검증 완료 (IDA 덤프 `packages/data/re/ida/libObj.so.c` + `stream.ko` objdump). 실기 미검증.
- 대상: `libObj.so` 1.10, `/usr/kmod/stream.ko` 1.10
- 한 줄 판정: 바닥은 "uncached"가 아니라 **`/dev/mem`의 strongly-ordered device 매핑**이다. Sony는 같은 phys를 **`/dev/stream`의 non-cacheable write-buffered 매핑**으로 써서 빠른 것이며, **cached(write-back)가 아니다**. 따라서 **dcache clean은 필요 없고**(그래서 unlock에 캐시 연산이 없다), 필요한 건 프레임당 **write barrier(배리어)** 하나뿐이다. 최소 수정은 매핑 디바이스 문자열을 `/dev/mem`→`/dev/stream`으로 바꾸는 것.

---

## 1. 검증한 사실 (오프셋·vtable·시그니처)

모두 `libObj.so.c`(= IDA 9.4 덤프)와 BitmapImpl vtable `_ZTVN3grm3bmp10BitmapImplE`(`0xE568F0`, 포인터값 `0xE568F8`) 기준.

| 항목 | 값 | WIP/보고값 대비 |
|---|---|---|
| `GRM_bitmapWriteLockBits` export | `0x555B4C` → `sub_589D88(bmp,mode,&out)` + 빈 스텁 `sub_555854` | **정확** |
| `GRM_bitmapWriteUnlockBits` export | `0x555B5C` → `sub_589DB8(bmp)` + 빈 스텁 `sub_555854` | **정확** |
| `sub_555854` | 빈 함수(`;`) — export==raw vtable 호출 | **정확** |
| lock → BMP vtable 인덱스 | `+76` (`sub_589D88`이 `(*(vt+76))(bmp)` tail-call) | **정확** (`sub_5894F8` 구현) |
| unlock → BMP vtable 인덱스 | `+80` (`sub_589DB8`이 `(*(vt+80))(bmp)`) | **정확** (`sub_588F14` 구현) |
| lock 시그니처 | `(void* bmp, int mode, void** out)` — assert 문자열 `BMP_WriteLockBits(void*, int, void**)`이 확증. 썽크는 r0/r1/r2를 그대로 통과시키므로 IDA가 `a1`만 보여도 3인자. | **정확** |
| lock 반환/동작 (`sub_5894F8`) | 성공 시 `*out = *(bmp+8)`(매핑된 CPU VA), 반환 `0`. `mode 0`=non-block(즉시 시도), `-1`=블록, 그 외=timed. `mode 0`에서 잠금 가능하면 획득(우리 전용 버퍼라 항상 성공), 불가 시 `-8` 반환. | **정확** |
| unlock 동작 (`sub_588F14`) | `writingWriters--`(=0 assert) → `pthread_cond_broadcast` → `pthread_mutex_unlock`. **캐시 연산 없음.** | **정확** (WIP "no dcache clean" 맞음) |
| `BMP_CreateFromPhys` | `0x589A00` = `sub_589A00(w16,h16,fmt,yuv,phys,rowPixels16,BMP_RectangleRecord* rect,void** out,sortOrder,startPos)` | **정확** |
| `BMP_Release` | `0x589E18` = `sub_589E18` (vtable `+100` 후 `+88`) | **정확** |
| `fmt2bpp` | `0x589F48` = `sub_589F48(fmt,&bpp)` | **정확** |

`rowPixels` 인자는 **픽셀 단위**(640)이지 바이트(1280)가 아니다. Sony `sub_5D99D0`도 `640`을 넘긴다(아래). 결과 바이트 스트라이드는 `640*2=1280` = 현재 `dstRowB`와 동일하므로 같은 `convRow` 루프가 양쪽 매핑에 그대로 쓰인다.

### Sony의 실제 호출 (ground truth, `sub_5D99D0` @ `0x5D99D0`)

```
dest = unk_BC852E;                                        // rect record 초기값(0 아님)
BMP_CreateFromPhys(640, 480, 2 /*16bpp*/, 0, dword_EEED1C /*OSD phys*/, 640,
                   &dest, &out, 0, 0);
```

- **WIP/Path A의 `dest=0`은 버그 아님**: `rect`(`src`)는 생성 내부에서 `impl+12`(클립 사각형)로만 복사되고, 실제 매핑 크기는 생성자가 정렬한 w/h(`impl+24/26`)와 bpp로 계산된다(`sub_589378`). 현행 Path A도 `dest=0`으로 동작 중. cached 경로는 32B VDF 레코드를 만들지 않고 픽셀만 쓰므로 `dest` 내용은 무관하다. (충실도를 원하면 Sony처럼 `unk_BC852E`로 둘 것 — `.rodata 0xBC852E`의 8바이트. 기능상 불필요.)

## 2. 왜 빠른가 — MA 매퍼 + `stream.ko` (진짜 메커니즘)

### MA 매퍼 `sub_5E7860` @ `0x5E7860` (device 선택)

```
if (fd == -1) {                                  // a1[7]
  if (phys + 0x80000000u < 0x40000000u)          // phys ∈ [0x80000000,0xBFFFFFFF] (SDRAM)
      name = "/dev/stream";
  else {
      if ((phys + 0x40000000u) >= 0x10000000u) abort();  // [0xC0000000,0xCFFFFFFF]만 허용
      name = "/dev/mem";
  }
  if (a1[9]) name = a1[9];                        // device override; CreateFromPhys 경로는 null → 위 자동선택
  open(name, flags);
}
mmap(0, len, PROT_READ|PROT_WRITE /*3*/, MAP_SHARED /*1*/, fd, phys_aligned);
```

- 우리 `grm_sens_work` 버퍼(`dword_EEED1C`, 에뮬 phys `0x9ac00000`)는 SDRAM 창에 있으므로 GRM/MA가 자동으로 **`/dev/stream`** 을 연다. override(`a1[9]`)는 `CreateFromPhys` 경로에서 null이라 자동선택이 적용된다. **정확** (WIP 주장 확인).

### `stream.ko`의 `stream_mmap` (pgprot 실측, objdump)

`stream_mmap`는 `remap_pfn_range`만 쓰며 다음을 수행:

```
vma->vm_page_prot &= ~0x3C;        // bic  #0x3C  = L_PTE_MT_MASK (메모리타입 필드) 전체 clear
prot = vma->vm_page_prot | 0x40;   // orr  #0x40  (remap에 넘기는 prot)
remap_pfn_range(vma, vm_start, vm_pgoff, vm_end-vm_start, prot);
```

- `0x3C` = `L_PTE_MT_MASK`(`0x0f<<2`). 이를 **지워버리므로** 이 매핑은 **write-back cacheable이 아니다**(write-back이면 MT 필드에 `0x0C`가 있어야 하는데 방금 0으로 clear됨). 즉 **non-cacheable**.
- 결과: `/dev/stream` = **Normal non-cacheable / write-buffered** 매핑. `/dev/mem`(비-RAM phys → `pgprot_noncached` = strongly-ordered device)과 달리 **쓰기 버퍼 결합(write-combining)이 허용**되어 쓰기량 처리가 수십 배 빠르다. 이것이 실측 8 MB/s 바닥의 진짜 원인(= strongly-ordered)과 Sony가 빠른 이유(= write-buffered)를 설명한다.
- ⚠️ 보고/WIP의 "CACHED /dev/stream" 표현은 **부정확**. 올바른 표현은 "non-cached write-buffered". 순효과(빠름 + clean 불필요)는 WIP 결론과 같지만, 메커니즘·주석을 바로잡아야 한다. (비트 `0x40`의 정확한 ARM 속성명은 커널 pgtable 헤더 없이는 비트단위 확정 불가 — 단 MT 필드가 0으로 clear된 사실만으로 "write-back 아님"은 확정된다.)

## 3. 코히런시 — clean은 불필요, barrier만 필요

- `/dev/stream` 매핑이 **non-cacheable**이므로 OSD 픽셀은 CPU 캐시에 남지 않는다 → **dcache clean 불필요**. 그래서 Sony unlock(`sub_588F14`)에 캐시 연산이 없는 것이 일관된다.
- ch53 OSD 스캔아웃은 **연속**(매 프레임 phys 재독, 0002 §3)이다. CPU 쓰기가 DMA에 보이려면 **쓰기 버퍼가 비워져야** 한다 → 프레임당 **메모리 배리어(DSB/DMB)** 하나면 충분.
  - GRM 경로: unlock의 `pthread_mutex_unlock`/`cond_broadcast`가 배리어를 포함 → 자동 충족.
  - 디바이스-스왑 경로(§4): GRM을 안 쓰므로 **명시적 `__sync_synchronize()`** 를 프레임당 1회 추가.
- **clean 범위 질문**: 해당 없음(캐시 없음). 비용은 배리어 1회(수십 ns)로 무시 가능. 현행 `/dev/mem` 전체-프레임 uncached 쓰기 비용과 비교해 압도적 이득.
- **가장 큰 코히런시 리스크 = 테어링**: single-buffer in-place + 연속 ch53 스캔아웃이라, 쓰는 도중 DMA가 그 행을 읽으면 찢김이 보인다. write-buffered는 결합/재배열 때문에 strongly-ordered 대비 찢김 노출이 미세하게 더 크다. 그러나 (a) 이미 single-buffer in-place가 받아들인 모델이고(0002 §3, 메모리 route-b-present-fullrate), (b) dirty-row만 쓰므로 찢김이 변경 행으로 한정되며, (c) 프레임당 배리어로 경계가 지어진다. **완화**: 변경 행만 기록(이미 적용), 배리어를 쓰기 직후 1회, 필요 시 vblank 근처 제출은 추후 과제. 실용상 메뉴 네비게이션에서 무시 가능.

## 4. 권장 레시피 A — 디바이스 스왑 (최소·견고, 추천)

핵심 통찰: 현재 present 코드(single-buffer in-place, `convRow`, dirty-row)는 **그대로 두고**, 버퍼를 매핑하는 디바이스만 `/dev/mem`→`/dev/stream`으로 바꾸면 Sony와 동일한 non-cached write-buffered 매핑을 얻는다. GRM BMP·vtable·lock/unlock·신규 오프셋 **전부 불필요**. `mmap` 인자는 `libma`가 쓰는 것과 동일(이미 현행 코드와 동일 패턴).

**프레임당 시퀀스**: (setup 1회) `/dev/stream` open + `mmap(phys)` → `dst`. (present) dirty 행만 `convRow`로 기록 → `__sync_synchronize()` 1회.

```diff
--- a/packages/custom-binary-app/platform/a5000-inproc/display_rigel.cpp
+++ b/packages/custom-binary-app/platform/a5000-inproc/display_rigel.cpp
@@ (버퍼 매핑: 현재 ~709행)
-        mfd_ = ::open("/dev/mem", O_RDWR);
-        if (mfd_ < 0) { plog("vdf: /dev/mem open failed"); return false; }
+        // CACHED(정확히는 non-cached write-buffered) 매핑: Sony GRM/MA가 SDRAM phys에
+        // 쓰는 것과 동일한 /dev/stream(= stream.ko, L_PTE_MT clear = non-cacheable,
+        // write-combining 허용)로 매핑한다. /dev/mem(strongly-ordered device, ~8MB/s)
+        // 쓰기 바닥(0001/0002)을 제거한다. 실패하면 /dev/mem로 폴백(무회귀).
+        const char *mapDev = (env_int("A5K_VDF_UNCACHED", 0) ||
+                              ::access("/android/a5k/vdf_uncached", F_OK) == 0)
+                             ? "/dev/mem" : "/dev/stream";
+        mfd_ = ::open(mapDev, O_RDWR);
+        if (mfd_ < 0 && mapDev[5] == 's') {       // /dev/stream 없으면 /dev/mem로
+            plog("vdf: /dev/stream open failed -> /dev/mem"); mapDev = "/dev/mem";
+            mfd_ = ::open(mapDev, O_RDWR);
+        }
+        if (mfd_ < 0) { plog("vdf: %s open failed", mapDev); return false; }
+        plog("vdf: OSD buffer mapping via %s (%s)", mapDev,
+             mapDev[5] == 's' ? "non-cached write-buffered, fast" : "uncached device, slow");
@@ (present(): dirty 기록 루프 종료 직후, 현재 ~938행 firstFrame_ = false; 뒤)
         firstFrame_ = false;
+        // non-cached write-buffered 매핑에서 CPU 쓰기 버퍼를 비워 연속 ch53 스캔아웃이
+        // 최신 픽셀을 읽게 한다. dcache clean은 불필요(캐시 없음) — 배리어 1회면 충분.
+        if (dirtyRows > 0) __sync_synchronize();
```

- `A5K_VDF_UNCACHED=1` / 마커 `/android/a5k/vdf_uncached` 로 옛 경로로 즉시 되돌릴 수 있는 안전장치. 기본은 `/dev/stream`.
- `engine.h` 변경 **불필요**.
- 벽돌 위험 0: RAM-only, open/mmap만 다름, 폴백 완비.

## 5. 레시피 B — GRM lock/unlock 충실 복제 (WIP 교정본, 대안)

Sony API를 그대로 흉내 내고 싶을 때. 기능은 A와 동치지만 BMP 객체·vtable 결합과 프레임당 mutex가 추가된다(우리 전용 버퍼엔 불필요한 비용). WIP 오프셋·인덱스·시그니처는 모두 검증상 **정확**했고, 교정은 **주석의 "cached"→"non-cached write-buffered"**, **"coherency by mapping"→"coherency by write-buffer drain(배리어), unlock의 mutex가 그 배리어 제공"** 뿐이다.

`engine.h` (WIP 그대로 유효, 주석만 교정):

```diff
+    // GRM bitmap write lock/unlock: Sony가 BMP 픽셀을 쓰는 "빠른" 경로.
+    // 검증(libObj.so.c + BitmapImpl vtable 0xE568F8):
+    //   OFF_GRM_bmpWriteLock  (0x555B4C)=GRM_bitmapWriteLockBits -> sub_589D88 ->
+    //     bmp-vtable[+76]=sub_5894F8. ABI (bmp, mode, void** out). mode 0=non-block
+    //     (우리 전용 버퍼라 성공), -1=block. 성공 시 0 반환, *out=bmp[+8]=매핑 VA.
+    //     그 VA는 MA 매퍼 sub_5E7860이 SDRAM phys에 대해 "/dev/stream"(stream.ko,
+    //     L_PTE_MT clear = NON-CACHEABLE write-buffered)으로 만든 것. 속도이득은
+    //     cached가 아니라 write-combining 때문(vs /dev/mem strongly-ordered).
+    //   OFF_GRM_bmpWriteUnlock (0x555B5C)=GRM_bitmapWriteUnlockBits -> sub_589DB8 ->
+    //     bmp-vtable[+80]=sub_588F14. writingWriters-- + cond_broadcast + mutex_unlock.
+    //     dcache clean 없음(필요 없음: non-cacheable). 코히런시는 mutex_unlock에
+    //     포함된 배리어가 쓰기 버퍼를 비워 제공. stride=640px*2B=1280B=dstRowB.
+    OFF_GRM_bmpWriteLock   = 0x555B4C,
+    OFF_GRM_bmpWriteUnlock = 0x555B5C,
```

`display_rigel.cpp` — WIP 로직 유지, 교정점:

1. `setupCached()`의 `BMP_CreateFromPhys` 호출/`rect=&dest(=0)`은 **그대로 OK**(§1). `memset` 주석의 "RGBA4444 alpha nibble" 문구는 포맷 설명일 뿐 기능 무관.
2. `present()`의 cached 분기: lock으로 VA 획득 → dirty 행 기록 → **unlock(= 배리어 제공, clean 아님)**. WIP의 주석 "coherency with the ch53 DMA is provided by the liro /dev/stream mapping itself, no explicit clean here" 를 아래로 교정:

```diff
-        // CACHED mode: write-unlock (publishes the writer release; coherency with the ch53
-        // DMA is provided by the liro /dev/stream mapping, no explicit clean here). Done
+        // non-cached write-buffered mode: write-unlock은 writer 해제 + mutex_unlock의
+        // 배리어로 CPU 쓰기 버퍼를 비워 연속 ch53 스캔아웃에 가시화한다. dcache clean은
+        // 필요 없다(매핑이 cacheable이 아님 — stream.ko가 L_PTE_MT를 clear). Done
         // BEFORE the timing capture so the SLOW instrument reflects write + unlock cost.
```

3. WIP가 `present()`에 섞어 넣은 **진단용 라인은 되돌릴 것**(프로덕션 반영 금지):
```diff
-        bool sweep = true || firstFrame_ || (presentN & 15) == 0;   // DIAG: force full-scan
+        bool sweep = firstFrame_ || (presentN & 15) == 0;
```
(이 `true ||` 강제 full-scan은 dirty-row 최적화 0002 §4를 무력화한다. WIP의 디버그 잔재이며 반드시 제거.)

나머지(`fn_grmlock`/`fn_grmunlock` typedef, `cached_`/`cachedBmp_` 멤버, `shutdown()`의 `BMP_Release`, lock 실패 시 `bufMap_[0]` 폴백)는 그대로 유효.

## 6. WIP 패치 평가 요약

- **오프셋·vtable 인덱스·시그니처·반환값**: 전부 정확.
- **`BMP_CreateFromPhys` 인자/`rect=0`**: 정확(기능 무관).
- **"unlock에 캐시 clean 없음"**: 정확.
- **메커니즘 서술("CACHED", "coherency by mapping")**: **부정확** → "non-cached write-buffered, 코히런시는 배리어(= unlock의 mutex)"로 교정.
- **진단 잔재 `sweep = true || ...`**: 프로덕션 반영 금지(제거).
- **설계 판단**: GRM lock/unlock(레시피 B)은 동작하나 우리 전용 버퍼엔 과한 결합. **레시피 A(디바이스 스왑 + 배리어)** 가 더 작고 견고하여 추천.
