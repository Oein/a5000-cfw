# 0008. 측광 + 표시/촬영 보조(DISP·히스토그램·수준기·격자선) end-to-end

> 상태: 정적 RE 확정(측광=setMeteringMode/getMeteringMode 실바디 확인, 히스토그램=ObjRenderer 액세서 체인 심볼 확인, 격자선=ModelGridLine+PAS_Grid 확인, DISP 패턴=getPanelDisplayPattern 실바디+Backup propId 확인). **수준기(전자 수평계)는 a5000에 없음**(모델/센서 근거 아래 §5). 일부 값 매핑은 device-only(아래 "미확정").
> 대상: `viewUnified2.so`(뷰/위젯), `libObj.so`(GEN 위젯·Model·ObjRenderer 엔진), `im.elf`/CVPDM. 디컴파일 출처 `packages/data/re/ida/`(로컬 전용).
> 관련: display/0005(뷰별 ch53 제출 경로·funcMode 23), camera/0001(funcMode enum), settings/0002(CVPDM 그룹표), sdcom/0003(카메라 param), backup/0001(Backup 구조).

## 1. 측광 모드 (Multi / Center / Spot)

### 1.1 control id
- 설정노드: `cmnViewSettingNodeRootMeteringMode`. 전용 뷰 `ViewMeteringmode`(viewUnified7, 레이아웃 `ST_METERING`), 아이콘 위젯 `ACT_IconMeteringMode`·`ACT_IconSpotMeteringArea`.
- 뷰 래퍼: `WrapperMeteringMode::setMeteringMode`(viewUnified2 @0x22198A), `getMeteringMode`(@0x221A06).
- **읽기/쓰기 경로 = CVPDM 그룹 eventId 22** (settings/0002 "측광" 행과 일치):
  - set: `(*(vtable+56))(mgr, 22, value)` — CVPDM write 슬롯 14.
  - get: `(*(vtable+12))(mgr, 22, &out)` — CVPDM read 슬롯 3. 기본 반환 4.
  - 내부 enum 매핑은 `sub_221918`(UI→내부), `sub_2219DE`(내부→UI). `isInhOn`(@0x22103E)로 모드별 금지(예: 특정 모드에서 측광 고정) 게이트.
- SDCom 대체 경로: `CameraGetParameters` 응답의 **param 270 = meterMode**(기준값 0), `CameraSetParameters 0x1003`로 set 가능(sdcom/0003 §1). 즉 측광은 **CVPDM 그룹22(뷰레이어)와 SDCom 270(엔진직결) 두 경로** 모두 존재.

### 1.2 엔진 측광 메커니즘 + 노출 피드백
- 측광 모드는 엔진 AE가 라이브뷰 YUV의 휘도 적분을 **어떤 가중치로 합산하는지**를 고른다(Multi=분할 평가, Center=중앙 가중, Spot=중앙 소영역). 결과 EV가 노출 제어(조리개/셔터/ISO/노출보정)를 구동 — 이들은 CVPDM 그룹이 없는 "출력 값"이라 `getModelInfo`(Path A, 라이브뷰 on 필요; camera/0002)로만 읽힌다.
- Spot 측광 영역 표시는 `ACT_IconSpotMeteringArea`(ch53 OSD 아이콘). 측광 **계산 자체는 엔진 전용**이라 비표시(우리가 다시 계산하지 않음).
- 재생 메타: libObj `M_SinglePbBase`가 이미지의 `MeteringModeValid`를 들고 있음(촬영 시 측광 모드가 EXIF로 저장됨) — 표시 전용.

### 1.3 route-b 판정
- **set/read 전적으로 가능**: CVPDM 그룹22(RAM/엔진, 가역 — settings/0002 안전성) 또는 SDCom 270. 우리 메뉴에서 Multi/Center/Spot 토글 → 엔진이 즉시 측광 반영.
- 측광 아이콘은 우리 OSD로 직접 그린다(순정 아이콘 불필요). Spot 영역 사각형도 우리가 중앙에 그리면 됨.

## 2. DISP 레벨 사이클 (정보 오버레이)

### 2.1 상태와 제어
- a5000 모니터 DISP 사이클(실측 메뉴 `눈금표시/DISP 버튼` 존재, stock_menu_inventory): **그래픽 표시 / 전체 정보 표시 / 정보 표시 없음 / 히스토그램**. (상위기종의 "수준기" 상태는 a5000 미노출 — §5.)
- 사이클 가능 상태 집합은 설정노드 `cmnViewSettingNodeRootDISPButtonMonitor`(+`DispButtonPage1`)에서 모델별로 정의(CautionConfig `DispButtonMonitor` 프로퍼티 리스트).
- 현재 DISP 패턴은 **Backup propId `0x1070172`** 에 영속 저장. `CmnPanelCommonPattern::getPanelDisplayPattern`(libObj @0x193680)이 이 propId와 보조 prop 3개(`sub_1935F8`로 읽는 BKID 0x15040400/420/4A0 계열)를 조합해 **패턴 코드 0..7**을 반환하고, ViewStlrec의 `MyLayoutGroupConverter`가 그 코드로 레이아웃(`ST_NORMAL`=전체정보 / `ST_NORMAL_HISTOGRAM` / graphic / info-off 등)을 선택한다.
- 전체 정보 뷰는 funcMode 23(`ViewShootingInfoDisp`, camera/0001)과 연결 — 레이아웃은 ch53 FbContainer 위젯 경로로 제출(0005 §1.2, §2).

### 2.2 DISP 입력 처리 + funcMode 23 연계 (★0005와 직접 연결)
- 순정 DISP 소프트키는 위 패턴 코드를 다음 값으로 advance → Backup 0x1070172 갱신 → ViewStlrec 재레이아웃. "전체 정보 표시"로 들어가면 `ViewShootingInfoDisp`(funcMode **23**)가 되어 ch53를 FbContainer 경로가 소유한다.
- **우리 입력훅은 현재 DISP를 소비하지 않음**(`input_createevent.cpp:145`는 MENU 0x11만 peek). 그래서 passthrough에서 DISP가 순정으로 새어 funcMode 23을 띄우고, detour-swap이 경로 A(SenserIf) 전용이라 우리 UI가 패널에 안 뜨는 고착이 생긴다(0005 §3).
- **수정(0005 수정①과 동일)**: passthrough에서 **DISP도 소비**해 순정 23 진입을 차단하고, 우리 `shooting_osd.infoOn_` 토글 + 우리 자체 DISP 사이클(정보 on/off, 히스토그램 on/off, 격자 on/off)을 우리 OSD에서 운용. 보강으로 우리 메뉴 중 `mgr+100`(PRESENT_DISABLE)=1(0005 수정②).

### 2.3 route-b 판정
- **우리가 DISP 사이클을 소유**하는 것이 정답(순정 23 봉쇄 = 0005 아키텍처). 순정 Backup 0x1070172를 건드릴 필요 없음(우리 상태는 우리 메모리). 다만 순정과의 상태 동기가 필요하면 propId는 menu-write 집합(subsystem 0x107)이라 안전 쓰기 가능(backup 화이트리스트 확인 필요 — 미확정).

## 3. 히스토그램

### 3.1 계산 위치 = 엔진(ObjRenderer)
- 히스토그램은 **엔진이 계산**: libObj `OBJRENDERER` 네임스페이스에 전용 체인 — `ACSRID_HISTOGRAM_DETECT`(리소스 액세서), `HistogramMgr`/`RsrcMgrHistogram`/`RsrcAcsrHistogram`/`HistogramStatusControl`, 전용 child thread(`CHILD_THREAD_HISTOGRAM_IF`, `MSGID_RENDERER_CHILD_THREAD_HISTOGRAM_*`), 시퀀스 `SequenceHistOnceDetectInPinDeliver`/`State_HistOnceDetect`(가드 `GuardIsQFHDMode`, `GuardIsPlayOn`).
- 즉 라이브뷰/재생 **YUV pin deliver** 시점에 엔진이 휘도(및 R/G/B) 분포를 검출해 통계 버퍼를 만든다. 하드웨어/엔진 측 산출이라 우리가 YUV를 다시 적분할 필요 없음.

### 3.2 데이터 → 렌더
- 엔진 통계 → `ModelHistogram`(`ModelHistogramToInstance`, libObj) → 뷰 변환기 `ACT_Histogram`(+휘도/색 분리 `ACT_HistogramR/G/B/Y`, viewUnified2) → 위젯 `GEN_Histogram`(libObj @0x23003~)의 `updateSprite(float scale, ushort* bins)`로 바 렌더. 설정자: `setHistoSize`(bin 수), `setBarColor`, `setMaxHeight`, `setTopPercentage`(클리핑), `setBackGroundMargin`.
- 렌더 평면: `GEN_Histogram`은 뷰 위젯 → **ch53 OSD**(FbContainer 경로). 촬영(ST_NORMAL_HISTOGRAM)·재생(SINGLEPB_MASTER_HISTOGRAM, viewsinglepb) 레이아웃에 배치.

### 3.3 route-b 판정
- **우리 자체로 그릴 수 있음**. 데이터소스 = 엔진 `ModelHistogram`(이미 계산됨). 우리가 그 Model(또는 하위 ACSR 통계 버퍼)을 읽을 수 있으면 우리 OSD에 직접 바를 그린다. Model 읽기 API/오프셋은 아직 미확정(device/런타임 확인 필요) → 폴백은 순정 히스토그램 위젯만 오버레이. **권장: ModelHistogram read 경로 확정 후 자체 렌더**(측광 외 유일한 "엔진 데이터 필요" 보조).

## 4. 격자선 (Grid Line)

- 설정노드 `cmnViewSettingNodeRootCustomGridLine`, 모델 `ModelGridLine`(`ModelGridLineToInstance`), CVPDM element `CmnViewProcessDataElementCustomGridLine`.
- 렌더: 뷰 위젯 `ACT_IconGridLine`(+Converter) → `PAS_Grid`(viewUnified2 @0x2D6304). `PAS_Grid`는 `FrameType`·`AspectType`·`DrawType` enum을 가짐 → 격자 종류 구성(3분할 `CustomGridLineThree_partition`=rule-of-thirds, 사각 격자, 대각+사각 등). a5000 옵션: **3분할 격자 / 사각 격자 / 대각+사각 격자 / 끄기**(종류 enum은 PAS_Grid Draw/Frame type; 정확 값 매핑 device 확인).
- 렌더 평면: 순수 뷰 위젯 → **ch53 OSD**. 엔진 데이터 전혀 불필요(정적 선).
- **route-b 판정: 가장 단순**. 우리가 직접 선을 그린다(순정 설정/모델 불필요). 설정도 ModelGridLine로 set 가능하나 우리 UI에서는 자체 토글이면 충분.

## 5. 수준기(전자 수평계) — a5000에 없음

- **근거(정적)**:
  1. `Model*ToInstance` 전수에 **수준기/자세 모델 없음** — Level/Posture/Gradienter/Horizon/Tilt-angle 모델 부재(있는 건 `ModelAxisCalibration`·`ModelCompassCalibrate`=GPS/나침반 보정, `ModelAudioLevelMeter`=오디오, 모두 수평계 아님).
  2. `GEN_IconLevelBar`(libObj)는 `openLevelBar/getLevel/moveHlt/setDispNum` — **하이라이트 이동식 바**(노출 스케일/선택 바)지 센서 기반 수평계 아님.
  3. viewstlrec의 `ST_NORMAL_LEVEL*` 레이아웃은 **공용 펌웨어**(상위기종 a6000+용)로 존재하나 a5000은 이를 구동할 모델/센서 피드가 없어 **게이트 오프**. DISP 사이클 상태에도 "수준기" 미노출.
  4. 실측 메뉴(stock_menu_inventory)에 수준기 항목 없음.
- **센서**: `/usr/kmod/accel.ko`(가속도 센서) 존재하나 a5000에서는 **재생 이미지 자동 회전/세로-가로 판정** 용도로 추정(수평계 UI로 승격 안 됨). 3축 롤/피치 각도를 UI에 공급하는 경로는 이 빌드에 없음.
- **route-b 판정**: 순정에 없는 기능이라 **불필요**. 신규로 넣고 싶으면 `accel.ko` 노드(각도 raw) 직접 RE + 자체 수평계 위젯을 우리 OSD에 그려야 함 — **device-only RE 필요**(아래 미확정).

## 6. route-b 종합 권고

- **측광**: 우리 메뉴에서 CVPDM 그룹22(또는 SDCom 270)로 set. 아이콘·Spot 영역은 우리 OSD. (완전 지원)
- **DISP 사이클**: 우리가 소유. **입력훅에 DISP 소비 추가**(0005 수정①의 전제) — 순정 23 봉쇄. 정보/히스토그램/격자 on-off를 우리 사이클로.
- **히스토그램**: 엔진 `ModelHistogram`가 데이터 생산자. read 경로 확정되면 우리 OSD에 직접 렌더(권장), 아니면 순정 위젯 오버레이 폴백.
- **격자선**: 우리가 직접 그림(엔진 불필요). 최우선 쉬운 항목.
- **수준기**: 보류(순정 미지원). 수요 시 accel.ko RE 별도 과제.
