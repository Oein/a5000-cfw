# 0009. HDMI 출력 + 후면 LCD 동시 사용 — HW mux인가 SW 정책인가

- 상태: `derived`(정적 RE) + `emu`(VPH 모델) + 실기 노드 관측(HDMI 미연결) 보강, 2026-11-21
- 질문: HDMI 꽂으면 LCD가 꺼지는 게 **HW mux(물리적 불가)**냐 **SW 정책(가역 가능)**이냐, 후자면 route-b로 LCD를 켠 채 유지 가능한가.

---

## 0. TL;DR

| 항목 | 판정 | 신뢰도 |
|---|---|---|
| 동시 출력 금지의 성격 | **SW 정책.** HW mux 아님 | `derived`+`emu`+실기노드 |
| cxd90014 VPH 출력단 | **패널 데이터패스와 라인(HDMI) 데이터패스가 분리** — 별도 AIF 채널 + 별도 타이밍 생성기 + 별도 /dev 노드 | `emu`+실기노드 |
| 이중 타이밍 생성기 | **있음.** 패널 타이밍 ≠ 라인 타이밍(0xF3446000) → 서로 다른 해상도 동시 가능(미러 한정 아님) | `emu`/RE_HDMI |
| 순정이 LCD를 끄는 이유 | 데이터플로 씬이 아니라 **상위 뷰/전원 정책**이 "출력 1개만" 선택(switchDisplayOutputTo) + 패널 백라이트 off | `derived` |
| "동시출력" 정책 플래그 | **순정에 없음**(SimulOutput/DualDisplay 류 심볼 부재) → 순정은 단일-활성-디바이스 모델 | `derived` |
| route-b로 LCD 유지 | **조건부 가능(가역·RAM-only·플래시 미기록).** 패널 경로가 독립 HW라 HDMI 켠 뒤 패널 백라이트/채널/타이밍을 재-유지하면 됨. 단 VDF 공유 스케일러 대역·엔진 재구성은 device-seal | `inferred` |

**결론:** 물리적으로 둘 다 낼 수 있는 HW다. LCD가 꺼지는 건 Sony UI/전원 정책의 선택이며, 그 정책은 휘발 제어면(SDCom·sysparam·in-proc 훅)에서 되돌릴 수 있으므로 route-b 범위 안이다. 실제로 동시에 켠 상태의 안정성(대역·엔진)만 실기 봉인 대상.

## 1. VPH 출력단 구조 — 패널 vs 라인(HDMI)은 분리 데이터패스

cxd90014 VPH는 **두 개의 독립 합성/스캔아웃 경로**를 가진다. mux(둘 중 하나만 고르는 레지스터)가 아니라, 각 출력단이 자기 AIF 채널·타이밍 생성기·물리 출력 노드를 따로 쓴다.

| 출력단 | YUV(비디오) 평면 | OSD 평면 | 타이밍 생성기 | 물리 출력 | /dev 노드(실기) |
|---|---|---|---|---|---|
| **패널(console0)** | AIF ch51 | AIF ch53 (`+0x20` start-addr, PA 0xF3441320+0x20) | VPH 패널 타이밍 | MIPI/패널 | `/dev/stream`(stream.ko) |
| **라인(HDMI)** | AIF ch52 | AIF ch54 | 라인 타이밍 `0xF3446000` | VPH 라인 출력 → HDMI TX | `/dev/hdmi_external_tx` |

- AIF 채널 레지스터: 베이스 `0xF3441200 + 0x80*k` (k=0→ch51, k=1→ch52, k=2→ch53, k=3→ch54). 각 채널 `+0x00` bit0 = start/busy, `+0x48` signed pitch.
- 라인 출력 모드: `VPH+0x410` [18:16] 포맷(0 480i/576i … 5 1080p), 라인 active size `VPH+0x454`([11:0] W, [27:16] H).
- 라인 vsync = GIC 101, 패널 vsync = 102(둘 다 펄스) — **두 출력이 각자 vsync를 돌린다** = 이중 타이밍 생성기.
- HDMI TX는 외부 칩이 아니라 on-SoC APB 블록 PA `0xF2A24000`(16KiB). HPD는 IRQ 없이 **100ms 폴링**(SYS_STAT +0x024 bit1, INTR1 +0x1C4 bit6). CEC는 별도 APB `0xF3C10000`.
- 근거: 에뮬 VPH 모델 `packages/emulator/qemu-overlay/hw/display/cxd90014_vph.c`(패널 console0 = ch51+ch53, HDMI console1 = ch52+ch54, `vph_hdmi_update`가 별도 콘솔), `packages/emulator/docs/RE_HDMI.md` §0/§2, 실기 /dev 노드(패널 `/dev/stream` · HDMI `/dev/hdmi_external_tx` 분리, `/dev/hdmi_input`·`/dev/cec` 별도).

→ **mux 레지스터 부재 + 분리 채널/타이밍/노드 = 물리적 동시 출력 가능**. (기존 0003 "OSD mux 없음"과 일관: 패널 OSD 소스는 `+0x20` 단일 레지스터이며, 라인 OSD는 별도 ch54.)

## 2. HDMI 핫플러그 → 디스플레이 라우팅 이벤트 흐름

```
hdmi.ko 폴링(HPD, 100ms)  ──또는── av-cam task48 "HDMIState" → OSAL q 0x28017D
        │
   libInfraHdmi (HDMISenserResponder: get_hpd_status / set_tmds / set_power / set_resolution)
        │            [libInfraHdmi.so.c: get_hpd_status @0x35e30, 디스패처 @~0x3406 라인]
        ▼
   상위 뷰/비즈 로직(cmn_view / BizFw)  ──SDCom 1536──▶ libScalarDaemon
        │                                   (ScalarDisplayManagerIf::switchDisplayOutputTo)
        ▼
   libScalarDaemon:
     • CommandProcessorSetOsdOutput  (msgid 1536, "DEVICE_ID_HDMI"/"DEVICE_ID_PANEL")
          → SystemEventIssuerDisplay::setOutputLineout(dev)
          → reloadYuvLayoutTable(dev ^ 1, false)   ← 반대쪽 디바이스 YUV 레이아웃 재설정
          → setFaceFrameOutput(dev)
     • SystemEventIssuerDisplay::setPanelBacklightControl(on/off)  [sysparam 0x12006010]
     • setPanelBacklightLevel [0x12006011], setEVFBacklight* (a5000 EVF 없음=공유 스텁)
```

핵심 오프셋 맵(libScalarDaemon.so.c):

| 심볼 | 오프셋 | 역할 |
|---|---|---|
| `SystemEventIssuerDisplay::setPanelBacklightControl` | `0xe1898` | 패널 백라이트 on/off (sysparam `0x12006010`) |
| `SystemEventIssuerDisplay::setPanelBacklightLevel` | `0xe18e0` | 패널 밝기 (sysparam `0x12006011`) |
| `SystemEventIssuerDisplay::setOutputLineout` | `0xe1778` | OSD/라인 출력 디바이스 선택 |
| `SystemEventIssuerDisplay::reloadYuvLayoutTable` | `~0x` (라인 21524) | 디바이스별 YUV 레이아웃 재적용 |
| `CommandProcessorSetOsdOutput::SyncProcessor::execute` | `0x10e248` | SDCom 1536 처리, 위 3개 호출 |
| `CommandProcessorSetOsdOutput::...::extractSDComMessage` | `0x10e2a8` | "DEVICE_ID_HDMI" 파싱(param id 1536, type 3) |

디스플레이 매니저(libscalar_displaymanager.so.c):

| 심볼 | 오프셋 | 역할 |
|---|---|---|
| `ScalarDisplayManagerIf::switchDisplayOutputTo` | `0x36ac` | 디바이스 문자열로 **"하나로 전환"** SDCom 1536 송신 |
| 디바이스 열거 파서 | 라인 1412/1482/1536 | `DEVICE_ID_PANEL`(id 1537) / `DEVICE_ID_HDMI`(1539) / `DEVICE_ID_FINDER`(1538) / `DEVICE_ID_NONE`; 각 엔트리에 active 플래그 |

**관찰:** 상위 API 이름이 `switchDisplayOutputTo`(단수 전환)이고, `reloadYuvLayoutTable(other, false)`로 반대쪽을 접고, 별도로 패널 백라이트를 끈다. 즉 **"출력은 1개"**라는 전제가 뷰/전원 정책에 박혀 있다(HW 제약이 아니라 정책). HDMI 연결 시 패널 타이밍/채널을 정지시키는 호출은 이 라우팅 결과로 뒤따르는 것이지, 데이터플로 씬에는 없다(§3).

## 3. HDMI 시작/정지 데이터플로 씬 — 패널을 건드리지 않는다 (결정적)

`AVBB_SCN_START_HDMI.so.c :: scenario_run` (@0x21f0):

1. `PinConnect_VDF_to_HDMI` (@0x1bf0) — **VDF(비디오 데이터플로) 소스에 HDMI 싱크를 "추가" 연결**
2. `CheckPinUnConnectADF_to_HDMI` → `PinConnect_ADF_to_HDMI` (오디오)
3. `Backup_read(0x1500000)`로 3D 여부 읽고, 필요 시 `PinConnect_SubVDF_to_SubHDMI`
4. `SetResolHDMI`, (3D면 Set3dFormat/Set3dOperatingMode), `SetCableHDMI(1)` = HPD/케이블 assert

→ **이 씬 어디에도 패널/finder 핀 disconnect, 패널 백라이트 off가 없다.** HDMI는 VDF의 **추가 싱크**로 붙는다. `AVBB_SCN_STOP_HDMI`는 `SetCableHDMI(0)` + `SetLineOutVDF(0,0,0,0)`(라인 출력만 끔)로 라인단만 정리. 즉 데이터플로 그래프 레벨에서 VDF→패널과 VDF→HDMI는 공존 가능하며, 둘을 배타로 만드는 코드가 씬에 없다.

이것이 §1(HW 분리) + §2(정책은 상위)와 합쳐져 **"HW는 동시 가능, 끄는 건 상위 SW"**를 확정한다.

## 4. "동시 출력" 정책 플래그 존재 여부

- 전수 grep 결과 **디스플레이 동시출력 심볼 없음**: `SimulOutput`/`DualDisplay`/`DualView`/`Concurrent`/`PanelAndHdmi` 부재.
- `isSimultaneousRecOn`(cmn_view)은 **동시 "녹화"**(카드/정지+동영상)로 디스플레이와 무관.
- 결론: 순정은 **단일-활성-디스플레이 모델**만 구현. 동시 출력은 순정에 "꺼진 기능"이 아니라 "구현되지 않은 모드". 따라서 우리가 동시를 원하면 **정책을 우회**해 패널 경로를 독립적으로 살려야 한다(설정 토글로는 불가).

## 5. route-b 개입 타당성 (가역·RAM-only·플래시 미기록)

**판정: 조건부 가능.** 패널 데이터패스가 HDMI와 독립 HW이므로, HDMI를 정상 기동시킨 뒤 패널단을 "꺼지지 않게" 유지하면 동시 출력이 성립한다. 개입은 전부 휘발(엔진 상태/in-proc 훅)이라 재부팅 복구 = 벽돌위험 0.

개입 후보(가역성 순):

1. **패널 백라이트 off 억제 (가장 안전).** HDMI 연결 흐름이 내는 `setPanelBacklightControl(off)`(sysparam `0x12006010` ← libScalarDaemon `0xe1898`)를 막거나, off 직후 우리가 `on`을 재송신. route-b는 이미 SDCom/엔진 param 송수신 통로를 가지므로 **sysparam 0x12006010=on 재주입**이 최소 개입. 플래시 미기록.
2. **라우팅 전환 억제/보강.** `switchDisplayOutputTo("DEVICE_ID_HDMI")`(libscalar_displaymanager `0x36ac`가 내는 SDCom 1536)를 가로채, HDMI 활성화는 통과시키되 패널 디바이스의 active 플래그·YUV 레이아웃을 유지(= `reloadYuvLayoutTable`가 패널을 접지 않게). in-proc 훅 또는 SDCom 메시지 필터.
3. **패널 AIF 채널/타이밍 재기동.** 혹시 HDMI 라우팅이 패널 ch51/ch53 start 비트나 패널 타이밍을 정지시키면, 우리가 이미 지배하는 `+0x20`(ch53 OSD, 0003) 경로와 동일한 방식으로 패널 채널 start/타이밍을 재설정. 단 이건 레지스터 직접 제어라 2순위.

권장 1차: **①(백라이트 유지) + ②(라우팅 1536 필터)**. 둘 다 휘발 제어면이고 우리 .so의 기존 SDCom/훅 역량 안에 있다. 패널 채널 강제 재기동(③)은 ①②로 불충분할 때만.

**가역성 결론:** 전 개입이 sysparam/SDCom/in-proc 훅 = RAM/엔진 상태. `/setting`·flash 미기록. `/android/a5k/stop`으로 즉시 원복, 재부팅이면 순정 동작. §1 표의 "자유/정답 경로"에 해당.

## 6. a5000 HW 한계 — 미러인가 독립 해상도인가

- **이중 타이밍 생성기 존재** → 패널과 HDMI가 **서로 다른 해상도·타이밍**을 동시에 낼 수 있다(라인 타이밍 `0xF3446000`, 라인 모드 `VPH+0x410`, active size `VPH+0x454`가 패널과 독립). 미러 전용이 아님.
- 단, 비디오 평면의 **소스는 공유 VDF**다. VDF 스케일러가 패널용 리사이즈 출력(ch51)과 라인용 리사이즈 출력(ch52)을 동시에 공급해야 하며, 이때 **엔진 리사이즈 대역·버퍼·클럭**이 두 출력을 동시에 감당하는지는 정적 RE로 확정 불가(device-seal, §7). OSD는 평면이 완전히 분리(ch53 vs ch54)되어 동시가 자연스럽다.
- 즉 "HW 동시 가능"은 확정, "라이브뷰를 두 해상도로 동시에 안정 공급"은 대역 여유 문제로 남는다.

## 7. 실기 확인 필요 (device-seal)

사용자가 지금 **HDMI 미연결 상태 읽기전용** 접근 가능(연결 상태 관측은 이번 세션 불가). 아래는 **side-effect 없는 정적 보강 읽기** 후보다. `/dev` 노드 직접 ioctl은 부작용 우려로 피하고, `/proc`·`/sys`·`/dev/mem` 읽기만.

**지금(미연결) 읽어 보강 가능:**
- `cat /proc/iomem` — HDMI TX(`0xF2A24000`), CEC(`0xF3C10000`), VPH(`0xF3440000`), 라인 타이밍(`0xF3446000`) 창 네이밍 확인. 패널/라인 창이 별 레인지로 잡히면 §1 분리 확정.
- `ls -l /sys/module/hdmi/parameters/ /sys/module/cec/parameters/ /sys/module/stream/parameters/ /sys/module/stream2/parameters/` 및 `cat`(있으면) — 라인/패널 모듈 파라미터로 분리 드라이버 확인.
- `ls -l /sys/class/graphics/ /sys/class/video_output/`(존재 시) — fb/output 디바이스 수. 패널·라인 별 노드면 분리 보강.
- **읽기전용 `/dev/mem` peek**(부작용 없음, 레지스터 read): 미연결 상태에서
  - 패널 AIF ch51 `0xF3441200+0x00`, ch53 `0xF3441320+0x00`/`+0x20` → start/busy=1, 주소 프로그램됨 예상.
  - 라인 AIF ch52 `0xF3441280+0x00`, ch54 `0xF3441380+0x00` → **미연결이면 idle(start bit 0)** 예상.
  - 라인 모드 `0xF3440410`, 라인 active `0xF3440454` → 미연결 0/무효 예상.
  - 패널 타이밍 vs 라인 타이밍(`0xF3446000`)이 별도로 돌고 있음(패널만 active) 확인 → **"두 경로 독립 + 미연결 시 라인만 idle"**을 정적으로 봉인. (cam.py로 `busybox devmem` 또는 소형 read 헬퍼. 쓰기 금지.)

**HDMI 연결 상태에서만 확정(향후, 물리연결 필요):**
- 연결 시 패널 백라이트(`0x12006010`) off 여부, 패널 ch51/ch53 start 정지 여부, 패널 타이밍 정지 여부 — 즉 "순정이 실제로 끄는 범위".
- route-b ①②를 걸었을 때 패널 ch51/ch53 + 라인 ch52/ch54가 **동시에 start=1**로 유지되는지, 라이브뷰가 두 출력에 함께 뜨는지.
- 두 해상도 동시 공급 시 VDF 리사이즈 대역 한계(프레임드랍/언더런 레지스터).
