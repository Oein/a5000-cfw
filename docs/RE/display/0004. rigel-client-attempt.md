# 0004. 정식 Rigel 클라이언트 시도 (별도 프로세스)

- 상태: **영구 종료** (에뮬, 2026-11-19, 2회 재현 + 레지스터 레벨)
- 판정: 창은 수락되지만 합성이 패널(ch53)에 도달하지 않는다. detour-swap(0002)만이 패널 도달 벡터다.

## 1. 동기

detour-swap은 레코드 `+20`(phys)만 치환하는데 변경 게이트는 `+28`(서피스 id)을 비교하는 취약성이 있다. 이를 피하려고 "별도 프로세스가 `UX_DEBUG_CLIENT`(큐 `0x014b04b4`)로 창을 올리면 서버가 합성한다"는 정식 경로를 검토했다. 정적 RE상 SurfaceFlinger가 쓰는 경로(gralloc `scalara_framebuffer_device_open`, Connect, Register, createNativeWindow)와 동일하고 서버 슬롯은 1.10에 상설이며 서버 패치는 필요 없다.

## 2. 실험

별도 bionic 프로세스(`app/native/sftest/rgltest.cpp`, 빌드 타깃 `sftest/RGLTEST`)가 gralloc의 `rgl*` / `ws_hal_*`를 직접 호출했다.

- `ws_hal_alloc` 2회 (rc 0, 물리버퍼)
- `Connect()`는 rc=-1024 (핸드셰이크 실패)
- registerBuffers OK
- `rglCreateWindow(NULL, "UX_DEBUG_CLIENT", 640, 480, 0, 0, 2)`는 창 반환, 서버 errcode(창 메시지 `+0xA4`)=0 즉 수락
- `rglShowWindow`=1, `rglSwapBuffers` 1038회 전부 성공, 깨끗이 종료
- im.elf 무크래시. 반대로 **im.elf 내부(in-proc)에서 2번째 WindowClient를 만들면 크래시**한다. glibc로 빌드한 libObj 클라이언트는 오버레이 창 불가, registerBuffers 없음 등으로 사실상 쓸 수 없다 (`windowclient.md` §12).

결과: 단색 RED 픽셀이 패널에 나타나지 않았다 (screendump RED 0%). ch53 스캔아웃 버퍼 `0x8f7ee000` / `0x8f758000` 중앙은 0x0000으로 우리 버퍼 부재.

## 3. 네 가지 우회 각도 (모두 소진)

- (a) Connect -1024는 osal sync-reply 큐 미등록 때문이다 (`osal_reg_sync_msg_queue_cb`가 Connect 끝에서 호출). 오버레이 합성과 직교하므로 고쳐도 ch53 라우팅은 불변.
- (b) 핵심: Rigel 합성 출력(`sub_6789E8`, `0x6789E8`, glTexImage2D GL 합성)은 Android/메인서피스 평면이다. 패널 평면 전환은 ch51을 꺼서 라이브뷰와 공존 불가 (0003).
- (c) HW-FB 메인서피스(a6=0x1000)는 서버 create/post가 없어 창 목록에 등록되지 않는다. 메인서피스 attach는 Android 루트 평면이라 (b)와 같은 비패널 평면이다.
- (d) 클라이언트 버퍼 phys를 ch53 레코드에 넣는 유일한 수단은 stock VDF 제출에 올라타는 것이며, 이것이 곧 in-proc hook(detour-swap)이다. 별도 프로세스에는 합법 API가 없다.

## 4. 결론

- 패널 OSD 소스는 VPH ch53 `+0x20` 단일 레지스터이고 mux가 없다 (0003).
- 별도 프로세스 Rigel 클라이언트 교체안은 영구 종료. detour-swap이 유일 벡터.
- 교체 동기였던 취약성은 single-buffer in-place present(0002, e303d93)로 제출 캐던스와 분리되어 실익이 사라졌다. detour-swap의 런타임 패치 리스크는 실기 ptrace 주입 무크래시로 검증됐다 (`windowclient.md` §19).

## 5. 안전

에뮬 전용, RAM-only, 실기 미접촉, 프로덕션 코드 미변경.
