# 0001. Backup.bin 구조와 쓰기 안전 등급

> 상태: 구조·안전 집합 **derived + observed**. 목적: "영구 저장을 하려 할 때 어떤 propId를 펌웨어 경로로 쓰면 메뉴 조작과 동급으로 안전한가"를 확정(벽돌 위험 0 원칙의 근거).

## 1. 저장 2계층
- (A) 카메라 엔진 SDCom 상태 — 휘발(재부팅 복구)
- (B) `/setting/Backup.bin`(nflasha2 FAT) — **영구**. BK4 포맷, 약 403 서브시스템 / 17,093 속성, 체크섬 보유. `propId = (subsystem<<16) | index`. 펌웨어 API는 `BackupManager::Bkup_Read/Bkup_Write(propId, ...)`, 식별자는 `BKID_*`(심볼 197개). 공장 템플릿은 펌웨어 `0110_backup` 이미지에 있다.
- 실기 파일 파싱 결과: 프로퍼티 16,033개, 각각 현재 값 + resetData(공장 기본값, 파일에 내장) + size. 공장값과 다른 것은 **94개뿐**(사용자 실사용 변경). 파싱 신뢰는 저장된 Wi-Fi 프로필이 그대로 보이는 것으로 교차 확인했다(내용은 기재하지 않음).

## 2. 핵심 발견
- 메뉴 뷰 코드가 `Bkup_Write`하는 propId는 **전부 서브시스템 0x107 안의 173개**다. 0x107 = 앱/메뉴 설정 서브시스템. (모델 타입 0x1070316도 0x107이지만 메뉴-쓰기 집합엔 없음.)
- 변경된 94개 중 17개가 메뉴-쓰기 173과 교집합(= 메뉴가 영속함이 실증된 최고 신뢰 집합): `0x01070009 0x0107001F 0x01070030 0x01070033 0x01070040 0x0107004A 0x01070087 0x01070144 0x010706CA 0x010706DB 0x01070774 0x010708D5 0x010709D1 0x01070AC4 0x01070AC6 0x01070AF9 0x01070C7F`.

## 3. 안전 등급

| 등급 | 대상 | 정책 |
|---|---|---|
| **Tier A (안전)** | 서브시스템 0x107 중 메뉴-쓰기 173개 | 펌웨어 `Bkup_Write`로 **메뉴-유효 값**을 쓰면 메뉴 설정 변경과 바이트 단위로 동일. 공장값/현재값은 둘 다 실존 값이라 되돌리기·현상 유지는 즉시 안전. 새 값은 enum 범위 확정 후. |
| **Tier B (민감)** | 무선/네트워크/이름: 0x13E0000(기기 이름), 0x13E0002(저장 Wi-Fi AP), 0x13E0004(DLNA 대상), 0x13E0006(Wi-Fi Direct), 0x147xxxx(PC 이름) | 쓰기 가능하나 잘못 쓰면 저장 Wi-Fi 손상/연결 단절·개인정보 포함. 구조 확인 후 대면으로만. |
| **Tier C (금지)** | ① 0x107 외 모든 서브시스템(엔진/센서/렌더러 내부, 대용량 캘리브 0x003 포함) ② 0x107 내부라도 메뉴-쓰기 173에 없는 것(엔진 상태/카운터) ③ 기기 정체성 0x1070316 | 쓰지 않는다. |

- 이름 달린 소수(참고): `0x01070140` = CLOCK_FORCE_SETTLED, `0x01070309`·`0x0107030F~0312` = 하이라이트 재생 계열, `0x0107030B~030E` = 배경음악 설정. `0x010708BB`·`0x01070CD7` = YUV 타이밍 테이블(이름은 APP_*지만 캘리브성이라 Tier A에 있어도 건드리지 말 것).

## 4. 쓰기 규칙
1. 반드시 펌웨어 `BackupManager::Bkup_Write(propId, ...)` 경로. **raw `dd`/파일 직접 편집 금지**(체크섬·구조 파괴 = 부팅 불가).
2. Tier A propId + 유효 값만. Tier B는 대면·구조 확인 후. Tier C 금지.
3. 쓰기 전 복구 경로(NAND 전체 백업, SETTING 백업) 유지.
4. 영속이 꼭 필요 없으면 SDCom 휘발 set만 사용(재부팅 복구, 위험 0).

## 5. propId ↔ 설정 이름 매핑이 정적으로 안 되는 이유
- "기능ID → propId" 단일 디스패치 테이블이 없다. 매핑이 도메인 매니저별로 흩어져 있다.
- 설정 노드 클래스(CautionConfig, 198개)는 이름·구조만 가지며 참조하는 0x107은 `0x1070316`(모델 타입)뿐이다.
- 값 read/write는 libObj의 도메인 매니저가 하며, 전용 소형 매니저(`M_*`)만 1:1로 정적 추출이 가능하다(beep = `0x1070026`/`M_BEEP`, 시계 = `M_CLOCK` 군 `0x0107002D/2F/34, 00CA, 013E`, 미디어/폴더 = `M_MEDIA` 군 `0x01070036~39, 45`). 거대 매니저(ObjEffect/ObjDisplay/ObjRenderer)에 묶인 노출·WB·픽처이펙트·표시 계열은 정적으로 깨끗이 분리되지 않는다.
- 해법은 **실기 diff**: 설정당 1토글이면 충분(옵션 전부 불필요). 값 enum은 이미 settings 트리에 있어 범위 확인에 기기가 필요 없다. 커스텀 UI가 올릴 설정(10~30개 추정)만 매핑하면 된다 → [0002](0002.%20propid-mapping-measured.md).

## 6. 저장 타이밍 2종 (매핑 방법을 결정)
- **즉시 기록**(beep, AF 보조광, 피킹): 메뉴 변경 시 backup에 바로 기록 → `bk r`(라이브 읽기)로 즉시 diff.
- **flush 지연**(제브라 등 렌더러/STATE_MGR 경유): 값이 런타임 상태 관리자에 있다가 **정상 전원 off 때만** backup으로 flush → 라이브 diff에 안 보임. 격리 전원 사이클 파일 diff(변경 전 flush, 설정 1개만 변경, 변경 후 flush, pmca 전체 diff)로 확정. 부팅 노이즈 서브시스템 `{0x003,0x00D,0x051,0x058,0x059,0x092,0x093,0x0A1,0x0BC,0x125,0x185}`는 diff에서 제외.

## 7. 도구
- `/usr/bin/bk.elf`: `bk r 0x<propId>` 라이브 읽기, `bk w 0x<id> <HEX>` 쓰기(⚠️ 값 포맷 확인 필요 — 과거 `01000000`이 `00`으로 기록된 사례 있음).
- 파일 파서/diff 스크립트와 전체 덤프(16,033행), 메뉴-쓰기 173 목록은 `packages/data/re/backup/`(비공개, 개인 Wi-Fi 데이터 포함 가능).
