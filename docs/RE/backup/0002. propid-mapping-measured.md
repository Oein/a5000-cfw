# 0002. 설정 ↔ propId 실측 매핑

> 상태: **observed**. 방법: `bk r`(엔진 라이브 읽기)로 값을 보면서 순정 메뉴에서 설정 1개씩 토글해 diff. 파일/재부팅 불필요, 벽돌 위험 0.

## 확정 6개

| 설정 | propId | size | 값 매핑 | 신뢰 |
|---|---|---|---|---|
| 오디오 신호(beep) | **0x01070026** | 4 | on/off 계열(01↔03), 정적 `M_BEEP` 교차 확인 | 확정 |
| AF 보조광 | **0x0107005C** | 1 | 끔=1 / 자동=0 | 확정(AF 토글에만 반응) |
| 피킹 레벨 | **0x01070352** | 1 | 고=0 / 중=1 / 저=2 / 끔=3 | 확정 |
| 피킹 색상 | **0x01070360** | 1 | 색상 토글에만 반응. 실기 토글 관찰은 노랑↔흰 = 2↔0. (settings enum 기준 추정 매핑은 빨0/노1/흰2로 서로 어긋남 — 값 해석은 재확인 필요) | 확정(prop) / 값 매핑 재확인 |
| 제브라 enable | **0x010701B8** | 1 | 끔=0 / 켬=1 (공장 0) | 확정(전원 사이클 diff) |
| 제브라 레벨 | **0x010701B9** | 1 | 70=0, 75=1, 80=2, 85=3, 90=4, 95=5, 100=6, 100+=7 | 확정(90=04, 100=06 교차 검증) |

값 인코딩은 settings 트리의 enum과 다를 수 있어 **delta 패턴으로 매핑**한다.

## 노이즈로 판명 (설정 아님)
`0x010708B9`, `0x01070B75`, `0x010701B9`(일부 상황), `0x01070AF9`는 메뉴 조작 시 변동하는 트래커/페어/디스플레이 보조 상태. 매핑에서 제외.

## 방법론의 한계
1. 설정 propId가 뽑아둔 후보 집합(0x107 메뉴-쓰기 173) 안에 있어야 라이브 diff로 잡힌다.
2. 렌더러/비-0x107 설정은 후보 집합을 확장하거나 전원 사이클 파일 diff를 써야 한다. 제브라가 이 사례이며 0x107 안에서 propId는 확정됐지만 심볼은 `BKID_RENDERER_ZEBRA`(렌더러 서브시스템)로 별개다 — prop 번호는 확정, 심볼 정합은 미복구.

## 이외 미확정
- Superior/Intelligent Auto 전용 propId(정적 검색 0건)
- AF 보조광/피킹의 "새 값" 유효 범위(reset·current만 Tier A 안전 보장)
- PAL/언어/지역 등 Tier B 항목의 propId
