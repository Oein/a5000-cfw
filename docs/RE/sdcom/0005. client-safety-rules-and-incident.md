# 0005. SDCom 클라이언트 안전 규칙과 사고 기록

> 상태: **observed** (2026-11-12 사고에서 확정). 네이티브 SDCom 클라이언트를 작성할 때 반드시 지킬 규칙.

## 사고 요약
셔터 변경 실험 중 카메라 화면이 검게 변하고 네트워크가 무응답이 되었다(전원 재부팅 필요).

- **원인(확정)**: 테스트 클라이언트가 `SDComMsgIntParam`을 헤더에 데이터 멤버 없이 선언해 **4바이트만 할당**했는데 라이브러리 생성자는 0x10바이트를 기록 → 힙 오버플로 → `delete` 시 glibc abort(`free(): invalid next size`).
- 이 크래시는 `addParam` 직후에 발생해 0x101A는 **전송조차 되지 않았다**. 즉 명령 자체가 아니라 클라이언트의 메모리 손상이 문제.
- 결과: SDCom/osal 큐를 연 프로세스가 비정상 종료 → 화면 검정, ping 무응답(im.elf 또는 osal_uipc 정리 경로 문제로 추정, 미확인).

## 규칙
1. libsdcom 객체는 **크기를 정확히** 맞춰 할당한다: `SDComMsgIntParam` **0x10**, `SDComIPC` **0x44**, `SDComMsg` **0x48**. 선언에 패딩 멤버를 두고 `sizeof` 정적 검증을 건다.
2. SIGSEGV/SIGABRT/SIGTERM 핸들러에서 **반드시 disconnect** 후 종료.
3. 새 코드 경로는 SDCom **미연결 상태**의 단독 실행(드라이런, 환경 변수로 전환)으로 먼저 검증.
4. 바이너리는 SD가 아니라 RAM tmpfs(`/android/a5k/`)에서 실행(SD는 noexec, `/tmp`는 NAND vfat이라 쓰기 금지).
5. 상태 변경 전 사용자 확인. 카메라 크래시 = 물리 전원 재부팅(원격 복구 불가).

## 사고 이후 검증된 호출
수정판 클라이언트로 connect, GetParameters(116개), ShiftShutterSpeed(+1/−1 왕복)가 문제 없이 동작했다([0003](0003.%20camera-parameters-and-shift-commands.md)).
