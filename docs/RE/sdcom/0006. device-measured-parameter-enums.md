# 0006. 실기 측정 파라미터 enum 도메인 (0x1002 / 0x100A / movie·audio)

> 상태: **observed** — 2026-11-21 실기(ILCE-5000), ScalarDaemon `componentId=12`(sdprobe), 큐 0x1540432.
> 컨텍스트: **우리 ILCE Remote 앱이 open한 카메라(D2A/SmartRemote류 연결 모드)** 전경 상태에서 떠온 응답.
> 원본 덤프(비공개): `packages/data/re/device/getparams_full.log`(0x1002·0x100A×21), `packages/data/re/device/movie_audio.log`(0x300c·0x3102·0x300a).
> id↔이름 매핑: `packages/data/re/scalar/camera_params.tsv`.

이 보고서는 [0003](0003.%20camera-parameters-and-shift-commands.md)의 "enum 수치는 런타임 값표 → device 덤프로 확정" 항목을 **실측으로 확정/정정**한다.

## 0. 헤더 프로브

| msg | 의미 | 응답 |
|---|---|---|
| 0x000d | GetBodyFirmwareVersion | id=97 int=65546 (0x1000A → **FW 1.00.0A** 류) |
| 0x0009 | GetSystemState | id=69 int=**2** |
| 0x1002 | CameraGetParameters | result=0, **현재값 116개** |
| 0x100A | CameraGetSupportedParameters | result=0, **지원셋 155개(154+result)** |

### ⭐ 구조적 발견 — 0x100A는 param 118과 무관하게 전체를 한 번에 반환
- 앱은 0x100A를 **21회** 호출(매번 요청 param `id=118`에 서로 다른 값=118의 "조회 대상"을 실음)했으나, **21블록이 전부 동일한 155개**를 돌려준다.
- 즉 0x100A는 **per-param 쿼리가 아니라 "현재 컨텍스트에서 설정 가능한 전체 지원표"를 통째로 반환**한다. 파라미터별 순차 쿼리는 불필요했다 → [0003](0003.%20camera-parameters-and-shift-commands.md) §1의 "param 118" 서술을 이 사실로 보강.
- 분석은 블록 1개(tx=5)만으로 충분.

## 1. ⭐ 0x100A id 축은 0x1002 get-id 축과 **부분적으로 다르다** (가장 중요한 주의)

0x100A 응답의 paramId를 camera_params.tsv에 그대로 대입하면 **틀린다**. 세 가지 확증:

1. **ISO 사다리**(`0,100,125,…,16000` 24단)는 0x100A에서 **id=270** 아래 나온다. 그러나 get(0x1002)에서 ISO는 **id=269(isoGain)**이고 **270=meterMode**다. → 지원셋 270 ≠ get 270.
2. 0x100A의 **id 316~344 / 388~411 블록**은 전부 `16/-16`, `7/-7`, `32/-32` 같은 **(max,min) 범위쌍**이다. 그런데 get 축에서 그 id들은 전혀 다른 enum(예: get 331=steadyShotStill=2)이다. → 범위쌍 id는 get-id와 무관한 내부 열거.
3. 교차검증(현재값 ∈ 지원 arr)에서 **다수가 불일치(XX)**: 264·272·280·350·355 등. 같은 축이라면 현재값은 반드시 지원셋에 들어가야 한다.

**결론:** 0x100A는 **자체 열거(flat namespace)**다. get-id와 **우연히 일치하는 소수의 enum 엔트리만** 신뢰 가능하고, 범위쌍/빈배열/불일치 엔트리는 get-id 이름을 붙이면 안 된다.

### 0x100A 엔트리 4분류
| 종류 | 포맷 | 의미 | 신뢰도 |
|---|---|---|---|
| enum 배열 | type=5 arr | 허용 enum 값 목록 | sup-id==get-id ∧ 현재값∈set 이면 **동일축 확정** |
| 범위쌍 | type=1 int ×2 (`+N`,`−N`) | 미세조정 축의 max/min 경계 | id 축 분기 → get 이름 **금지** |
| 범위 마커 | type=3 (len 4/8, 값 없음) | 범위형 descriptor(267·276·370) | 경계값 별도 |
| 빈 배열 | type=5 arr[0] | **이 컨텍스트에서 설정 불가** | 경로 봉인 신호 |

| **selfTimer** | 328 | 범위쌍(-16) → 불명 |
| **steadyShot(정지)** | 331 | 범위쌍(16) → 불명. 동작 축은 [movie 0002] param 331 |

## 6. ⭐ 컨텍스트 한계 (봉인 조건 명시)

- 이 지원셋 전체는 **"우리 앱이 open한 카메라 모드"(D2A/SmartRemote류 연결)**에서의 값이다.
- **exposureMode {0,1,2}처럼 좁게 나온 것은 앱-연결 모드 제약일 가능성**이 높다. 순정 다이얼 **P/A/S/M/iAuto/SCN/Panorama** 각각의 전체 도메인은 이와 다를 수 있다.
- 현재값이 0003(바디 직접 M모드) 대비 바뀐 것(263: 19→0, 269: 200→0, 265: 0→10)이 그 종속성의 직접 증거.
- **완전 봉인 = 각 다이얼 모드에서 재덤프 필요.** 특히 §5의 flash/driveMode/selfTimer/steadyShot/storageFormat과 creative/scene(261/262)는 **촬영 모드별로 재측정**해야 전체 도메인이 닫힌다.

## 7. Movie / Audio 지원셋

> 동영상은 비활성 상태(0x300a MovieGetParameters가 result≠0으로 1개만 반환). 아래 지원표는 존재하나 **현재 비활성 컨텍스트** 값이다.

### 0x300c MovieGetSupportedParameters — param 2048~2052, 각 arr[6]
| id | arr[6] |
|---|---|
| 2048 | {0,0,0,0,1,1} |
| 2049 | {0,0,0,0,0,3} |
| 2050 | {1,1,1,1,1,0} |
| 2051 | {5,4,5,4,2,1} |
| 2052 | {0,0,6,6,4,4} |

- **6-열 구조**: 6개 "기록설정 슬롯"(파일포맷/프레임레이트 조합 추정)에 대해 5개 param(2048~2052 = 파일포맷/화면크기/프레임레이트/화질/비트레이트 류 추정)이 열로 나열된 형태. 동영상 비활성이라 열 의미 확정은 녹화 가능 컨텍스트에서 재덤프 필요. 동작 경로는 [movie 0001](../movie/0001.%20movie-record.md).

### 0x3102 AudioGetSupportedParameters — param 1280/1281, 각 arr[2]
| id | arr | 의미(추정) |
|---|---|---|
| 1280 | {0, 1} | 오디오 녹음 on/off |
| 1281 | {0, 1} | 윈드노이즈 리덕션(또는 레벨 플래그) on/off |

- 둘 다 **boolean 도메인**. 동작 경로 [movie 0001](../movie/0001.%20movie-record.md) §4(SDCom 0x3100).
