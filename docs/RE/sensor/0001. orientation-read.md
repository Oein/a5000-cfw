# sensor/0001 — 바디 회전/방향(orientation) 읽기

바디를 가로(landscape)로 눕혔는지 세로(portrait)로 세웠는지(+상하반전)를 **읽기 전용·벽돌위험 0**으로 얻는 경로를 정적 RE로 확정한다. 정밀 각도는 디지털 레벨 경로로, 최소 4사분면 분류는 그 각도에서 바로 도출된다.

신뢰도: `observed`(실기) · `derived`(바이너리 정적 도출) · `inferred`(추정).

---

## TL;DR
- **생산자 체인**: `accel.ko`(I2C MMA845x류, OUT_X/Y/Z·CTRL_REG1~5, OSAL 메시지 큐 드라이버) → `libdig_level.so`(원시 3축 레지스터 → atan2로 각도 → 4사분면 분류) → 두 소비 경로로 분기. `derived`
- **1순위 읽기 경로(route-b 네이티브, im.elf 내부)** = **SDCom `StartDigitalLevel` 명령 + `SDEVENT_DIGITALLEVEL_ANGLE_UPDATE` 이벤트 구독**. 폴링 아닌 구독, 완전 읽기, 벽돌위험 0. `derived`
- **값→방향(4사분면, `libdig_level` enum)**: `0`=가로 정상, `1`=세로(한 방향), `2`=가로 상하반전(180°), `3`=세로(반대 방향). atan2(-Y,-Z) 각도 밴드 + 이력(hysteresis)으로 결정. `derived`
- **대안 읽기 경로(트랙 A/Android)** = Android `SensorManager` `TYPE_ACCELEROMETER`/`TYPE_GRAVITY` (HAL `sensors.diadem.so`가 엔진에서 SDCom으로 중계). 앱 `OrientationWatcher`가 실제 사용 중, degrees {0,90,180,270} 산출. `derived`/일부 `observed`(앱 로그)
- **직접 커널 노드(`/dev`·`/sys`) 경로는 사실상 없음**: `accel.ko`가 표준 input/char 디바이스가 아니라 OSAL 큐로 itron/DSP측 accel API에 붙어 있음 → Linux/Android에서 보이는 유일한 창은 HAL(SDCom 경유). `derived`
- **실기 확정 필요**: a5000이 실제로 각도 스트림을 내보내는지(모델 게이트 `PROP_DEVICE_DIGITAL_LEVEL`). 순정 UI엔 전자수평계 OSD가 없음(display/0008)이나 센서/엔진 lib는 존재 → 스트림 자체는 살아 있을 가능성. 앱 `OrientationWatcher` 로그로 즉시 확인 가능.

## 1. 생산자: accel.ko → libdig_level.so

### 1.1 accel.ko (원시 3축)
`packages/data/re/ida/accel.ko.*` 기준. Freescale MMA845x 계열 I2C 가속도계 드라이버다.
- 레지스터 심볼: `I2C_SLAVE_ADDR`, `OUT_X_MSB/LSB`, `OUT_Y_MSB/LSB`, `OUT_Z_MSB/LSB`, `WHO_AM_I`, `FF_MT_CFG/THS/COUNT`, `CTRL_REG1~5`. (MMA8451/8452 레지스터 맵과 일치)
- 커널 모듈(vermagic 3.0.27)이지만 입출력을 **표준 Linux char/input 디바이스로 노출하지 않는다**. `osal_snd_sync_msg`/`osal_rcv_msg_tmo`/`udif_driver_register`/`acc_api_cb` 등 **Sony OSAL/UDIF 메시지 큐**로 상위에 데이터를 전달한다. 캘리브레이션은 `Backup_read`.
- 함의: route-b/Android에서 `/dev/<accel>`·`/sys/.../accel`를 cat 해서 읽는 경로는 **존재하지 않는다**(device 덤프 dmesg·node 목록에도 흔적 없음, `inferred`). 읽기는 반드시 상위 lib/HAL/SDCom을 거친다.

### 1.2 libdig_level.so (각도·사분면 산출 = 핵심 변환기)
`packages/data/re/ida/libdig_level.so.*`. PSM "디지털 레벨" 서브시스템. 원시 3축을 받아 각도와 방향 사분면을 만든다.
- `psm_dig_level_get_raw_register_for_ori` — accel 서브시스템에 OSAL cmd(send/recv)를 보내 원시 3축 레지스터를 읽어 전역 버퍼(valid 플래그 + X/Y/Z 워드)에 적재.
- `psm_dig_level_get_orientation_data` — 아래 분류 로직 수행, 결과 구조체 출력.
- `psm_dig_level_calc_angle` — `atan2`/`sqrt`/`sincos`로 세밀 각도 계산(전자수평계 눈금용). 외부 심볼로 `atan2`, `atan`, `sqrt`, `sincos` import.
- `psm_dig_level_angle_notification` / `psm_dig_level_req_notify_angle` / `psm_dig_level_notify_subsystem` / `psm_dig_level_snd_subsystem` / `psm_dig_level_snd_Infra_input` — 구독자에게 각도/방향 변경을 밀어주는(push) 알림 경로.
- `psm_dig_level_read_bkup` + `Backup_read`/`Backup_write`(subsystem 19857418) — 수평 기준 캘리브레이션 값. (쓰기는 공장 조정용, 범위 밖)

#### 4사분면 분류 로직 (`psm_dig_level_get_orientation_data`, `derived`)
원시 Y/Z로 롤 각을 만든 뒤 각도 밴드로 분류한다(출력 구조체: +4=유효 플래그, +8=방향값, +12=에러코드):

```
roll = atan2(-Y, -Z) * 180/π          (단위 deg, Y=word_E2C2, Z=word_E2C4)

 -38 ≤ roll ≤  38      → 0   (가로 정상 / landscape)
  52 ≤ roll ≤ 128      → 1   (세로 / portrait, 한 방향)
 142 ≤ roll ≤ 180
 또는 -180 ≤ roll ≤ -142 → 2  (가로 상하반전 / landscape 180°)
-128 ≤ roll ≤ -52      → 3   (세로 / portrait, 반대 방향)

경계 구간(38~52, 128~142, -52~-38, -142~-128) → 직전 방향 유지(hysteresis, a1+36에 이전값 보관)
```
추가로 **face-up/face-down(바닥·천장 보기) 감지**: 두 번째 `atan2`(피치, 75°~105° 등) 결과가 수직에 가까우면 방향이 모호하므로 강제로 `0`으로 고정하고 유효성을 재설정한다. 즉 바디를 하늘/땅으로 향하면 "가로 정상"으로 떨어진다.

→ **이것이 "가로/세로/상하반전" 분류의 정답 변환이다.** route-b가 원시 3축을 직접 받더라도 이 밴드 로직만 재현하면 된다.

## 2. 읽기 경로 (우선순위)

### (a) ⭐ SDCom 디지털 레벨 명령 + 이벤트 구독 — route-b 1순위
`libScalarDaemon.so` / `libObj.so`(= im.elf 오브젝트) 기준.

- **명령**: `StartDigitalLevel` / `StopDigitalLevel` (SDCom 요청). `request_params.tsv`에 이름 존재(수치 msgId는 메시지 카탈로그 `message_ids.tsv`에 미등재 → **실기에서 확정 필요**, 아래 §6). 동기(SyncProcessor)는 `migrateToAsync`로 비동기 전환, 비동기(AsyncProcessor)가 실제 알림을 돌린다.
- **엔진 배선**: `CommandProcessorStartDigitalLevel::AsyncProcessor::execute` → `InputService::startDigitalLevelNotify()` (libObj @ 0x37f0bc). 이 함수는 OSAL sync msg(큐 19858229)로 dig_level 서브시스템에 `angle_notification_on_off = 1`을 세팅한다. `StopDigitalLevel` → `stopDigitalLevelNotify()`로 off.
- **이벤트(구독 수신)**: `SDEVENT_DIGITALLEVEL_ANGLE_UPDATE` (libScalarDaemon 문자열 @ 0x116508). dig_level가 각도/방향이 바뀔 때 이 시스템 이벤트를 발생시키고, `StartDigitalLevel` Async job이 `removeWaitingEvent`로 받아 클라이언트에 전달. **폴링 불필요, 구독 모델**.
- **별도 경로**: `InputService::startOrientationRollNotify` / `stopOrientationRollNotify` (libObj @ 0x37f008)도 존재. OSAL msg(type=100, period=500) 전송 → 롤 값 주기 알림. 이것이 Android `DisplayManager.OrientationRollListener`의 네이티브 뒷면(앱에서는 a5000에 해당 Java 리스너 인터페이스가 없어 `NoClassDefFoundError`). 네이티브(im.elf 내부)에서는 호출 가능성 있음 — 실기 확인 대상.
- **벽돌위험 0**: 전부 휘발 엔진 상태(SDCom), 재부팅 복구. 읽기/구독만.
- **standalone(sdprobe/sdctl, componentId=12)로 가능?** `StartDigitalLevel`은 요청/이벤트 왕복이 필요하므로, 이벤트 수신까지 되는 D2A 세션이어야 한다(sdcom/0001의 standalone D2A 획득 미확정 항목과 동일 제약). 단발 Get으로는 안 됨 → im.elf 내부(route-b 주입)에서 `InputService::startDigitalLevelNotify` 직접 호출이 가장 확실.

### (b) im.elf 모델 파라미터(readModelParam) — 해당 없음
`model/<selector>` 셀렉터 전수 검색 결과 orientation/roll/level 전용 읽기 셀렉터는 **없다**(존재하는 건 `model/AUDIO_LEVEL_METER`, `model/STILL_PANTILT` 등 무관). 방향은 모델 파라미터 read가 아니라 **(a)의 이벤트 push**로만 뷰에 전달된다(`viewUnified2.so`가 `start/stopDigitalLevelNotify`를 직접 호출하는 것으로 확인). → 경로 (b) 폐기.

### (c) Android SensorManager (HAL sensors.diadem.so) — 트랙 A/대안
`packages/data/re/ida/sensors.diadem.so.*` = 표준 Android 센서 HAL.
- `AccelerometerSensor`("diadem 3-axis accelerometer"), `sensors_poll_context_t::pollEvents`, `AccelerometerSensor::setMsgParam(SDComMsgParam*)`, `invertAngleToAcceleration(sensors_event_t*)`. → **HAL이 원시 3축을 직접 I/O 하지 않고 SDCom 메시지 파라미터로 받아 `sensors_event_t`로 변환**한다. 즉 엔진(libdig_level)→SDCom→HAL→`sensorservice`→앱 `SensorManager`.
- 트랙 A 앱 실사용(`packages/android-app/.../OrientationWatcher.java`): `TYPE_ACCELEROMETER`(없으면 `TYPE_GRAVITY`)를 `SENSOR_DELAY_GAME`으로 등록, `onSensorChanged`에서 분류:
  ```
  y > +6.5  → degrees 0     (정상)
  y < -6.5  → degrees 180   (상하반전)
  x > +6.5  → degrees 270   (오른쪽이 위)
  x < -6.5  → degrees 90
  (THRESHOLD 6.5 m/s², 9.8 중) 변화 시에만 갱신
  ```
  — 이것은 `libdig_level`의 0/1/2/3 사분면과 **다른 인코딩(시계방향 degrees)**이며, 축-부호 대응은 실기 raw x/y/z 로그로 맞춰야 한다(§6).
- 같은 파일의 `com.sony.scalar.sysutil.didep.Settings.getAutoRotate()`는 **현재 방향이 아니라 자동회전 on/off 설정값**이다(`0`=켬, `1`=꺼짐). 방향 읽기로 오인 금지.
- route-b는 네이티브 프로세스라 Android 센서 스택 접근이 번거롭다 → (a)가 우선. 다만 "검증된 플러밍"으로 트랙 A 프로토타입에선 (c)가 정답.

## 3. 값 → 방향 매핑 요약

| 경로 | 값 | 의미 |
|---|---|---|
| (a) libdig_level/SDCom 사분면 | 0 | 가로 정상 (landscape) |
| | 1 | 세로 (portrait, 한 방향) |
| | 2 | 가로 상하반전 (landscape 180°) |
| | 3 | 세로 (portrait, 반대 방향) |
| | (face up/down) | 강제 0 |
| (c) Android degrees | 0 / 90 / 180 / 270 | 라이브뷰를 바로 세우는 시계방향 회전각 |

사분면 ↔ degrees 축-부호 대응(1↔90/270 중 어느 쪽, 2↔180)은 `derived` 단계에선 확정 불가 → **실기 raw 3축으로 봉인**(§6). EXIF 이미지 회전과도 동일 4분할이므로 `libexif`/`AvindexContentInfo.TAG_ORIENTATION`(재생측)과 교차검증 가능.

---

## 4. 이벤트(구독) 경로
- **SDCom**: `StartDigitalLevel` 구독 → `SDEVENT_DIGITALLEVEL_ANGLE_UPDATE` 수신(각도/방향 갱신 시). 폴링 대신 이벤트. `StopDigitalLevel`로 해제.
- **엔진 OSAL**: `InputService::startDigitalLevelNotify`(큐 19858229, on/off) / `startOrientationRollNotify`(type 100, period 500ms).
- **Android**: `SensorManager.registerListener`(TYPE_ACCELEROMETER/GRAVITY) 콜백.

---

## 5. 벽돌위험 판정
전 경로 **읽기/구독 전용 = 벽돌위험 0**. SDCom·OSAL 알림은 휘발(재부팅 복구). 쓰기 성격은 dig_level 캘리브레이션(`Backup_write` subsystem 19857418)뿐이며 이는 공장 수평 조정용으로 **범위 밖(건드리지 않음)**. 자동회전 **설정** 변경(didep.Settings)도 범위 밖.

---

## 6. 실기 확인 필요 (읽기전용, 지금 가능)
현재 실기 읽기전용 접근 + sdprobe/sdctl(componentId=12) 조회 가능 전제.

1. **모델 게이트 확인** — 앱/프로퍼티로 `ScalarProperties.PROP_DEVICE_DIGITAL_LEVEL`, `PROP_UI_DIGITAL_LEVEL_TYPE` 정수값 확인. a5000 순정 UI엔 전자수평계 OSD가 없다(display/0008)지만 센서/엔진 lib는 적재됨 → 스트림 생존 여부가 핵심.
2. **Android 경로 즉시 검증(가장 쉬움)** — 트랙 A 앱 `OrientationWatcher` 디버그 로그로 `Sensor <type> listening` 여부와 raw `x/y/z`, `Camera orientation <deg>` 전이를 바디를 돌려가며 확인. 이게 되면 a5000이 실제로 각도를 내보낸다는 증거 + 축/부호 확정.
3. **SDCom msgId 확정** — `StartDigitalLevel`/`StopDigitalLevel`의 수치 msgId가 `message_ids.tsv`에 없음. im.elf 내 `InputService::startDigitalLevelNotify` 호출 지점/OSAL 큐(19858229) 또는 sdprobe로 해당 요청 코드를 역추적해 확정. 이벤트 `SDEVENT_DIGITALLEVEL_ANGLE_UPDATE`의 수치 SD_EVENT_ID와 ParamList 레이아웃(각도 필드 오프셋, 방향 필드 유무)도 이벤트 왕복 계측으로 확정(sdcom/0004 "이벤트 id 왕복 미확인"과 동일 작업).
4. **사분면↔degrees 대응표 봉인** — 2·3의 raw와 전이를 대조해 `libdig_level` 0/1/2/3 ↔ Android 0/90/180/270 ↔ EXIF orientation 대응을 1:1로 고정.

## 7. route-b 권고
- 네이티브(im.elf 주입) UI/디버그에서 방향이 필요하면 **`InputService::startDigitalLevelNotify()` 호출 후 `SDEVENT_DIGITALLEVEL_ANGLE_UPDATE` 구독**(또는 `startOrientationRollNotify`)이 가장 깔끔한 읽기전용 경로. 각도 밴드→사분면 변환은 §1.2 로직 재현.
- 프로토타입/트랙 A 검증은 **Android `SensorManager` 가속도계**(§2c, 이미 `OrientationWatcher`로 구현됨).
- raw 3축 직접 접근은 Linux 커널 노드가 없어 불가 → lib/HAL/SDCom 경유 필수.
