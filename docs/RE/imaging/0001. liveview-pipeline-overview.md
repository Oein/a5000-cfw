# 0001. 라이브뷰 파이프라인 개요 — 센서에서 패널까지

- 상태: **derived**(av-cam.bin / libObj 정적 RE) + **inferred**(에뮬 동적 실행으로 경로 확정). 실기 미검증.
- 좌표계: 주소는 av-cam.bin VA(물리 PA = VA + 0x40000000). MMIO는 `0xF…` 그대로.
- 신뢰도: 블록·레지스터·함수는 derived, 프레임당 동작 순서·타이밍은 에뮬 실행으로 inferred.

이 보고서는 라이브뷰(모니터링) 한 프레임이 **센서 → 캡처 프론트엔드 → ISP/리사이즈 → VDF YC pin → VPH ch51 → 패널**로 흐르는 전체 경로를 한눈에 잡는다. 단계별 레지스터/함수는 [0002](<0002. aif-isp-vdf-path.md>), 제어 명령은 [0003](<0003. sdcom-imaging-control.md>), 자체 구동 가능성은 [0004](<0004. lean-stack-feasibility.md>).

---

## 0. 한 줄 요약

```
IMX156 ─SubLVDS─▶ SIF ─▶ CamCore FE(0xF3000000) ─AIF ch4─▶ IIB(0x60000000)
  ─▶ RC 리사이즈(0xF3880000): AIF ch23(R) → 1728→1024 H-리사이즈 → AIF ch26(W) → DRAM(0x8CE00000/0x8CF34000)
  ─▶ av-cam EE 시퀀스 stage1 → YC state 2(437737D4) → SendYCPin
  ─▶ VDF UpdateYuvThrough(4367EC50) → VphUpdateYuvCall(43661BC8) → 438F6CF4
  ─▶ VPH AIF ch51(0xF3441200): Y8 1024×516, pitch 1152 → VPH 스케일러(0xF3440300) 1024×516→640×480
  ─▶ 패널 YUV 평면(0x144 bit0) ⊕ OSD 평면(ch53) → 640×480 LCD
```

- **구동 주체는 av-cam.bin(µITRON 엔진)**. Linux/Android(im.elf·libObj)는 이 경로의 **영상 데이터에 전혀 관여하지 않는다** — OSD 평면(ch53)만 올린다([0002 §4](<0002. aif-isp-vdf-path.md>), display/0003).
- 센서 제어는 **쓰기 전용 P2S 직렬화기**(0xF3C00300, IRQ 38)로 나가며 **센서 ID read-back이 존재하지 않는다**. 센서 타입은 빌드 시 고정.
- 라이브뷰 ch51은 실제로 **8비트 1-plane(루마)** 를 운반한다. 크로마 채널은 이 모드에서 프로그램되지 않는다([0002 §3](<0002. aif-isp-vdf-path.md>)).

## 1. 엔진 객체와 태스크

| 역할 | 객체/클래스 | 주소/식별 | 근거 |
|---|---|---|---|
| 센서 드라이버 | `Camera::Imager::IMX156_ImagerCtrl` | vtable 0x43E8B868, 인스턴스 0x43D7031C(ch0 단일) | RTTI 0x43EA80B8; `sub_436AE9D8` |
| 엔진 프레임 틱 | 이벤트 소스 29 콜백 `4376C1E4` | 1프레임 = 33367µs(29.97fps) | 엔진 cfg 0x43D87254 +0x24 = 0x8257; `RE_ENGINE_TICK` §1 |
| VD 시퀀스(모니터링 상태기) | VD_Pre `4376CFDC` / VD_Post `4376FC48` / VD_Sequence `4376BDBC` | — | 파이프라인 §1~2 |
| EE(Image) 시퀀스 | `43546E40`(stage0=포스트잡, stage1=YC state2) | stage1이 `437737D4` 호출 | 파이프라인 §1 |
| YC 출력 | `SendYCPin 43773EA8`(SyncYCOut.cpp) | `dword_43D8AF48[0..3]` 상태 2일 때만 전송 | §7.3 근거 |
| VDF YC 수신 | `SystemCmdPinSend::YcPinExec 43672FC4` → `VdfInputCmdUpdateYuvPin 4367F700` | 모드 `&0xF0==0x20`이면 `UpdateYuvThrough 4367EC50` | SENSOR_ISP §2.6 |

엔진은 부팅 직후부터 **라이브뷰 EE를 매 프레임 돌린다**(SetMode·GetParam·SetExposure·Execute·P2S send가 프레임마다 실행). 즉 "라이브뷰 켜기"는 새 경로를 여는 것이 아니라 이미 도는 모니터링 상태기가 YC 출력을 내도록 **상태를 올리는** 것이다([0003 §3](<0003. sdcom-imaging-control.md>)).

## 2. 프레임 한 장의 단계 순서

에뮬에서 비정상 펌웨어 없이 관측한 프레임당 DMA/완료 순서(SENSOR_ISP §7.1, LIVEVIEW_IMAGE §2):

1. **센서 레지스터 송신(P2S)** — 노출/게인/리드아웃 테이블을 `436AE4EC`로 직렬 송신, IRQ 38로 완료.
2. **프론트엔드 유닛(0xF3000000) 프레임** — SubLVDS→SIF→CamCore. 완료는 "Pig" IRQ 36. AIF ch4가 FE 출력을 IIB(0x60000000)로 3456B×516라인 스트리밍.
3. **RC 리사이즈(0xF3880000)** — AIF ch23(R, IIB)로 읽어 1728→1024 수평 리사이즈, AIF ch26(W)로 DRAM 0x8CE00000/0x8CF34000에 교대 기록. 완료 = 그룹 0xF3881000 nibble3 → IRQ 41.
4. **EE stage1 → YC state 2** — `437737D4`가 `dword_43D8AF48[0]=2` 설정, VD_Post에서 `SendYCPin`.
5. **VDF → VPH** — `UpdateYuvThrough` → `VphUpdateYuvCall 43661BC8` → `438F6CF4`가 ch51을 같은 버퍼로 프로그램.
6. **VPH 합성** — 스케일러(0xF3440300) 1024×516→640×480, OSD(ch53)와 HW 합성해 패널 출력.

곁가지(영상 데이터 아님): FE ch5/ch1(iram 통계/보정 테이블 ping-pong), develop ch18(0x26000B 통계 출력). AE/AWB/AF 통계는 RC **이전**에 추출되므로 ch51 버퍼를 보지 않는다(LIVEVIEW_IMAGE §5).

## 3. 두 개의 타이밍 클럭 (라이브뷰가 검게 나오던 근본 원인)

라이브뷰에는 서로 다른 두 클럭이 얽혀 있고, 이 둘의 관계가 YC state 2 도달의 핵심이었다.

| 클럭 | 주기 | 역할 |
|---|---|---|
| 엔진 프레임(evsel 소스 29) | 33367µs(29.97fps) | 센서 프레임, EE/VD 시퀀스 |
| SYSV "V"(0xF3402000, 펌웨어는 0xF3400000+0x20xx로 읽음) | 실기 추정 = 엔진 프레임과 동일 | VD_Pre의 2V 위상 체크, VDF 프레임 게이트 |
| 패널 vsync(IRQ 101/102) | 60Hz(별도) | VPH shadow config 적용 |

- VD_Pre는 2V 모드(`dword_43D872C4=2`)에서 매 프레임 SYSV 위상 bit0(`+0x28`)를 자기 V 카운터와 비교한다. **SYSV V가 엔진 프레임당 정확히 1씩 증가하고 위상이 매 프레임 토글**해야 통과한다(LIVEVIEW_PIPELINE §2.2).
- VDF `UpdateYuvThrough`도 같은 카운터(`dword_43D55EF8`, IRQ 98 핸들러 `43655A90`가 기록)와 YC pin의 프레임 번호를 비교해, 맞지 않으면 pin을 error 5로 버린다(DISPLAY_SCANOUT §3.2).
- **결론**: 실기는 SYSV V = 엔진 프레임(33367µs)이며, 패널 60Hz는 별도 제너레이터에서 디커플된다. (에뮬은 SYSV를 60Hz로 돌려 위상이 매 프레임 상수가 되는 바람에 라이브뷰가 영원히 검게 나왔고, SYSV를 마스터 V로 바꿔 해결 — LIVEVIEW_PIPELINE §5, LIVEVIEW TL;DR. 이 사실은 실기 로직을 그대로 반영하므로 lean stack 설계에 직접 쓸 수 있다.)

## 4. "TEST SIGNAL" (테스트 패턴) vs 실제 센서

- 실제 센서 경로는 §2 그대로(SubLVDS→SIF→FE→RC). 센서는 P2S로만 설정되고 읽히지 않는다.
- 에뮬의 `cxd90014-aif.lv-source=bars|ramp|file:` 는 **RC 출력 AIF ch26 완료 시점**에 호스트 프레임을 DRAM(ch26 목적지)에 써 넣는 디버그 주입으로, 다운스트림(EE/VDF/VPH, 더블버퍼)은 전혀 바뀌지 않는다(LIVEVIEW_IMAGE Implementation status). 이는 펌웨어 내부의 "TEST SIGNAL"(AIF 테스트 패턴 소스)과 같은 주입 지점을 모사한 것이며, 실기 메뉴의 테스트 패턴도 센서 대신 AIF 소스를 바꾸는 방식으로 추정된다(inferred — 정적으로 테스트 패턴 토글 레지스터는 미확정).

## 5. 열린 질문

1. 라이브뷰가 루마 전용(param[24]=1, YC pin에 C 정보 없음)인 것이 실제 설정인지, 에뮬 상태의 결과인지. 실기는 컬러이므로 C-plane 경로(ch25 또는 `+64==1` Y/C 인터리브)가 어떤 모드 상태에서 켜지는지 미확정(LIVEVIEW_IMAGE §3).
2. 패널 톤 LUT(0x51AC..0x51E4)와 스케일러 외 CSC 유닛(0x340/0x380/0x3C0)의 디코드, 값 범위(16–235 vs 0–255).
3. SYSV V 주기 레지스터 `+0x3C`(64800→27000)의 단위, `+0x2010 & 3`(모드) 의미.
4. RC 입력 포맷 코드 0xA, 크롭 워드(+0x34..+0x42), 왜곡보정 경로(`+3113`) 선택 조건.
