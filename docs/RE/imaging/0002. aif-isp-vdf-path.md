# 0002. AIF · ISP · VDF 경로 상세 — 블록/레지스터/채널

- 상태: **derived**(av-cam.bin, `packages/data/re/ida/gfx/vdf_vph_driver.c`·`vdf_aif.c`, vph_regs.txt) + **inferred**(에뮬 동적 관측값). 실기 미검증.
- 좌표: av-cam VA(PA=VA+0x40000000), MMIO `0xF…`. `[?]`=미증명.

[0001](<0001. liveview-pipeline-overview.md>)의 각 단계를 블록 단위로 펼친다. 패널 합성(VPH ch51⊕ch53) 자체는 display/0003에서 다루므로 여기서는 **영상 데이터가 어떻게 그 ch51 버퍼까지 만들어지는지**에 집중한다.

---

## 1. 센서 제어 — P2S 직렬화기 (0xF3C00300, IRQ 38)

센서(IMX156)는 SIO/SPI/I2C가 아니라 **P2S("parallel-to-serial") 직렬화기**로 레지스터를 **쓰기만** 한다(SENSOR_ISP §1.3).

| 레지스터 | 접근 | 의미 | 근거 |
|---|---|---|---|
| 0xF3C00300 | RMW | bit0=config, `+0x0C` 바이트수/플래그 | `436AE62C`, `436AE684` |
| 0xF3C00340+4·i | W | 패킹 페이로드(워드당 1바이트, i<32) | `436AE6A4` |
| 0xF3C00800/+8 | W | 모드비트 / kick 토글(1,0,1) | `436AE62C`, `436AE734` |
| 0xF3C00904 | W\|=1 | IRQ ack/enable | ISR `436AE784` |
| **0xF3C00908** | R/W | **bit0 = start/busy**. busy 중이면 새 전송 거부 | `43A49854` |

- 패킷 빌드: `436AE414`(begin, SyncMode=2) → 레지스터별 `436AE5EC(addr,data)`(포매터 `43A49B36`가 연속 주소를 런으로 패킹) → `436AE4EC`(program+start). 완료는 **IRQ 38**(`436AE3EC`) → `43A49938`가 객체 이벤트 플래그 set, `436AE458`("P2SWaitTransComp", 2ms 타임아웃)가 대기.
- **AsyncInitial 초기 레지스터 19개**(`dw_43B36D78`): `00:34 0E:04 10:08 … B2:02`. 노출/게인/리드아웃 프레임 테이블은 `dw_43BDD108`/`43B1EF5C`(미디코드).
- **센서 ID read-back 없음.** 유일한 센서 "읽기"는 SIF 싱크코드 카운터(§3)와 이미저 온도 ADC("ImagerTempAD")뿐.
- 센서 전원/리셋: Backup GPIO 쌍(0xF90008/09 등)으로 `PowerOn 436AF630`이 토글. 실기 Backup에서 대부분 0xFFFFFFFF(미장착)이고 0xF9000E/0F=port0/pin1만 유효[?].

## 2. 캡처 프론트엔드 — CamCore "Pig" 유닛

이미지 데이터는 **SubLVDS PHY(0xF292B000) → SIF 싱크코드 수신(0xF3122000/0xF3123000) → CamCore FE 유닛**으로 들어온다.

- **FE 유닛 2개**: 0xF3000000(유닛0, IRQ 36), 0xF3100000(유닛1, IRQ 37), 그리고 0xF3120000(IRQ 35). 동일 레지스터 레이아웃(SENSOR_ISP §2.3):

| off | 의미 |
|---|---|
| +0x00/+0x08 | 서브블록 리셋/enable 비트 |
| +0x10 | 커맨드: 2·x=path A(bit1), 8·x=path B(bit3) 아밍 |
| +0x1C/+0x24 | path A/B의 **AIF 채널 마스크**(bit 0x1000<<k) |
| **+0x48/+0x4C** | 상태 A/B(W1C) — 프레임 완료 비트 |
| +0x50 | bit27/bit25 = 두 path의 IRQ enable |

- ISR(예 IRQ 36 `43A465F2`): `+0x48/+0x4C` 읽어 ack → 마스크의 각 AIF 비트에 대해 AIF "done" 훅(`43A970AE`→`438964B0`) 호출 → 대기자 리스트 실행.
- 라이브뷰에서 **아밍되는 것은 유닛0 path B/C**(상태 `0x0C000000`, 매 프레임 IRQ 36). 유닛1(IRQ 37)은 이 모드에서 비사용(SENSOR_ISP §7.2).

## 3. ISP / 리사이즈 — RC 엔진 (0xF3880000)이 ch51 버퍼를 만든다

라이브뷰 실제 영상 writer는 **RC(리사이즈) 엔진 "job_RCHV_dataset_main" `437712E4`**, 프레임당 `Sync_Kick_RCH 437DFDB0`가 1회 kick(LIVEVIEW_IMAGE §2).

- **AIF ch23**(0xF3881200, R): IIB(0x60000000)에서 FE 스트림 읽음(0xD80B × 516라인).
- **AIF ch26**(0xF3881380, nibble3, W): DRAM **0x0CE00000/0x0CF34000**(CPU로는 0x8CE00000/0x8CF34000)에 교대 기록. 완료 = 그룹 0xF3881000 nibble3 → **IRQ 41**(`438CB858`).
- 변환: 입력 1728px → 출력 1024px **수평 리사이즈**(516→516 라인), 2B/px 스트림 → **1B/px(루마) 평면**.
- RC 자체 메모리 체크(`437714A6..`): 필요량 = `pitch × lines × 2`, **param[24]=1이면 ÷2**. 여기선 param[24]=1이라 1-plane만 요구(1152×516=594432B ≤ 리스트 1140480B). 즉 펌웨어가 이 모드에서 **루마 전용 1-plane**을 구성한다(LIVEVIEW_IMAGE §2.2).

> **버스 주소 별칭**: RC/AIF는 DRAM을 0부터 어드레싱(bus 0x0xxxxxxx = PA 0x8xxxxxxx). VPH ch51은 CPU PA 0x8CE00000을 직접 쓴다. 변환 함수는 미확인[?].

### ch51 포맷(실행 관측)

| 속성 | 값 |
|---|---|
| 레이아웃 | 1-plane, 8bit/sample, 라인 선형 |
| 크기 | 1024×516 samples(`+0x24` × (`+0x2C`+1)) |
| 라인 pitch | 1152B(`+0x24`=0x400 + `+0x28`=0x80) |
| 버퍼 | 2개(0x134000 간격), 프레임마다 교대 |
| 크로마 | 이 경로엔 없음(C주소 0, `+64`=0, ch51만 start) |

## 4. VDF → VPH YC 경로 (영상 평면 프로그래밍)

YC state 2가 되면(`437737D4`) VDF가 YC pin을 받아 VPH ch51을 프로그램한다.

```
437737D4(dword_43D8AF48[0]=2) → SendYCPin 43773EA8(VD_Post)
 → SystemCmdPinSend::YcPinExec 43672FC4 → VdfInputCmdUpdateYuvPin 4367F700
 → (mode &0xF0==0x20) UpdateYuvThrough 4367EC50  [프레임 게이트: dword_43D55EF8 == pin.frame]
 → VphUpdateYuvCall 43661BC8 → 438F969C → 438F6CF4(a1=1 패널)
 → pbl_aif_set_func 43895C64 → ch51(0xF3441200) 레지스터 프로그램
```

- `438F6CF4`가 받는 YUV 디스크립터(DISPLAY_SCANOUT §3): `+0 Y주소, +4 Ystride(px), +12/14 w/h, +16 C주소, +32 fmt(0=packed 2B/px, ≠0=planar 1B+별도 C), +60 vflip, +64 Y/C 인터리브`.
- **VPH 스케일러 유닛0(0xF3440300)** 가 1024×516→640×480(LIVEVIEW_IMAGE §1.3): `0x308 = 0x1133199D`(H비 0x199D=((1024−1)<<12)/(640−1), V비 0x1133=((516−1)<<12)/(480−1)), `0x30C=0x003B2727` 로우패스, `0x310 bit0`=enable. 과거에 CSC로 오인했던 블록이 실제는 스케일러.
- 패널 레이어 on 비트 = `0xF3440144 bit0`(YUV), bit1(OSD). 실행값 `0x01000233`(vph_regs.txt f3440144의 필드 비트와 일치).

## 5. AIF DMA 채널 — 프레임버퍼 주소가 사는 곳

AIF 범용 드라이버 `pbl_aif_set_func 43895C64`(`vdf_aif.c`), 채널 테이블 **0x43B278D4**(12B/ch: `{group_reg, ch_reg, dir, nibble}`). 채널별 레지스터(DISPLAY_SCANOUT §2):

| off | 의미 |
|---|---|
| +0x00 | ctrl: **bit0=start/busy**(끝나면 HW가 self-clear, busy 중 start 거부), bits1-2=mode, bit11+16-19=IIB/ring |
| +0x04 | bit31=running |
| **+0x20** | **start 주소**(guest-physical) |
| **+0x24** | 라인당 바이트 |
| +0x28/+0x2C | ofs0 / count0(=라인수−1) |
| +0x30..+0x44 | ofs1..3/count1..3(4-D 주소 생성, YUV plane 인터리브) |
| +0x48 | VPH 채널: [15:0]=라인 pitch(부호), [31:16]=field offset |

- `pbl_aif_set_func`는 ctrl bit0이 아직 1이면 **−3(busy)** 반환. 즉 **채널 완료 = ctrl bit0 self-clear**가 HW 계약의 핵심.
- 카메라 파이프 채널 그룹(SENSOR_ISP §2.4): ch0–5(FE유닛0, 0xF3002000), ch6–11(FE유닛1), ch17–20(develop/YC), ch23–34(리사이즈/필터), ch51–58(VPH), ch59–68(VFX).
- **에뮬 모델 교차참조**: `packages/emulator/qemu-overlay/hw/dma/cxd90014_aif.c`(채널 완료+주입), `hw/misc/cxd90014_campig.c`(Pig 프레임 done+SIF), `hw/misc/cxd90014_p2s.c`(센서 송신). 이들은 실기 HW 계약을 모델링한 것이라 레지스터 의미의 레퍼런스로 유효.

## 6. 엔진 준비 게이트 (파이프라인이 열리기 위한 HW 완료 조건)

라이브뷰가 YC 프레임을 내려면 다음 완료들이 순서대로 필요(SENSOR_ISP §3):

| 게이트 | 필요 HW 동작 |
|---|---|
| G1 P2S 완료 | `0xF3C00908 bit0` self-clear, `0xF3C00904` 상태, IRQ 38 |
| G2 AIF 채널 완료 | ctrl `+0x00 bit0`/`+0x04 bit31` self-clear |
| G3 FE 프레임 done | Pig `+0x48/+0x4C` 상태비트 + IRQ 36/37/35 |
| G4 ISP/develop 완료 IRQ | 67–75(필요 여부 미확정 — 현재 경로에선 불필요했음) |
| G5 YC pin → VDF | G1–G4의 소프트웨어 귀결 |
| — 센서 ID/핸드셰이크 | **존재하지 않음** |

에뮬 결과(SENSOR_ISP §7.2): G1–G3 모델링으로 FE가 매 프레임 돌고 ch26→ch51까지 간다. develop/resize IRQ 67–75, VFX 77/78은 이 경로에 불필요했다(엔진이 kick 안 하거나 폴링). 단 영상 **내용**(컬러·스탯)에는 관여할 수 있음.

## 7. 열린 질문

1. Pig ISR가 기대하는 `+0x48/+0x4C` 정확한 상태 비트, `+0x10/+0x14/+0x20` 값(0x8/0x4, 0x161/0x981)의 의미.
2. 각 CamCore RTTI 블록(CamDev/CamNr/CamRdc 등)이 어느 베이스에 사는지.
3. RC 버스주소 변환(0x8CF34000→0x0CF34000), develop ch18의 0x40xxxxxx 공간.
4. 컬러 C-plane 경로를 켜는 모드 상태(param[24]=0 조건).
