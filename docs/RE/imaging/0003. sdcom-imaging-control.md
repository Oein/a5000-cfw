# 0003. SDCom 이미징 제어면 — 라이브뷰/노출/AF/캡처

- 상태: **observed**(일부 SDCom Get/Shift 실기 성공) + **derived**(메시지 ID·카메라 param 표 정적 도출) + **inferred**(YC 요청 트리거).
- 좌표: SDCom 메시지/param 표는 `packages/data/re/scalar/{message_ids,camera_params,request_params}.tsv`. av-cam VA는 PA=VA+0x40000000.

[0001](<0001. liveview-pipeline-overview.md>)/[0002](<0002. aif-isp-vdf-path.md>)가 **데이터 평면**이라면 이 보고서는 **제어면**이다: 외부(앱/UI)가 이미징 엔진을 켜고 끄고 노출/AF/캡처를 지시하는 통로. SDCom 전반(연결·메시지 카탈로그·Get/Shift·안전규칙)은 sdcom 카테고리에서 다루므로, 여기서는 **이미징 파이프라인에 직접 작용하는 부분만** 정리한다(중복 금지, sdcom/0003 보완).

---

## 1. 통로 구분 (혼동 주의)

| 통로 | 큐/ID | 지속성 | 벽돌위험 | 이미징 역할 |
|---|---|---|---|---|
| **SDCom 런타임 메시지** | `connect(0x1540432)` → addParam → sendSync | 휘발 RAM | 없음~낮음 | 라이브뷰/노출/AF/캡처 **런타임 제어** |
| 엔진 내부 상태기 | av-cam 모드 시퀀서 | 휘발 | 없음 | YC 출력 요청(§3) |
| Backup propId | 0x107xxxx | 영구 flash | 낮음(화이트리스트) | 네이티브 전용 설정 영속(제브라/피킹 등 — backup 카테고리) |

**핵심**: 라이브뷰 ON/노출/AF/캡처는 전부 SDCom 휘발 경로 → 재부팅 복구 = 벽돌 안전. 영상 데이터 평면([0002])은 SDCom이 **프레임을 pull하는 게 아니라** 엔진이 하드웨어 평면에 직접 그린다.

## 2. 이미징 관련 SDCom 명령 (derived, sdcom/0003 §5)

| 범주 | 명령(메시지 ID) | 비고 |
|---|---|---|
| 카메라 열기/라이브뷰 | `OpenCamera 0x1000` → `CameraStartPreview 0x1004` | 라이브뷰 시작 |
| 영상 사각형 | `GetVideoLayout 0x0604`, `StartYUVAreaGet 0x0603` | 픽셀 fetch가 아니라 레이아웃/변경알림 |
| 노출 조회 | `CameraGetParameters 0x1002`(116개), `CameraGetSupportedParameters 0x100A` | param id 256~388 |
| 노출 설정 | `CameraSetParameters 0x1003`(IntArray) | 대부분 설정이 여기로 |
| 노출 Shift | `CameraShiftShutterSpeed 0x101A`, `CameraShiftAperture 0x1019`, `CameraShiftProgramLine 0x102D` | IntParam id5=단계수(−63..63), **비동기 ~2s 반영** |
| AF/캡처 | `AutoFocus 0x1006` → `TakePicture 0x1008` → `StopTakePicture 0x1027`, 셀프타이머 0x1020/0x1021 | |
| 동영상 | `StartMovieRecording 0x3002` / `Stop 0x3003` | |
| 줌/초점확대 | `StartZoom 0x102E`/`StopZoom 0x102F`/`SetDigitalZoom 0x1030`, 0x1032/0x1033/0x1036 | |

주요 카메라 param(실기 관측값 기준, sdcom/0003 §1): 263 exposureMode(M=19), 265 focusMode(AF-S=0), 267 조리개(f값×100), 268 셔터([분자,분모]), 269 isoGain, 266 exposureBias.

- 조리개/셔터는 값표가 없어 **Shift 방식**으로 단계 이동(실기 성공: `0x101A id5=+1` 2s 대기 → 1/640→1/800).
- **피킹/제브라/AF보조광은 SDCom `0x1003`로 set 불가**(키 자체가 camera 표에 없음) → 엔진 내부 PARAMID + Backup prop 경로. (제브라 라이브 적용은 VDF 내부 0x59000E, 영속은 Backup 0x010701b8/b9 — backup/0003.)

## 3. 라이브뷰 YC 출력은 "명령"이 아니라 "상태 시퀀스"다 (중요)

라이브뷰 영상이 패널에 뜨려면 YC 출력 비트가 서야 하는데, 이것을 켜는 **직접 앱 명령이 없다**(RE_LIVEVIEW_REQUEST §0).

- 바이트 `0x43D874F4`(블록 0x43D87298+604)는 쓰기 대상이 아니라 **상수 ROM 테이블(`0x43B24F00[state]`)의 lookup 결과**다. YC 출력 비트(bit1/2)는 "모니터링" 상태(0x02/0x03/0x04 등)에서만 켜진다.
- 상태는 av-cam **모드 시퀀서**(`s_mode_sequencer`, 13모듈)가 올린다. 앱은 부팅 때 sync 요청(0x3003 류) 하나만 보냈고, 나머지는 펌웨어 자체 43-step 시퀀스가 진행한다.
- 즉 외부 제어면의 역할은 **카메라/모드를 모니터링 상태로 전이시키는 것**이고, 그 뒤 YC state 2는 [0001 §3]의 타이밍 게이트와 EE 시퀀스가 충족한다.

### 시퀀스가 막히던 두 지점(실기 로직 이해용)

1. **SA DSP 완료 대기**: 모듈10(이미저 컨트롤 시퀀서)이 이미저 start job 중 `ZIT ConvZ1C`(센서 결함 테이블 변환)를 **SA DSP 코어0(0xF34A0000)** 에서 돌리고 IRQ 51(source-A) 완료를 기다린다(RE_LIVEVIEW_REQUEST §0, RE_SA_DSP §0). 이건 외부 명령과 무관한 **엔진 내부 필수 단계**다 → lean stack 함의는 [0004].
2. **타이밍 게이트**: SA 완료 후 YC state 2는 SYSV V = 엔진 프레임 정합([0001 §3])에 달림.

## 4. 캡처(정지화상)의 추가 게이트 (제어면에서 본 요지)

`TakePicture 0x1008` 흐름은 RAW 버퍼 할당(dmm) + SA 매니저의 부트 유닛 free에 의존(RE_STILL_CAPTURE §0). 외부 명령 하나로 끝나는 게 아니라, 엔진이 메모리 레이아웃/SA 유닛을 확보해야 진행된다. 상세는 캡처 전용 RE 주제(여기선 제어면 트리거만 명시).

## 5. 외부에서 영상 프레임을 pull할 수 있나?

- `StartYUVAreaGet 0x0603`은 레이아웃/변경 알림이지 픽셀 fetch가 아니다.
- 연속 프레임을 클라이언트로 pull하는 경로(`CamseqGetPreviewFrame` 류)는 **미확정**(sdcom/0003 §5). 현 구조상 라이브뷰 영상은 엔진이 VPH ch51에 직접 그리고 OSD가 그 위에 합성되므로(display/0003), 외부 UI는 **영상을 받는 게 아니라 영상 위에 OSD만 올리는** 모델이다.
- 이 사실이 route-b 아키텍처(촬영=순정 OSD, 커스텀 UI는 MENU에서만)의 근거다([route-b-stock-osd-passthrough] 메모리).

## 6. 열린 질문

1. 모니터링 상태 전이를 유발하는 정확한 SDCom/모드 요청 코드(0x30xx 중 어느 것이 YC-out 상태까지 끌어올리는지).
2. Superior Auto 등 enum의 런타임 .bss 값(정적 불가, 메뉴 토글+라이브 덤프 필요 — sdcom/0003 §3).
3. 프레임 pull API 존재 여부(`CamseqGetPreviewFrame`).
4. SDCom param ID ↔ 엔진 PARAMID ↔ Backup propId 삼중 매핑의 미확정 구간.
