# 0001. 순정 메뉴 노드 트리 구조

> 상태: **derived**(정적, 높음). 패치 방법은 정적으로 도출했으나 /usr 플래시 수정은 벽돌 티어라 **적용하지 않음**(참고용). 대상: viewUnified2.so, CautionConfig.so.

## 1. 핵심 결론

a5000 메인 MENU는 코드가 아니라 **데이터(정적 노드 트리)** 로 정의된다. 탭/페이지/항목 구조는 `viewUnified2.so`의 `CmnViewSettingNode` 트리(a5000 root = `0x4822D4`)이고, 항목 하나하나는 `CautionConfig.so`의 설정 노드(`cmnViewSettingNodeRoot*` 계열, 약 198개)를 가리킨다.

## 2. 노드 클래스

- `CmnViewSettingNode(children**, numChildren, const CmnViewSettingProperties*)` — 40B, .bss에 놓이며 정적 생성자에서 초기화.
- `CmnViewSettingProperties { const _settingProperty* list; int count; }` — 8B.
- `_settingProperty { u32 propId; u32 type(0=resid, 1=int); u32 value; }` — 12B.
- propId 의미: 0=제목 문자열, 1/2/3=아이콘, 5=가이드 문자열, 10/11/14/15/19=값/플래그. 설정 트리 덤프에서 `13=`은 `CmnViewProcessDataMgr` **eventId**임이 교차 증명되었다(FlashMode=8, DRO=24, ArtFilter=26, Metering=22, Drive=7, Focus=13, ExpComp=20, AirplaneMode=181 등 6건 이상 코드 쪽 상수와 1:1).

## 3. 기종별 루트 선택

`viewUnified2.so`의 `sub_150ED0`이 `Bkup_Read(0x1070316)`(모델 타입 바이트)로 루트를 고른다.

| 모델 타입 값 | 루트 |
|---|---|
| 1 | 0x481E24 |
| 17, 32 | 0x4811A0 |
| 21 | 0x4810B0 |
| **23 (a5000)** | **0x4822D4** |
| 24 | 0x4830BC |
| 25 | 0x481BCC |
| 27 | 0x4813D0 |
| 28 | 0x48329C |
| 30 | 0x482B44 |
| 기타 | 0x481A10 |

a5000 공장 백업 템플릿의 0x1070316 값은 0x17(23). 이 값만 바꿔도 다른 기종 트리로 바뀌지만, 미지원 기능 항목이 섞이고 이 propId는 **기기 정체성**이라 쓰기 금지다([../backup/0001](../backup/0001.%20backup-bin-structure-and-write-safety.md)).

## 4. a5000 메뉴 규모

6탭 / 20페이지 / 106항목. 탭1 카메라 설정(6p) · 탭2 사용자 정의(4p) · 탭3 무선(2p) · 탭4 애플리케이션(1p) · 탭5 재생(2p) · 탭6 설정(5p). 실제 라벨 인벤토리는 [0002](0002.%20stock-menu-inventory-device-verified.md).

## 5. 노드 생성과 패치 포인트(참고)

- 노드는 `sub_152964`(정적 초기화, 약 15KB)에서 `CmnViewSettingNode::CmnViewSettingNode(this, arr, n, props)` 호출로 만들어진다.
- 자식 **개수**: 호출 직전의 Thumb `movs r2,#imm8`(`0x22nn`) 즉시값. 예: 카메라 1페이지 노드는 0x155538의 `06 22`.
- 자식 **항목**: 페이지 배열 원소는 `.rel.dyn`(파일 오프셋 0x2D9C0 부근, 약 88,228개 8B 항목)의 `R_ARM_ABS32` 재배치. `r_info=(symidx<<8)|2`의 symidx를 바꾸면 다른 설정으로 교체되는 구조이며, viewUnified2가 import한 설정 약 182개를 쓸 수 있다.
- 미-import 심볼 추가는 `.dynsym` 확장이 필요(미구현).
- 이 모든 것은 **/usr 플래시 수정**이므로 우리 프로젝트는 쓰지 않는다. 대신 별도 프로세스/주입 UI로 우회한다.

## 6. 뷰별 하위 메뉴 테이블

`CmnViewMenuItemStruct`(40B, libObj `CmnViewMenuData`): `+0 subItems*`, `+4 u8 count`, `+8 id`, `+0xC..+0x18 resid x4`, `+0x1D execType`, `+0x20 optionNum`, `+0x24 char*`. 장면 선택, 얼굴 인식, DISP 등 뷰별 선택지가 이 형태다.

## 7. 7번째 탭 / 항목 주입은 RAM-only로 불가 (결론)

- 탭바는 노드 트리와 별개 경로다. `PAS_MenuListTab`(viewUnified2, 위젯 id 0xA056F604) 클래스에 **6탭이 컴파일 타임 상수**로 박혀 있다: 표시 수 = `min(노드 자식 수, 6)`(상수 반환 `sub_2EC9AA`에 의해 cap=6), 생성자 `sub_2EE4F4`가 `PAS_BtnPopup` 6개를 객체 멤버로 임베드하고 렌더(`sub_2F00E0`)가 탭 번호로 직접 인덱싱. 순정 10개 루트의 최상위 탭 수는 4·5·6 뿐.
- 노드 래퍼 주입(`sub_150ED0` 후킹으로 자식 +1)은 모델/벨트 레벨까지는 렌더러가 수용하지만, 보이는 7번째 탭은 `.uxc`/클래스 수정 = /usr 리소스 수정 필요 → 벽돌 티어.
- 마지막 설정 탭 벨트에 "항목" 추가도 4중으로 막힌다: 부분 wrapper가 `sub_150F8C`가 즉시 호출하는 노드 +8 등을 null 전달해 im.elf SIGSEGV / 벨트가 +36 selected 체인으로 그룹을 해석해 래핑이 첫 홉에서 풀림 / OK 액션(action 47 → `sub_152640`)은 하강 전용이라 open-request 미발화 / 벨트 라벨은 프레임워크 resid(0x0204E000류)만 받아 새 문자열을 RAM-only로 넣을 수 없음.
- 결정: Mods는 메뉴 UI 없이 로더 전용으로 간다([../boot/0003](../boot/0003.%20autostart-via-dmode-and-env.md) 참조).
