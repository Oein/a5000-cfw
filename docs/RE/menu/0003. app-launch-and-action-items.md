# 0003. 메뉴의 앱 실행과 액션 항목 — 네이티브 실행 경로

> 상태: **derived**(정적, 기기 무관) + 일부 observed. 목적: route-b 캐스케이드 메뉴가 순정 6탭의 **비설정 항목**(Android 앱 실행, 액션)을 순정과 동일하게 트리거하는 방법과 벽돌 위험/게이트 확정. 설정값(ENUM/BOOL/RANGE)은 settings 카테고리.

## 1. 세 가지 메커니즘

| 메커니즘 | 무엇 | 네이티브 호출 | 위험 |
|---|---|---|---|
| A. 전용 View 열기 | 확인 UI가 필요한 액션(포맷, 초기화, DB 복원, 폴더, USB 등) | `viewManagerIf::openView("view/XXX")` → `viewXXX.so` 안에서 엔진 명령 | 액션별 |
| B. 모델 실행 | 토글/즉시 실행(비행기, 데모 등) | `requestModelExecute("@Mxxx", cmd, ParamList)` | 없음~영구(backup prop) |
| C. Android 월드 핸드오프 | "애플리케이션" 탭 — 진짜 Android 앱 실행 | ABT 월드 스위치 + SyncAndroid | 없음(RAM/mount만) |

함정 교정: `View::requestApplicationExecute`는 이름과 달리 **Android 앱 실행이 아니라** 모델 실행 이벤트를 ViewManager 큐에 넣는 범용 디스패처(`requestModelExecute`의 꼬리 호출)다.

## 2. Android 앱(PMCA) 실행

a5000은 네이티브 Sony Linux(메인)와 `/android` chroot(Android 2.3.7)를 **동시** 구동한다. PMCA 앱(OpenMemories Tweak 포함)은 chroot 안의 평범한 액티비티다.

- 런처: `com.sony.scalar.dlsys.scalaralauncher.ScalarALauncher`("애플리케이션 목록" UI). 관련: `ScalarACustomKeyLauncher`, `UsbConnectionActivity`, `ScalarADisclaimerMenu`.
- 포그라운드 복원 상태 파일: `/android/data/resume_info.txt`, 포맷 `resume:<package>:<class>:`. 비어 있으면 기본값으로 런처가 복원된다.
- 네이티브↔Android 브릿지: `com/android/server/DAConnectionManagerService`(JNI). 월드 스위치는 ABT 아비터(`arbiter.so`, `libarbiter_proxy.so`)의 `ABT_set_state(type, cmd, func, param, env, blob[0x28], last)`.
- cmd enum(arbiter.so 문자열): `ABT_CMD_SET_D`(Android "D" 월드), `SET_A`(카메라 "A"), `APP_INFO`, `ANDROID_EXIT`, `ANDROID_EXIT_CMP`, `ANDROID_BOOT_CMP`. 카테고리: `ABT_CAT_PB/USB/OFF/REC`. 내부 post(`sub_1440`)는 `[type][cmd]` 두 워드 뒤에 func/param/env 문자열(각 128B)과 blob(+0x188)을 실어 ABT 워커 큐로 보낸다 — func/param/env는 숫자가 아니라 컴포넌트/인텐트 문자열 운반용.
- **SyncAndroid 역할 교정**: `libSyncAndroid.so`는 ABT/arbiter를 import하지 않는다. `_act/_sus/_res`는 `/android/data` 라이프사이클(bk1/bk2.bak 백업, mount, dosfsck, factory reset)만 담당 — 디스플레이/입력 핸드오프가 **아님**. (이전 가설 정정.)
- 디스플레이: Android SurfaceFlinger는 Rigel 윈도우 서버의 클라이언트 하나(`UX_WINDOW_SYSTEM_ANDROID`).
- OM Tweak 좌표: 패키지 `com.github.ma1co.openmemories.tweak`, 런처 액티비티 `.MainActivity`. chroot에 `am`이 있다(`/android/system/bin/am`).

### 브릭0 구현 권장
`am start`만으로는 화면·입력이 넘어가지 않는다(Rigel 합성 전면 + ABT 입력 소유권). 권장 순서:
1. 우리 오버레이(Rigel WindowClient) teardown
2. Sony 자신의 핸드오프 재사용 — 1차 버전은 순정 런처(ScalarALauncher)를 전면화(순정 탭4와 동치, 완전 브릭0), 2차로 `chroot /android /system/bin/am start -n com.github.ma1co.openmemories.tweak/.MainActivity`로 직행
3. 종료 시 `ABT_CMD_ANDROID_EXIT`로 복귀 후 윈도우 재생성

미확정: ANDROID_* cmd의 **숫자값**과 프로덕션 호출 시퀀스. libObj 내 `ABT_set_state` 직접 호출 2곳은 둘 다 테스트 모드 코드(하드코딩 type=4/cmd=0 디버그 exit)이고, 런처 문자열(`ScalarALauncher`, `resume:`)은 libObj에 없어 `libmpr.so` 계열 쪽 호출로 추정. 실기에서 탭4 진입 전후 ABT 덤프로 관찰해 복제할 것.

## 3. openView 확정 오프셋 (route-b in-proc용)

| 심볼 | libObj 주소 | 적합성 |
|---|---|---|
| `ViewBase::openView(char const*,int,bool)` | 0x00394288 | 살아있는 `ViewBase*`가 필요 — in-proc 부적합 |
| **`viewManagerIf::openView(char const*,int)`** | **0x00394A1C** | **채택** — 싱글톤 경유, 뷰 객체 불필요 |

0x394A1C → `sub_394944` → ViewManager 싱글톤(`dword_EEDDD8`)에 open-view Event(`0x11012001`)를 push. `getModelInfo`(0x39485C), `requestModelExecute`(0x3948E0)와 완전히 같은 패턴이라 이미 신뢰·사용 중인 엔트리와 동급의 RAM/엔진큐 호출이다. viewUnified2.so에 존재가 확인된 view-id 리터럴: `view/FORMAT`, `view/INITIAL_SETTING`, `view/SELECT_FOLDER`, `view/CREATE_FOLDER`, `view/USBAUTO`/`USBMASSSTORAGE`/`USBMTP`/`USBREMOTEPC`, `view/AREA_SET`, `view/KEYBOARD`, `view/MANUALREPAIR`, `view/AUTOREPAIR`. 주의: 오버레이가 위에 남아 있으면 뷰가 떠도 안 보인다(오버레이 teardown은 display 쪽).

## 4. 액션 항목별 경로와 위험

### 설정 탭
| 항목 | 경로 | 위험 | 게이트 |
|---|---|---|---|
| 포맷 | A: `view/FORMAT` → viewFormat.so → 엔진 FORMAT | **파괴적**(SD 데이터 소실) | **EXPERIMENTAL 필수**, 2단 확인 |
| 설정 리셋(Initialize) | A: `view/INITIAL_SETTING` → viewInitialSetting.so | **파괴적**(커스텀 설정 소실, backup 기록) | **필수** |
| 이미지 DB 복원 | A: `view/MANUALREPAIR` → viewManualRepair.so (재생측 `MANUAL_REPAIR_FOR_PLAY`, 자동 `AUTOREPAIR`) | DB 재작성(원본 보존, 장시간/중단 위험) | 권장, 자동 실행 금지 |
| 파일 번호 | B/A | 경미 | 리셋은 권장 |
| REC 폴더 선택 / 새 폴더 | A: viewSelectFolder / viewCreateFolder | 안전 | 없음 |
| 폴더명 형식 | B enum | 안전 | 없음 |
| 데모 모드 | B + viewDemoMoviePb | 안전 | 없음 |
| USB 연결 | A: viewUsbAuto/MassStorage/MTP/RemotePc | 안전 | 없음 |
| HDMI 해상도/제어 | B: `ui_libInfraHdmi.so` | 안전 | 없음 |
| 언어 | B enum(backup) | 낮음 | Tier B |
| 지역/날짜시간 | A: viewAreaSet 등(PAL/NTSC 연동 가능) | 낮음~중 | Tier B |
| 클리닝/캘리브레이션 | A: 전용 view | 안전~중 | 캘리브는 권장 |
| 버전/미디어 정보/인증 로고 | 읽기 전용 | 안전 | — |

### 무선 탭
- **비행기 모드**: `CmnViewProcessDataMgr` 그룹 쓰기 `setParameter(eventId 181, raw)`. raw 0=비행기 ON / 1=OFF(`AirplaneModeOn 15=0`, `AirplaneModeOff 15=1`). 엔진이 순정 메뉴 토글과 동일하게 라디오 ON/OFF + backup 영속을 처리하므로 메뉴 조작과 동급 — **벽돌 0, 게이트 불필요, route-b 배선 완료**. (`libInfraAirplaneMode.so`의 Backup 읽기/쓰기는 라디오 inhibit 영속용일 뿐 메뉴 토글 경로가 아님. `model/AIRPLANE` sel1/0x101 읽기는 상태 표시용.)
- 장치 이름 편집: `view/KEYBOARD` + `NsMiscSetDeviceName`(ui_libNetService, 형식 검증 `PsmApiCheckDeviceNameFormat`), 안전.
- SSID/PW 재설정, 네트워크 설정 리셋(게이트 권장), WPS 푸시, AP 설정, MAC 표시: NetService API/전용 view.
- 스마트폰/컴퓨터 전송, TV 보기, NFC(ui_libInfraNfc): 후속 구현.

### 재생 탭
삭제(파괴적, 삭제 확인 UI 유지), 보호/인쇄지정(DPOF)/회전(Sony rotateImage), 슬라이드쇼/확대(`view/ZOOM_PB`)/인덱스(`view/INDEX_PLAYBACK`)/보기 모드/표시/4K 재생(HDMI 출력 모델)은 안전.

### 위험 분류 요약
- 자동 실행 가능: 비행기, 장치 이름, 데모, USB/HDMI 모드, 폴더, 재생 메타, 정보 표시
- **파괴적 — 게이트와 2단 확인 필수**: 포맷, 설정 리셋, DB 복원, 삭제
- Tier B(민감): 언어, 지역(PAL/NTSC), 캘리브레이션
- 어느 항목도 raw Backup 쓰기나 비-메뉴 BKID를 건드리지 않는다 — 전부 순정 메뉴가 쓰는 경로라 "메뉴 조작과 동급" 안전 등급([../backup/0001](../backup/0001.%20backup-bin-structure-and-write-safety.md)).

## 5. 이미지 DB 복원 (SDCom으로 불가)
- SDCom 복원 메시지는 없다(Media 군은 0x0501~0x0505뿐). 트리거는 in-process MWF 모델이다: 재생측 `ViewManualRepairForPlay`가 `model/REPAIR`에 init(cmd 0xF01, 미디어 id@0x12000001, 2@0x101)을 보낸 뒤 **`@M05E`, cmd 3**으로 실행(viewUnified4 `sub_FC600`), cmd 4/5/6은 cancel/finish/dispose. 내부는 `M_BRO_REPAIR` 상태머신 → `ObjSalvage` 엔진.
- `im.elf`는 이미지 서버일 뿐 복원 코드를 갖지 않는다. 복원 모델/뷰/엔진은 viewUnified*/libObj/libMWF를 로드한 카메라 앱 프로세스에서 돈다.
- 진행률은 `getModelInfo("model/REPAIR", 4)`의 param 0x107(→ `PAS_BarProgress::setProgress`)로만 읽히고 외부 노출 경로가 없다.
- 결론: 외부 프로세스는 **프로세스 내부 주입**으로만 트리거/관측 가능. 트랙 A 앱은 "복원 중" 오버레이로 대체했다.
