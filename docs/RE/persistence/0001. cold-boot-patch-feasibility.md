# 0001. 콜드 부팅 영속화(cold-boot persistence) 타당성 지도

> 상태: 부팅 체인·검증 스킴 **derived**(로컬 디컴파일 + 공개 fwtool 교차확인), 자동 실행 경로 **observed**(에뮬 확정), 플래시 쓰기 경로는 전부 **실기 미검증**.
> 성격: **CLAUDE.md §1 최고 벽돌 위험 경로의 타당성/메커니즘 조사**. 익스플로잇·플래시 절차서가 아니다. 실기 쓰기는 하지 않았고 하지 않는다.
> 목적: "장차 플래시 쓰기가 허용된다면, route-b 패치를 매 콜드 부팅마다 자동 실행시킬 주입 지점은 어디이고, 각 지점을 막는 무결성/진위 검사는 무엇이며, 벽돌/복구 비용은 얼마인가"를 위험 순위로 정리.

---

## 0. 결론 요약 (TL;DR)

1. **a5000(SoC CXD90014) 펌웨어에는 전자 서명(공개키 서명)이 없다.** 보호는 **대칭 암호(공개된 AES 키) + 전진 체크섬(CRC32/16비트 합)**뿐이며, 둘 다 키·알고리즘이 공개되어 **위조 가능**하다. 즉 "서명을 뚫어야 해서 불가능"한 벽은 a5000엔 **존재하지 않는다**(§2, §3).
2. 그럼에도 **권장 영속화 경로는 플래시를 전혀 건드리지 않는 `/setting` 기반 LD_PRELOAD 자동 실행**이다(§4 경로 a). 콜드 부팅에서 실행되고, `/setting`은 rw FAT + NAND 백업 복구라 **벽돌 위험 0**이며, 서명·암호·WBI를 전부 우회한다. 플래시 수정이 주는 추가 이득이 거의 없다.
3. 플래시를 실제로 고쳐야 하는 유일한 진짜 블로커는 서명이 아니라 **WBI(warm-boot 스냅샷) 정합성**과 **복구 불변식**이다(§4, §5). 이는 암호학이 아니라 상태 정합성 문제다.
4. **실기 확인이 필요한 미지수**: (a) 부트로더가 "업데이터 모드 플래그"를 FAT 파일로 보는지 서브-LSI 상태로 보는지, (b) 콜드 부팅 시 `wbi_memclr`/부트 유닛 프리로드 실제 값, (c) 비-플래그 부트로더 복구 진입(키 홀드) 존재 여부, (d) 롤백/퓨즈 카운터의 부재(현재까지 a5000에서 **발견되지 않음**).

## 1. 부팅 체인과 각 단계가 어디서 검증되는가

로드 관계(누가 누구를 로드하는가)와 무결성 검사 위치:

| 단계 | 주체 → 대상 | 파티션 | 지속성 | 이 단계의 무결성 검사 |
|---|---|---|---|---|
| 0. BootROM | SoC 내장 ROM → 부트로더 | on-chip | 고정(마스크 ROM) | **정적 분석 불가**(덤프 없음). a5000에서 secure-boot 증거 없음(§2.4) |
| 1. 부트로더 | 내부 RAM 0xC0000000 상주 → 커널+initrd를 RAM에 적재 | 예약 flash 블록(0x0~0x40000), 업데이트 비대상 | 영구(업데이트로 안 써짐) | 커널/initrd/av-cam/Backup를 RAM에 올리고 hand-off 작성. **런타임 서명 검증 코드 없음**(아래 §2.2) |
| 2. 커널 | zImage/Image → `/sbin/init` | nflasha3(정상) / nflasha1(업데이터) | 영구 | cmdline은 부트로더가 PA 0x80033000(kemco 블록) 또는 빌트인으로 전달. 서명 없음 |
| 3. rootfs/init | `/sbin/init` → `bootin.elf` → `im.elf` | nflasha7(/), nflasha15(/usr), nflasha3(/system) | 영구 | `init`은 **파일 존재 검사만**(`/setting/mode/dmode` 등). 코드 서명 없음 |
| 4. im.elf (메인 UI/엔진) | → libObj.so → View들 | nflasha15 | 영구 | 애플리케이션 로더. 서명 없음 |

핵심:
- **정상 콜드 부팅 경로는 평소 거의 실행되지 않는다.** 카메라는 공장이 빌드 시 만든 **WBI 스냅샷(nflasha5)에서 매번 warm 재개**한다([../boot/0002](../boot/0002.%20wbi-warm-snapshot.md)). `init`→`bootin`→`im.elf`의 콜드 경로는 WBI drop/무효화 시에만 돈다. → 영속 주입을 **콜드 경로에만** 심으면 평소엔 실행되지 않을 수 있다(§4 경로 a가 이걸 해결).
- **단계 1(부트로더)·단계 0(BootROM)은 덤프가 없어 정적으로 열 수 없다.** 다만 이들은 업데이트로 **써지지 않으므로** 주입 대상이 될 수도 없고, 동시에 복구 생명선이다(§5).

### 1.1 bootin.elf = 서명 없는 얇은 런처 (derived, `packages/data/re/ida/bootin.elf.c`)
`bootin.elf`는 검증기가 아니라 **쉘 스크립트성 런처**다. `main`은:
1. `/setting/mode/dmode`를 읽어 debug/boot 모드 비트를 세팅(값 0/1/2/3 → `im.elf`에 넘길 인자, `l/w/g/s` 플래그),
2. `im.elf <flags> debug ... lazy-global &` 커맨드라인을 문자열로 조립,
3. `system()`으로 `im.elf`를 fork.

어떤 체크섬·서명·해시 검사도 없다(임포트가 open/read/system/putenv/mount 등 libc뿐, 암호 심볼 0). **환경변수(LD_PRELOAD 포함)가 bootin→im.elf로 상속**되는 구조가 §4 경로 a의 토대다.

## 2. 무결성/진위: 체크섬인가 서명인가 (핵심 질문)

### 2.1 공식 펌웨어 패키지(.dat / FDAT)의 보호 스킴 — 공개 사실로 확정
로컬 체크아웃된 공개 도구 `packages/tools/fwtool.py`(ma1co, 공개 프로젝트)의 소스가 스킴을 **그대로** 드러낸다. 이는 이미 공개된 지식이다.

- **바깥 `.dat` 컨테이너**(`fwtool/sony/dat.py`): 끝의 `DEND` 청크에 **CRC32** 한 개. `readDat`은 파일 전체(마지막 청크 헤더+DEND 제외) CRC32를 재계산해 일치만 본다. → **전진 체크섬, 키 없음, 위조 자명**.
- **안쪽 FDAT 펌웨어 이미지**(`fwtool/sony/fdat.py`): 헤더에 `checksum`(CRC32, 헤더 영역 대상) + 블록마다 16비트 합 체크섬(`BlockCrypter._calcSum`). 본문은 **블록 암호로 암호화**되어 있고, SoC별 crypter가 매핑돼 있다:

| SoC 세대 | crypter 클래스 | 키 |
|---|---|---|
| CXD4105/4115/4120 (1세대) | `ShaCrypter` (SHA1 XOR 스트림) | 공개 |
| CXD4132 (2세대) | `AesCrypter` (AES-ECB) | 공개 |
| **CXD90014 (a5000 해당)** | **`DoubleAesCrypter` (AES-ECB 2중)** | **공개(`key_aes` + `key_cxd90014`)** |
| CXD90045 (상위 세대) | `AesCbcCrypter` (AES-CBC) + **말미 0x110바이트(IV 0x10 + 256바이트)** | 암호화 미지원(fwtool `encrypt` → 예외) |

- **CXD90014 = a5000**은 **2중 AES-ECB**로 암·복호 **양방향 모두 fwtool이 지원**한다. 실제로 원본 `.dat`를 unpack→repack하면 **SHA-256 바이트 동일** 재현됨([../boot/0001 §1](0001%20...) 참조). → **수정 이미지를 만들어도 업데이터가 받아들일 수 있는 형태로 재포장 가능**.

### 2.2 실행 단계(부트로더/커널/init)의 런타임 검증
- 부트로더/커널 측 서명 검증 코드는 **발견되지 않음**. 부트로더 덤프가 없어 정적 확정은 못 하지만, (i) init·bootin·im.elf 어디에도 서명 검사가 없고, (ii) 업데이트 자체가 서명 없이 재포장 가능하며, (iii) 공개 커뮤니티 증거(§2.4)가 이 세대의 무서명을 뒷받침한다.
- 업데이트 중 이미지 CRC 검사는 **기록 후**(`/dev/nflashaX` 재독) 수행한다([../boot/0001 §1](0001%20...)). 즉 "쓰기 전 암호학적 게이트"가 아니라 "쓰고 나서 CRC로 검산"하는 방식 → 체크섬을 맞추면 통과.

### 2.3 "체크섬(위조 가능)" vs "서명(위조 불가)" 판정
- **a5000의 모든 무결성 요소는 전진 체크섬/대칭 암호 계열**이다: CRC32(.dat), CRC32+16비트 합(FDAT), 공개 키 AES. **공개키 서명(RSA/ECDSA)은 체인 어디에도 없다.**
- 대칭 키가 공개이고 체크섬 알고리즘이 공개이므로, 올바르게 암호화·체크섬된 **임의 내용**을 만들 수 있다. 암호학적으로 막히는 지점이 **없다**.

### 2.4 커뮤니티 교차 확인 (web)
- **ma1co/Sony-PMCA-RE README**: *"Devices based on the CXD90045 and CXD90057 architectures are not compatible, since their firmware is cryptographically signed."* → **서명은 CXD90045/90057(상위 세대)부터** 도입. a5000의 **CXD90014는 그 아래 = 무서명** 버킷(명시적 배제 대상이 아님).
- **DavidBuchanan314/ILCE-7M4-RE**(훨씬 신형): eMMC는 AES-XTS 암호화, 그리고 BootROM secure-boot 언급. erlla/sony-a7m4-custom-firmware: 업데이터가 `/etc/VerificationKey.pem`로 **RSA-2048/PKCS#1v1.5/SHA-256** 서명을 검증. → **신형은 진짜 서명 + secure boot**. a5000는 이 세대가 **아니다**.
- 결론: **a5000은 "무서명/대칭암호" 버킷**. "서명을 못 뚫어서 불가능"이 아니라 "뚫을 서명이 없다".

## 3. 공식 업데이트 경로와 롤백/퓨즈(anti-rollback)

### 3.1 업데이터가 이미지를 검증·기록하는 방식 (derived)
- 업데이터 코어는 **nflasha1**(6MB plain FAT, 자체 커널+initrd)로, **업데이트로 기록되지 않는다**(복구 생명선, §5). 모드 플래그 `/setting/updater/mode`가 있으면 다음 부팅이 UFP(USB 펌웨어 업데이트)로 간다([../boot/0004](../boot/0004.%20recovery-paths-and-invariant.md), 에뮬 `RE_UPDATER_BOOT.md`).
- USB로 받은 `updater.img`가 `loader_writer.sh`/`pformat_*`로 파티션을 기록하고, config.xml 순서대로 tar 섹션을 처리, **기록 후 CRC 재독 검산**(`*_sum`: `type,crc32(zlib),size,mode,...,path`). 파티션 이미지는 TPZL(LZPT) 압축.
- 즉 "쓰기 게이트"는 **CRC 일치**이며 서명이 아니다. 올바른 CRC의 이미지는 수용된다(암호학적 차단 없음).

### 3.2 WBI와 "롤백/퓨즈 카운터"의 a5000 대응물
- 신형(ZV-E10 등)이 말하는 **WBI1 섹터 0x2C000 + 퓨즈 카운터(anti-rollback)**에 해당하는 것을 a5000에서 찾으면:
  - a5000의 **WBI(nflasha5, 60MB)**는 anti-rollback 카운터가 **아니라** **warm-boot RAM 스냅샷**이다(im.elf+라이브러리 코드 페이지의 RAM 상태, lz77, 1073섹션). 콜드/웜 결정은 부트로더/커널이 WBI 헤더+cmdline(`warm.mode`/`ignore_drop`)으로 수행([../boot/0002](../boot/0002.%20wbi-warm-snapshot.md)).
  - **퓨즈 기반 롤백 카운터는 a5000에서 발견되지 않았다**(bootin/init/boot_upm/boot_liro 어디에도 없음; `bkid_ldr_boot_mode`는 Backup propId 기반 "로더 부트 모드"일 뿐 퓨즈 아님). anti-rollback은 서명과 함께 상위 세대에서 들어온 것으로 보인다(미확정, 부트로더 덤프 필요).
- **함의**: a5000에서 플래시 수정의 장벽은 **버전 롤백 퓨즈가 아니라 WBI 정합성**이다. `/usr`(nflasha15) 등 스냅샷 대상 파일을 바꾸면 warm 재개 시 **옛 RAM + 새 파일**이 섞여 크래시한다. 따라서 플래시 수정은 (a) 스냅샷 무관 경로로 기동, (b) 정합 WBI 재생성, (c) 콜드 강제 중 하나를 **반드시** 해결해야 한다(모두 미검증).

### 3.3 쓰기 가능 vs 잠금 파티션
| 파티션 | 업데이트 기록 | 주입 관점 |
|---|---|---|
| 부트로더(0x0~0x40000), nflasha1(updater) | **아니오** | 건드리면 안 됨 = 복구 생명선(§5). 서명은 없지만 **물리 복구 불가** 리스크 |
| nflasha2(/setting, rw FAT) | 일부(템플릿 복원) | **주입 비대상이자 영속화 안식처**(§4 경로 a). 메뉴-쓰기 173개만 안전([../backup/0001](../backup/0001.%20backup-bin-structure-and-write-safety.md)) |
| nflasha3(커널/initrd/av-cam), nflasha7(/), nflasha15(/usr), nflasha16(/system) | **예** | 서명 없이 재포장·기록 가능하나 **WBI 정합성·벽돌 노출 최고** |
| nflasha5(WBI) | 예(후 drop) | 수정 시 정합성 재생성 필수 |

## 4. 주입 지점 — 벽돌 위험·우회 난이도 순위

콜드 부팅 생존 여부 / 무엇이 막는가 / 벽돌·복구 스토리를 함께.

### 경로 a — `/setting` 기반 부팅 자동 실행 (LD_PRELOAD) ★권장★
- **메커니즘**: `/setting/mode/dmode` 파일 존재 → init `check_mode_file()`가 `is_oreore_env=1` → `/setting/env.txt`를 putenv → `LD_PRELOAD`가 bootin→im.elf로 상속 → 우리 `.so`가 콜드 부팅 시 im.elf에 매핑([../boot/0003](../boot/0003.%20autostart-via-dmode-and-env.md), 에뮬 observed; 실기는 OpenMemories-Tweak이 동일 방식 사용).
- **콜드 부팅 생존?**: **그렇다**(파일이 `/setting`에 있으면 매 콜드 부팅 적용). ptrace 불필요.
- **무엇이 막는가**: 암호학적 차단 **없음**. 유일한 제약은 (i) **WBI warm 재개 시 init이 재실행되지 않음** → 상시 warm 카메라에선 평소 트리거가 안 걸릴 수 있음(실기 확인 필요, §6), (ii) ptrace 주입은 event0 입력을 죽이므로 LD_PRELOAD 방식이어야 함(이미 observed).
- **벽돌/복구**: `/setting`은 rw FAT + NAND 백업으로 **재부팅/파일 삭제로 즉시 복구**. **벽돌 위험 0**. CLAUDE.md §1 "자유 경로".
- **판정**: **최적해.** 플래시 서명·암호·WBI를 전부 우회하면서 콜드 부팅 영속을 얻는다. 플래시 수정의 거의 모든 목적을 비-플래시로 달성.

### 경로 b — 쓰기 가능·무서명 rootfs/usr 파일 수정
- **메커니즘**: nflasha15(/usr)나 nflasha7(/)의 바이너리/스크립트를 재포장(TPZL 재압축 필요)해 교체. 서명이 없으므로 CRC만 맞추면 업데이터가 수용.
- **콜드 부팅 생존?**: 그렇다(플래시 영구).
- **무엇이 막는가**: **서명 아님.** (i) **WBI 정합성**(§3.2): /usr은 스냅샷 대상 → warm 재개 시 옛 RAM+새 파일 혼재로 크래시. (ii) nflasha15 TPZL 재압축 인코더 미작성(현재 도구 한계). (iii) 부팅 시간 수용 기준([../boot/0004 §부팅 시간](0004%20...)).
- **벽돌/복구**: 중~고. 잘못된 /usr로 부팅 실패해도 **업데이터는 남는다**(nflasha1 미기록) → USB 복구 가능. 단 "검정 화면 + USB 미열거"에 빠지면 소프트 복구 상실(§5 함정).
- **판정**: 가능하지만 경로 a 대비 **이득 없이 위험만 추가**. WBI 해결 전엔 에뮬 전용.

### 경로 c — 서명된 단계 수정
- **a5000엔 해당 없음.** 서명 단계가 존재하지 않으므로 "키 필요/우회 필요"가 성립하지 않는다. (상위 세대 CXD90045+에서만 유효한 고민.) a5000에서 이 항목은 **공란**이 정답.

### 경로 d — 업데이터 경로(공식 .dat 재포장 후 USB 플래시)
- **메커니즘**: fwtool로 FDAT 복호→수정→재암호화(2중 AES, 공개 키)→CRC 재계산→`.dat` 재포장→DEND CRC32 갱신→USB UFP로 플래시.
- **콜드 부팅 생존?**: 그렇다(파티션 영구 기록).
- **무엇이 막는가**: **서명 아님(무서명 확정).** 막는 것은 (i) 기록 후 CRC 검산(맞추면 통과), (ii) WBI 정합성(§3.2), (iii) **복구 불변식**(§5) — 업데이터 자신/부트로더를 깨면 복구 불가.
- **벽돌/복구**: **최고(진짜 벽돌).** 파티션 전체를 다시 쓰므로 실패 시 영향 최대. 단 nflasha1+nflasha2 플래그 경로가 살아 있으면 재플래시 복구 가능.
- **판정**: 최종 "교체 전환" 단계에서만. NAND 백업·복구 리허설·대면·전수검증 전까지 **금지**(CLAUDE.md §1).

### 순위 정리
| 경로 | 콜드 생존 | 막는 검사 | 벽돌 위험 | 우선순위 |
|---|---|---|---|---|
| **a. /setting LD_PRELOAD** | 예 | 없음(암호학) / WBI warm 트리거 시점만 | **0** | **1순위(권장)** |
| b. /usr·rootfs 수정 | 예 | WBI 정합성, TPZL 재압축 | 중~고 | 보류(에뮬) |
| c. 서명 단계 | — | (a5000엔 서명 없음) | — | N/A |
| d. 업데이터 재플래시 | 예 | WBI 정합성, 복구 불변식 | **최고** | 교체 전환까지 금지 |

## 5. 복구 불변식 (어떤 경로든 지켜야 함)
- **생명선**: nflasha1(updater 코어, 업데이트 미기록) + nflasha2(`updater/mode` 플래그 + Backup). `/usr`·Android·`/system`을 다 지워도 **플래그가 설정돼 있으면** 업데이터가 부팅한다([../boot/0004](../boot/0004.%20recovery-paths-and-invariant.md)).
- **함정**: 플래그 세팅 소프트 경로는 USB SWITCH_MODE(메인 펌웨어가 USB/`up.sh`를 돌 만큼 살아 있어야) 또는 루트 셸뿐. "검정 화면 + USB 미열거"면 둘 다 사라지고 비-플래그 부트로더 진입(키 홀드/실패 카운터)만 남으나 **미확인**.
- **불변식**: 교체/CFW는 updater 도달 능력(USB 또는 셸)을 절대 없애면 안 된다. 실기엔 UART 없음 → 복구는 전부 USB.

## 6. 실기 확인이 필요한 미지수
1. **부트로더의 모드 결정 소스**: `/setting/updater/mode`(FAT 파일) vs `ud_send_lsi.elf`가 세팅하는 서브-LSI 상태. 플래그만 세팅(ud_send_lsi 없이)한 실기 콜드 부팅으로 판별.
2. **콜드 부팅 hand-off 실제 값**: `wbi_memclr`(PA 0x800210E8)와 부트 유닛 프리로드(0x9EC00000). 실기 콜드 직후 RAM 덤프로 확정(에뮬은 공장 BIS 스냅샷 값 1만 보유).
3. **warm 재개 하 경로 a 트리거 시점**: 상시 warm 카메라에서 `dmode`/`env.txt` 자동 실행이 실제 언제 적용되는지(init 재실행 조건).
4. **비-플래그 부트로더 복구 진입**(키 홀드/부팅 실패 카운터) 존재 여부 — 복구 안전망의 핵심.
5. **anti-rollback/퓨즈의 부재 확정**: 현재까지 a5000에서 미발견. 부트로더 덤프 없이는 "없음"을 완전 증명 불가(상위 세대엔 존재).

---

## 7. 권고
- **콜드 부팅 영속이 필요하면 경로 a(/setting LD_PRELOAD)로 충분하다.** 플래시를 쓰지 않고 콜드 부팅마다 route-b `.so`를 올릴 수 있으며 벽돌 위험 0.
- 플래시 수정(경로 b/d)은 **서명 때문이 아니라 WBI 정합성·복구 불변식 때문에** 위험하며, 최종 교체 전환 전까지 에뮬레이터 전용으로 둔다.
- 공개 커밋에는 **스킴의 클래스와 오프셋만**. 키 바이트·재포장 절차·플래시 수순은 `packages/data/re/`(gitignore)로. 본 문서는 그 공개 안전 요약이다.
