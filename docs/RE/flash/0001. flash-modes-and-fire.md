# 0001. 플래시 모드·보정·적목 + 팝업/충전/발광 기구

> 상태: **정적 분석 확정**. 근거: SDCom param 표 `packages/data/re/scalar/camera_params.tsv`·`event_tables.tsv`·`message_ids.tsv`, 엔진 object 층 `packages/data/re/ida/libObj.so.c`(ObjCamera/CamMgr/CamMsgConv), UI inventory `packages/data/re/static/inventory.md`(enum 값표). 저수준 발광 드라이버는 디컴파일 집합 밖(device-only, §5).

a5000 내장 팝업 플래시 = **엔진-소유 데이터면** 모델(focus/scene와 동형). 뷰(UI)는 **모드/보정/적목을 set**하고 **팝업·충전·자동발광 상태를 read**만 한다. 실제 충전·팝업·발광은 엔진 `ObjCamera` + 전원 서브보드가 소유한다.

---

## 1. 제어 id — 모드/보정/적목 (우리가 set)

세 축 모두 **SDCom param 축(256~388)** 에 있고 `CameraSetParameters 0x1003`(IntArray)로 set, `CameraGetParameters 0x1002`로 read. 엔진 내부로는 `libObj` ObjCamera의 PARAMID/MSGID로 내려간다.

| 축 | SDCom param id | 엔진 PARAMID / MSGID | 비고 |
|---|---|---|---|
| 플래시 모드 | **264 `strobeModeType`** (반영본 **276 `strobeModeType2`**) | `PARAMID_STROBE_MODE` / `MSGID_SET_STROBE_MODE_CMD`, 완료이벤트 `pvt_subActionObjectStrobeModeCmpEvt`(`PARAMID_STROBE_MODE_SET`/`_ACT`) | set→Cmp 비동기 |
| 플래시 보정(광량) | **278 `strobeEvShift`** | `PARAMID_STROBE_EV_SHIFT` / `MSGID_SET_STROBE_EV_SHIFT_CMD`, 스텝 `PARAMID_STROBE_EV_STEP` | ±3.0EV |
| 적목 감소 | **277 `redEyeReduction`** | `PARAMID_RED_EYE_REDUCTION_MODE` / `MSGID_SET_RED_EYE_REDUCTION_MODE_CMD` | On/Off |

> **네임스페이스 주의**(sdcom/0003 §4 재확인): 위 숫자는 **SDCom param id**다. 설정-노드 id(`FlashMode`/`FlashComp`/`RedEyeReduction` 메뉴 노드)와 다르고, 엔진 PARAMID(`PARAMID_STROBE_*`, 5자리 내부 번호)와도 다르다. set은 반드시 SDCom param id(264/277/278)로 한다.

### 1.1 플래시 모드 enum (param 264 = `strobeModeType`)
inventory `FlashMode` 값표(25값). a5000 **유효** 모드만 굵게:

| 값 | 모드 | a5000 |
|---|---|---|
| **0** | Flash Off / 끔 | ✅ |
| **1** | Autoflash / 자동 | ✅ |
| **2** | Fill-flash / 강제 | ✅ (기준 바디덤프 `264=2`) |
| **3** | Slow Sync / 저속동기 | ✅ |
| **4,5** | Rear Sync / 후막동기 | ✅ (뒤막 발광) |
| 6 | Wireless / 무선 | 핫슈 전용 → inert |
| 7~16 | Manual 1/1~1/16 (+_Rear) | 외장 전용 → inert |
| 17~21 | Manual +RedEye | 외장 전용 → inert |
| **22~24** | Auto/Fill/SlowSync +RedEye | ✅ (적목 결합) |

→ a5000엔 수동 발광량·무선 다중발광 하드웨어가 없어 6~21은 공유 펌웨어 잔재. 우리 UI는 0/1/2/3/4 + (적목 결합 시 22~24)만 노출하면 된다.

### 1.2 플래시 보정 enum (param 278 = `strobeEvShift`)
inventory `FlashComp` 값표(32값) = 두 하위 범위. **0~18** = 1/3스텝(＋3.0 … ±0.0=9 … －3.0), **19~31** = 1/2스텝(＋3.0 … ±0.0=25 … －3.0). 노출 스텝 설정(1/3 vs 1/2 EV)에 따라 엔진이 해당 범위를 쓴다. 기준덤프 `278=0`.

### 1.3 적목 enum (param 277 = `redEyeReduction`)
inventory `RedEyeReduction`: **On=0 / Off=1**. ⚠️ 기준 바디덤프는 `277=raw 2` — 팝업 내림/비가용 상태의 N/A값으로 추정(§5-3).

## 2. 팝업 — 상태 read + (엔진) 올림

- **팝업 올림 명령**: 엔진 `PARAMID_STROBE_POPUP`(`_SET`/`_ACT`) → `MSGID_SET_STROBE_POPUP_CMD`. 팝업 모터는 엔진/서브보드가 구동. route-b가 직접 올릴 필요 없음(모드가 플래시 요구하면 엔진이 처리/유도).
- **팝업 상태 read(OSD용)**: 엔진 알림 **`NID_STROBE_POPUP`** — CamMsgConv 핸들러 `libObj sub_87B074`(0x87B074). EID `0x201E`, payload `uc_StrobePopupAct`: **0 = 내림, 1 = 올림**. 엔진 내부 bool PARAMID **38396**로 변환.
- 유사 알림 **`NID_STROBE_CHARGE_ENABLE`**(EID `0x201D`, `sub_87B12C`, bool→PARAMID 38393): 충전 활성(arm) 여부.

---

## 3. 충전 — 발광 준비 상태 (OSD "charge-ready")

- **`NID_STROBE_CHARGE`** — CamMsgConv 핸들러 `libObj sub_86F2F4`(0x86F2F4). EID `0x201F`, payload `uc_StrobeChargeStatus`: **3상태 0/1/2**(미충전 / 충전중 / 완료-발광준비 추정) → 엔진 PARAMID `0x95FD`(=38397)로 변환. 알 수 없는 값은 `NID_STROBE_CHARGE : Unexpected Value` 로그.
- **SDCom 노출**: `event_tables.tsv` → `CameraEventFlashChargeEventList = 0x2 0xffffffff`, `CameraEventFlashChargeParamList = 0x1352`. 즉 SDCom 클라이언트는 **이벤트 구독(sdcom/0004)으로 param `0x1352`** 를 받아 충전 상태를 알 수 있다.
- **과열 보호**: `OFF_BY_CHARGE_MOTOR_THERMAL` caution off-factor 존재 — 연속 발광/충전 과열 시 엔진이 보호. 우리가 건드리지 않음.

---

## 4. 발광(fire)·동기 — 엔진 소유, 조치 불필요

- 실제 발광은 **촬영 시퀀스 중 엔진이 셔터/노출과 동기**해 수행. 모드가 타이밍을 결정: 일반(앞막)=발광 후 노출, **후막동기(모드 4/5)=노출 끝 직전 발광**(rear curtain). 적목(22~24)=본발광 전 예비발광.
- **EXIF 기록**: `PARAMID_NOTIFY_EXIF_FLASH`(`libObj sub...` @ `DefObjCamera::PARAMID_NOTIFY_EXIF_FLASH`, EXIF tag `0x980A`, 내부 PARAMID 38922) — 캡처 이미지에 발광 여부/모드 기록. read-only.
- **테스트 발광**: `pvt_ExeStrobeTest`(`libObj sub_59FCBC` @ 0x59FCBC) → `IssueCommandSync(cat 0x3100, msg 0x6512)` = `MSGID_SYNC_STROBE_TEST_CMD`. 즉시 1회 발광(테스트모드용). route-b 불필요.
- 따라서 **촬영 passthrough 아키텍처**([route-b-stock-osd-passthrough]) 하에서 플래시 발광은 **순정 그대로** 동작한다 — 우리는 모드만 set하고 발광엔 개입하지 않는다.

---

## 5. route-b 판정 + device-only

**판정 요약**
- 모드(264)·보정(278)·적목(277) set: **✅ GREEN** — SDCom `0x1003` RAM-only, 휘발/재부팅 복구, shooting param과 동급 안전. 우리 메뉴/퀵바에서 직접 토글.
- 팝업/충전/자동발광 상태 read: **🔶 GREEN(read)** — `NID_STROBE_POPUP`/`NID_STROBE_CHARGE`(SDCom 이벤트 `0x1352`)/`NID_AUTO_STROBE_STATUS` 구독해 OSD 아이콘(팝업됨·충전완료·자동발광예정) 표시. 엔진 알림만 소비하므로 벽돌 위험 0.
- 발광/팝업 올림/테스트: **엔진 위임** — 조치 불필요(촬영 passthrough). 직접 호출 가능하나 불필요·비권장.
- 권장 모델: **촬영 passthrough와 동일**. 순정 엔진이 충전/팝업/발광/동기를 수행, 우리 UI는 SDCom param로 모드·보정·적목을 set하고 상태 이벤트를 read해 OSD에만 반영.

**device-only / 미확정**
1. 저수준 HV 충전·발광 트리거 구동(GPIO/전원 레일) — av-cam 디컴파일에 없음, 전원 서브보드/서브MCU 소유. 촬영 passthrough면 불필요.
2. `strobeModeType`(264) 런타임 raw↔메뉴 enum 전수 매핑 — 기준점(`2`=Fill) 일치 확인됨, 나머지는 라이브덤프.
3. `redEyeReduction`(277) raw=2 의미(팝업 내림 N/A 추정) — 실기 On/Off 토글 덤프로 확정.
4. `NID_STROBE_CHARGE` 0/1/2 정확한 라벨 — 발광 후 이벤트 캡처로 확정.
