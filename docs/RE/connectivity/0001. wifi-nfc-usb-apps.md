# 0001. 연결 기능 플로우 — Wi-Fi(전송/제어/TV)·NFC·PMCA 앱·USB(MTP/PC리모트)

> 상태: **derived**(정적 RE: 펌웨어 바이너리·XML·심볼) + 일부 **observed**(에뮬). 실기 미접촉. `[?]` = 미증명, `[device]` = 실기 캡처 필요.
> 목적: 순정 6개 연결 기능 각각의 **① 진입점(control id) → ② 담당 데몬/서비스 → ③ 전송 프로토콜 → ④ route-b 판정**.
> 스택/하드웨어 레벨은 재작성하지 않음 — `emulator/docs/RE_WIFI.md`·`RE_NFC.md`·`RE_USB*.md`·`docs/RE/network/0001` 참조.
> 공개안전: 동작·오프셋·공개 API 사실만. 소유자 SSID/비밀번호/MAC/개인정보는 기록하지 않음(위치만). 원시 자료는 `packages/data/re/`(gitignore).

## 0. 데몬/서비스 지형 (한 장)

a5000 네트워크는 **독립 네이티브 데몬 3개 + im.elf 내부 인프라 + Android chroot**로 나뉜다.

| 레이어 | 무엇 | 위치 | 역할 |
|---|---|---|---|
| **orb-server** | Sony **Camera Remote API** HTTP 서버 | `/usr/bin/orb-server`(독립 ELF, `WebApiLauncher.sh`로 기동) | TCP **:10000** `/sony/{camera,guide,system}` JSON-RPC, 라이브뷰 MJPEG **:60152**. liborb(libnode/libuv) 기반 |
| **WS_SubProcess.elf** | WCM 네트워크 유저랜드 | `/usr/bin/WS_SubProcess.elf`(`network.sh`로 기동) | `wpa_supplicant`(nl80211) 소유·이벤트 파싱, `dhcpd`/`pump` 관리 (`RE_WIFI.md §2.3`) |
| **netblog.elf** | 네트워크 로그 | `/usr/bin/netblog.elf` | 진단 로깅(기능 무관) |
| **im.elf 내부 Infra** | DLNA DMS·전송 서버·MTP 응답·NetService 클라 | im.elf 주소공간(`libInfra*`, `libNetService`, `libInfraDlnaControl`) | 실제 미디어/전송/제어 처리. **독립 데몬 없음** |
| **libNetService(WCM)** | Wi-Fi 연결 상태기계 | im.elf가 호출(`CT_ID_*` 서비스) | 드라이버 load·wpa_supplicant·scan·AP연결·GO·WPS·UPnP연결·Direct device·START/STOP_FUNC |
| **Android chroot** | PMCA 앱·런처·소프트키보드 | `/android`(Android 2.3.7) | PlayMemories Camera Apps 런타임 |

핵심: **"제어(WebAPI)"만 독립 데몬(orb-server)**이고, **DLNA 서버·이미지 전송·MTP·NFC 응답은 전부 im.elf 내부**다. 전부 공통 하부
= libNetService(WCM, `CT_ID_*`) → wpa_supplicant/dhcpd(WS_SubProcess). 전송계층 트리거는 `CT_ID_ASYNC_REQ_START_FUNC`/`STOP_FUNC`(기능=WebAPI/DLNA/전송).

## 1. Wi-Fi 연결 하부 — CT_ID 서비스 (모든 무선 기능 공통)

`ui_libNetService.so`가 노출하는 WCM 비동기 요청(소유자 Backup·실기 무관, 정적 심볼 전수):

| 그룹 | CT_ID | 용도 |
|---|---|---|
| 드라이버 | `LOAD_DRIVERS` / `UNLOAD_DRIVERS` | ath6kl 체인 insmod/rmmod (`RE_WIFI.md §2.1`) |
| supplicant | `START_WPA_SUPPLICANT` / `STOP_WPA_SUPPLICANT` | station용 supplicant |
| 스캔 | `BSS_SCAN_START` / `BSS_SCAN_STOP` | AP 목록 |
| STA | `CONNECT_TO_AP` / `DISCONNECT_FROM_AP` | 인프라 AP 접속(컴퓨터 전송·TV의 인프라 경로) |
| AP(GO) | `START_GROUP_OWNER` / `STOP_GROUP_OWNER` / `..._WPS` / `CANCEL_..._WPS` | **Wi-Fi Direct GO = 스마트폰 전송/제어용 카메라 AP** |
| WPS | `START_WPS` / `CANCEL_WPS` | WPS 푸시 |
| Direct | `DIRECT_DEVICE_SEARCH` / `CONNECT` / `DISCONNECT` / `CANCEL_*` | Wi-Fi Direct 피어(스마트폰) 탐색·접속 |
| UPnP | `CONNECT_TO_UPNP_DEVICE` / `CONNECT_TO_LAST_UPNP_DEVICE` / `START_AUTO_SEARCH_UPNP_DEVICE` / `DISCONNECT_*` | **DMR(TV) 탐색·접속 = TV 보기** |
| 기능 | `START_FUNC` / `STOP_FUNC` | 상위 기능 켜기/끄기(WebAPI·DLNA·전송 서버) |
| 설정 | `SETTING_START` / `SETTING_STOP` | 설정 세션 |

→ **기능 플로우 공통 골격**: (1) `LOAD_DRIVERS` (2) GO/STA/Direct 중 하나로 링크 (3) `START_FUNC`로 해당 기능 서버 기동.
세부 pin/power/BMI/WMI는 `RE_WIFI.md §1–3`. STA↔GO 분기·dhcpd/pump는 `RE_WIFI.md §2.3`.

## 2. 스마트폰 제어 / Smart Remote — Sony Camera Remote API

### 2.1 진입점
- 무선 메뉴 "스마트폰으로 조작"(Control with Smartphone) / Smart Remote(PMCA 앱) → Wi-Fi Direct GO 기동 후 **WebAPI 기능 START_FUNC**.
- SSDP 광고: `DmsRmtDesc.xml`의 `av:X_ScalarWebAPI_DeviceInfo`(아래). `DefaultFunction = RemoteShooting`.

### 2.2 담당 데몬 + 프로토콜 (신규 RE)
`bin/orb-server` = **Sony Camera Remote API v1.0 서버**. `WebApiLauncher.sh`:
```
orb-server -f /usr/share/network/remotecontrol -p 10000 -D -1 &   (LD_LIBRARY_PATH=/usr/glib)
```
- 심볼 네임스페이스 `libj::node::orb::server::service::*` → **liborb**(libnode/libuv 기반, 빌드경로 `.../liborb/deps/libnode/...`). HTTP + SSDP(`M-SEARCH`/`NOTIFY`) 내장.
- 서비스 3개(`DmsRmtDesc.xml` `X_ScalarWebAPI_ServiceList`, 모두 `http://10.0.0.1:10000/sony`):
  - **camera** (`Remote` v1_0) — 촬영/설정 전체
  - **guide** (`ServiceGuide` v1_0/1_1 — `GetServiceProtocols`, `GetServiceInformation`)
  - **system** (`AccessControl` — `DeveloperKey`, `DeveloperInfo`, `ActEnableMethods`)
- **라이브뷰**: `X_ScalarWebAPI_LiveView_URL = http://10.0.0.1:60152/liveview.JPG` (MJPEG push, 별도 포트 60152).
- `camera` 서비스 메서드(심볼 전수, `Remote::v1_0::*` + `*_invoke_cmd`): `getAvailableApiList`, `getApplicationInfo`,
  `startRecMode`/`setCameraFunction`, `actTakePicture`/`actZoom`/`actFormatStorage`, `startLiveview`/`stopLiveview`,
  `startMovieRec`/`stopMovieRec`, `startIntervalStillRec`/`stop`, `set/get/getAvailable/getSupported` × {ShootMode,
  ExposureMode, ExposureCompensation, FNumber, ShutterSpeed, Iso, WhiteBalance, FlashMode, FocusMode, StillSize,
  PostviewImageSize, MovieQuality, SteadyMode, ViewAngle, SelfTimer, BeepMode, TouchAFPosition}, `getEvent`(+폴링용
  `GetEvent*Params` 40여종: CameraStatus, Zoom, Liveview, StorageInformation, TakePicture, …). = 공개 Sony Camera
  Remote API SDK와 동일.
- **처리 분리**: orb-server는 **HTTP↔엔진 브리지**일 뿐. 실제 명령 처리는 im.elf의 `WebApiAddonUtilsUser`(`startLiveview_oparam`,
  `getMethodType_oparam` 심볼) → "sendMsgToServer"로 im.elf 서버에 전달(로그 `[startLiveview cmd] url=%s`). 즉 orb-server는
  **라이브뷰/촬영을 자체 수행하지 않고 SDCom/엔진에 위임** → route-b가 같은 엔진 경로를 이미 보유.
- 특수 엔드포인트: `/sony/localloopback`, `/sony/shutdown`.

### 2.3 route-b 판정 → **직접 구동 가능 (권장: 자작 재구현)**
- orb-server는 플래시 비기록 독립 바이너리 → RAM tmpfs에서 **그대로 기동 가능**(벽돌 0). 단 `/usr/glib`(glibc) 의존.
- 그러나 orb-server↔im.elf IPC는 순정 im.elf UI 상주를 전제 → route-b는 passthrough 아키텍처(`route-b-stock-osd-passthrough`)와 충돌 없음. 두 선택지:
  1. **순정 orb-server 재사용**: Wi-Fi Direct GO만 CT로 올리고 `START_FUNC(webapi)` → 폰앱 호환성 100%, 우리 코드 최소.
  2. **자작 HTTP 서버**(`NATIVE_PORT_PLAN §5 W4`): Camera Remote API 와이어 포맷을 우리 바이너리로 구현 → OpenMemories 비의존 목표에 부합, 디버그 API 추가 용이. 메서드 세트는 §2.2 심볼이 그대로 스펙.
- 라이브뷰 MJPEG(:60152)은 SDCom `0x0124/0x0127`(`NATIVE_PORT_PLAN §2`)로 우리가 이미 뽑는 경로.

## 3. TV 보기 (DLNA)

### 3.1 진입점
무선 메뉴 "TV에서 보기"(View on TV) → 인프라 AP(`CONNECT_TO_AP`) 또는 Direct, 이어 **UPnP DMR 탐색**(`START_AUTO_SEARCH_UPNP_DEVICE` / `CONNECT_TO_UPNP_DEVICE`).

### 3.2 담당 + 프로토콜
- **DLNA DMS는 im.elf 내부**(`lib/libInfraDlnaControl.so`; 독립 데몬 없음 — `bin`에 dlna/dms 바이너리 부재 확인).
- 디스크립터 `share/network/dlna/`:
  - `DmsDesc.xml` / `DmsRmtDesc.xml`: UPnP **MediaServer:1**, `X_DLNADOC = DMS-1.50`, `modelName=SonyImagingDevice`,
    서비스 **ContentDirectory:1**(`/upnp/control/ContentDirectory`) + **ConnectionManager:1`. `av:photoRoot=PhotoRoot`.
    `DmsRmtDesc.xml`에는 추가로 ScalarWebAPI 서비스(§2) 임베드.
  - `DmsDescPush.xml` / `XPlsDesc.xml`: **TV 푸시** = Sony 전용 `urn:schemas-sony-com:service:XPushList:1`
    (`/upnp/control/XPushList`). 카메라→DMR로 선택 이미지를 푸시(슬라이드쇼) 하는 경로.
  - `DmsDescVideoRoot.xml` 등 = 콘텐츠 분류별 루트.
- 전송: 표준 UPnP/DLNA (HTTP-GET 미디어, SOAP ContentDirectory Browse). 아이콘 `DLNA_camera_{48,120}.{jpg,png}`.

### 3.3 route-b 판정 → **순정 유지 권장 (후순위 자작)**
- DMS 서버가 im.elf 내부이므로 외부에서 "교체"는 불가(=im.elf 수정=플래시=벽돌). route-b는 **CT로 링크만 올리고 `START_FUNC(dlna)` 트리거** 가능 → 순정 DMS 그대로 사용(벽돌 0).
- 완전 자작은 표준 UPnP/DLNA라 우리 HTTP 서버에 ContentDirectory+XPushList 추가로 대체 가능하나 우선순위 낮음(사용빈도 낮고 표준이라 재구현 비용만 큼).

## 4. 스마트폰 전송 / 컴퓨터 전송 (이미지 전송)

### 4.1 진입점
- "스마트폰으로 보내기"(Send to Smartphone): Wi-Fi Direct **GO**(카메라=AP, `START_GROUP_OWNER`) → 폰(PlayMemories Mobile) 접속.
- "컴퓨터로 보내기"(Send to Computer): **인프라 AP**(`CONNECT_TO_AP`) → PC(PlayMemories Home) 접속.
- 에뮬 관찰(`RE_WIFI.md §4`): 미디어 없으면 "This function is not available now", 있으면 진행. 컴퓨터/TV는 AP 미설정 시 회색.

### 4.2 담당 + 프로토콜
- 링크 후 `START_FUNC(transfer)` → **im.elf 내부 전송 서버**가 선택 이미지를 제공. 독립 데몬 없음.
- 와이어 프로토콜: 카메라 GO = 10.0.0.1, dhcpd가 폰에 10.0.1.x 임대(`RE_WIFI.md §2.3`). 전송이 **DLNA pull(폰이 ContentDirectory
  Browse+HTTP-GET)**인지 **Sony 전용 push**인지는 정적으로 확정 못함 `[device]`. NFC 핸드오버 후 폰이 붙는 대상이 동일 SSID이고
  (`RE_NFC.md §2.5`), PlayMemories Mobile이 Camera Remote API/DLNA 클라이언트이므로 **DLNA DMS + WebAPI 조합 pull**이 유력 `[?]`.
- "컴퓨터로 보내기"는 PC의 PlayMemories Home이 인프라 네트워크에서 카메라 DMS를 pull하는 구조 `[?]`.

### 4.3 route-b 판정 → **순정 유지(링크는 우리 트리거) / 자작은 Wi-Fi 설계에 포함**
- 전송 서버 = im.elf 내부 → 교체 불가(플래시). route-b는 CT로 GO/STA 올리고 `START_FUNC` 트리거만.
- 자작 Wi-Fi(`NATIVE_PORT_PLAN §5`)에서는 우리 HTTP 서버(W4)가 `/api/...`로 원본 스트리밍을 제공 = 자체 전송 경로. 폰앱 호환이 필요하면 §2.2/§3.2 표준을 구현.

## 5. NFC 원터치

전수 RE는 `emulator/docs/RE_NFC.md`. 기능 플로우 요지만:
- **칩**: FeliCa Plug급 동적 태그(SIO ch2, `nfc.ko`). **읽기전용 Type3 NDEF**를 im.elf `libInfraNfc`가 매 리더 명령마다 생성.
- **NDEF 내용**: `application/x-sony-pmm {SSID, 8자 passphrase}`(카메라 Wi-Fi Direct 자격, Backup `0x13E` 레코드) + AAR `com.sony.playmemories.mobile`.
- **탭 플로우**: RFDET → 폰이 블록 전부 read → InfraNfc notify `0x104` → `ObjHandover` → 모델 이벤트 `0x3A4D2001 StartCommunicationEvt` → UI가 One-touch(NFC) 지정 기능 시작(= Wi-Fi Direct GO 자격 광고 + 스마트폰 연결). 에뮬 관찰: 탭 후 "PlayMemories Camera Apps — access point 검색" 화면 도달.
- **route-b 판정 → on/off·handover 구독만 가능, 콘텐츠는 순정 고정**: 리더 명령이 im.elf의 고정 큐 `0x18104BB`로만 가므로 외부 프로세스가 태그 응답 불가(InfraNfc 교체=`/usr`=벽돌). 안전 범위: InfraNfc sync API(op 1~4)로 NFC on/off·N마크 상태(0x101/2/3) 구독, `0x104` handover 수신 시 **우리 Wi-Fi 서비스 기동**. 태그 문자열 변경(일반 WSC/URL)은 Backup SSID/PW 필드(메뉴 리셋 경로) 또는 InfraNfc 교체 필요.

## 6. PlayMemories Camera Apps (PMCA)

상세 `docs/RE/menu/0003`, `emulator/docs/RE_USB_APP_INSTALL.md`.
- **앱 모델**: `/android` chroot(Android 2.3.7) 안의 평범한 액티비티. 런처 `com.sony.scalar.dlsys.scalaralauncher.ScalarALauncher`("애플리케이션 목록"). 복원 상태 `/android/data/resume_info.txt`(`resume:<pkg>:<class>:`).
- **실행/전환 = ABT 월드 스위치**: arbiter.so `ABT_set_state(type,cmd,...)`. cmd enum: `ABT_CMD_SET_D`(Android "D" 월드)/`SET_A`(카메라 "A")/`APP_INFO`/`ANDROID_EXIT`/`ANDROID_EXIT_CMP`/`ANDROID_BOOT_CMP`, 카테고리 `ABT_CAT_PB/USB/OFF/REC`. 디스플레이는 Android SurfaceFlinger가 Rigel 윈도우 클라(`UX_WINDOW_SYSTEM_ANDROID`) 하나. `am start`만으론 화면·입력 핸드오프 안 됨(ABT 필요). `ANDROID_*` 숫자값·프로덕션 시퀀스 `[device]`.
- **런타임/샌드박스**: 표준 Android 2.3 Dalvik(zygote/system_server). 네이티브↔Android 브리지 `DAConnectionManagerService`(JNI).
- **설치**: USB `pmca-console install` = ext-cmd (5,2) NotifyScalarDlmode → 앱다운로드 가젯(`SonyMtpAppInstallDevice`, MTP ops 0x9488/9/C/D, `sony.net/SEN_PRXY_MSG:`) → TLS 터널(ProxyConnect/Data/End) → SPK 설치. 에뮬에서 end-to-end 동작(모델 수정 불요).
- **route-b 판정 → 순정/Android 유지**: PMCA는 Android 월드. route-b가 할 일은 우리 메뉴에서 "앱 목록"을 트리거(1차=ScalarALauncher 전면화, 2차=`am start -n <pkg>/<act>`)하고 복귀 시 `ANDROID_EXIT`. **OpenMemories 중단**이므로 우리의 Wi-Fi/원격은 PMCA에 의존하지 않고 §2~4 네이티브 경로로 자작.

## 7. USB 모드 (MTP vs PC 리모트)

컨트롤러·가젯 레벨은 `RE_USB.md`/`RE_USB_DEVICE_CONTROLLER.md`/`RE_STORAGE_USB.md §6`.
- **컨트롤러**: Fujitsu/Socionext **F_USB20HDC**(0xF0210000, GIC 227), HDMAC DMA. VBUS/ID = OTG glue 0xF2920000+0x10. 커널 빌트인 `f_usb20hdc_udc`.
- **가젯(VID 0x054C)**: 디스크립터는 `libusb.so .data`(`*_desc_tbl`):
  - **MTP/Mass Storage**: `usbg_storage`(BOT, PID 0x047D) · `usbg_stillimage`(PTP: PictBridge 0x034A, Auto 0x02D7). 일반 카메라 MTP 노출 PID = 0x08D3(`SonyMtpExtCmdDevice`, `RE_USB_APP_INSTALL`).
  - **PC Remote(PC 테더 제어)**: `usbg_stillimage` **PID 0x0641** — PTP 벤더 오퍼레이션으로 PC에서 촬영 제어. 오퍼레이션 세트 미해독 `[device]`.
  - 기타: `usbg_sen`(벤더 벌크 0x0336), `usbg_buspower`(0x04EF), 업데이터 0x03E2, 앱다운로드 0x06A8.
- **모드 선택 진입점**: 설정 USB 항목 → `view/USBAUTO | USBMASSSTORAGE | USBMTP | USBREMOTEPC`(`viewManagerIf::openView`, `menu/0003 §3`). "Auto"는 호스트 협상, 나머지는 강제. MSC 가젯은 `libInfraMscServer`가 `usbg_storage.ko` insmod, MTP/PC리모트 응답은 im.elf 내부 Infra.
- 연결 시퀀스: VBUS present → UI "USB 모드 – MTP 연결 중"(`viewUsbMTP.uxc`); 유저랜드가 start-gadget ioctl(0xE305) 발행(에뮬 미발행 = 열린 항목, `RE_USB §4.3`).
- **route-b 판정 → 모드 선택만 트리거, 가젯은 순정**: route-b가 `view/USB*` openView로 모드 전환 가능(벽돌 0, 메뉴 동급). 실제 MTP/PC리모트 응답은 im.elf/커널 가젯 = 유지. 우리 UI는 "연결 중" 오버레이만.

## 8. route-b 종합 판정표

| 기능 | 진입점(control id) | 데몬/메커니즘 | route-b 판정 |
|---|---|---|---|
| 스마트폰 제어 / Smart Remote | 무선 메뉴 → GO + `START_FUNC(webapi)` | **orb-server :10000** `/sony/{camera,guide,system}` + :60152 라이브뷰, 처리=im.elf WebApiAddon→SDCom | **직접 구동 가능**. 순정 orb-server RAM 기동(호환) 또는 자작 HTTP(§2.2 심볼=스펙, 권장) |
| TV 보기 (DLNA) | 무선 메뉴 → `*_UPNP_DEVICE` + `START_FUNC(dlna)` | **im.elf DLNA DMS**(MediaServer:1 CDS+CMS, Sony XPushList 푸시) | **순정 유지**(링크·트리거는 우리). 자작 후순위 |
| 스마트폰/컴퓨터 전송 | 무선 메뉴 → GO/STA + `START_FUNC(transfer)` | **im.elf 전송 서버**(DLNA pull 유력 `[?]`), dhcpd/pump | **순정 유지**(트리거만). 자작 Wi-Fi W4 HTTP로 대체 가능 |
| NFC 원터치 | RFDET → InfraNfc `0x104` → `0x3A4D2001` | **im.elf InfraNfc**(읽기전용 태그) + nfc.ko | **on/off·handover 구독만**. 콘텐츠·응답은 순정 고정 |
| PMCA 앱 | 앱 목록 → **ABT 월드 스위치** | Android chroot(ScalarALauncher) | **순정/Android 유지**(우리 메뉴가 트리거·복귀). 우리 기능은 PMCA 비의존 |
| USB MTP / PC리모트 | `view/USB{AUTO,MASSSTORAGE,MTP,REMOTEPC}` | F_USB20HDC 가젯(PID로 모드 구분) + im.elf Infra | **모드 트리거만**, 가젯 응답은 순정 |

**공통 원칙(사용자 지침)**: Sony의 영상/엔진 처리는 유지. route-b는 **CT_ID로 링크를 올리고 `START_FUNC`로 순정 서버를 트리거**하는 게 벽돌 0 최단경로. 제어(WebAPI)만 독립 데몬이라 유일하게 "우리가 직접 띄우는" 선택지가 있고, 나머지(DLNA/전송/MTP/NFC)는 im.elf 내부라 트리거/구독만 가능. **OpenMemories 중단 → Wi-Fi 전 기능은 자작 설계**(`NATIVE_PORT_PLAN §5`)로 가며, §2.2(Camera Remote API 메서드)·§3.2(DLNA/XPushList)·§1(CT_ID)가 그 와이어 스펙의 출발점.
