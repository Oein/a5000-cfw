# 0002. WBI(빠른 부팅 스냅샷)와 /usr 수정의 함정

> 상태: 공장 스냅샷 재개 **observed**(바이트 비교 + cmdline), 생성/무효화 경로 **derived**, 부트로더·커널 측은 **정적 불가(미확정)**.

## 정정 기록
초기 가설("업데이트 시 drop → 콜드 부팅 → 전원 OFF 시 새 WBI 생성")은 **틀렸다.**

## 관찰
- 실기 `nflasha5` 내용 = 1.10 펌웨어에 포함된 WBI 이미지와 **바이트 동일**.
- 커널 cmdline: `warm.mode=2 warm.ignore_drop=1 warm.boot_drop=0 warm.resume_drop=0`.
- 업데이트 순서: `partconf_sum`(us_mkfs.sh → `ud_wbi_drop`) → **그 후** `part_image`가 공장 WBI를 기록. 즉 카메라는 **Sony가 빌드 시 만든 스냅샷에서 매번 재개**하며, 평소 `/sbin/init`의 콜드 경로는 사실상 실행되지 않는다.
- 스냅샷은 `im.elf`와 라이브러리 코드 페이지 일부를 RAM 상태로 포함한다(WBI 1073섹션, RAM 127MB, lz77).

## 생성/무효화 경로 (정적)
- 캡처: `im.elf` 전원 off 핸들러(`sub_9FB4`)가 `/sys/power/state`에 `"warm"`을 기록(Sony 커널 확장). warm_count 임계 초과 시 일반 suspend(`"mem"`).
- 무효화: 업데이터의 `ud_wbi_drop.elf`.
- warm/cold 결정은 부트로더/커널이 WBI 헤더 + cmdline으로 수행 — 부트로더·커널 코드가 펌웨어 파일에 없어 의미(`ignore_drop` 등)와 헤더 포맷은 정적으로 복원 불가.

## 함의
- `/usr`(nflasha15) 등 스냅샷과 관련된 파일을 바꾸면 재개 후 **옛 메모리 + 새 파일이 섞여** 오동작/크래시 위험.
- 따라서 펌웨어 수정에는 (a) 스냅샷과 무관한 경로로 기동, (b) 일치하는 WBI 직접 생성, (c) 콜드 부팅 강제 중 하나가 필요하며 모두 미검증 → **NAND 수정 전 필수 해결 과제**.
- `/setting/mode/dmode`와 init은 **콜드 부팅에서만** 실행되고 warm 재개 시 init은 재실행되지 않는다. 상시 warm 카메라에서 `dmode=0` 단독은 효과가 없다.
- **트랙 B(RAM 프로세스 / 주입)는 WBI 해결이 불필요**하다 — warm 재개된 순정 스택 옆에서 tmpfs로 실행하고 nflasha5·/usr·/system을 건드리지 않으므로 WBI/벽돌 노출 0. WBI는 최종 "교체 전환"에서만 블로커.
- 라이브 `ud_wbi_drop` 실행이 콜드 부팅을 강제하는지, 부분 소거 이미지를 재개해 크래시하는지는 미검증이며 위험하다. 안전한 비-카메라 진입은 업데이터 모드다([0004](0004.%20recovery-paths-and-invariant.md)).
