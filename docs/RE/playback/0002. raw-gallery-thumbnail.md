# 0002. raw-gallery-thumbnail — 갤러리/리뷰 데이터 모델과 RAW(.ARW) 썸네일/프리뷰

상태: 정적 분석 확정(로컬 Hex-Rays 캐시 + 에뮬 RE 교차 + ARW 공개 포맷 지식). "RAW 썸네일 출처" 핵심 질문 결론 확정. 캐시 RAM 비용 수치·DB 바이너리 스키마 세부는 디바이스 확인 필요(명시함).

주소: `libObj+X` = `/usr/lib/libObj.so` IDA 오프셋.

## 1. 갤러리 데이터 모델 (열거·색인)

- 콘텐츠 열거는 파일시스템 raw 스캔이 아니라 **엔진의 AV 인덱스 데이터베이스**를 통한다:
  - `MprIf::GetContentInfo(mediaId, EntryCondition, EntryId, idx)` — 조건별 콘텐츠 정보.
  - `MprIf::GetAVIndexFileID` — AV 인덱스 파일 ID.
  - 상위: `ObjMedia` / `ObjCntMgr`(콘텐츠 매니저) → `MprIf`/`MprCtrl` → `libmpr`(MprIf/MMgr 스레드, `/dev/mmca*` raw). DB 모듈 = `libInfraDatabase`(InfraDatabase_Init), 풀 = `libInfraStillPool`, 캐시 = `libInfraCacheMgr`.
- **DB 위치/빌드**: SD의 Sony 관리영역(`PRIVATE/…`, `AVF_INFO`, AVCHD는 `AVCHD/…`). DB가 없거나 손상 = `PARAMID_IS_NEED_REPAIR` → **AUTOREPAIR**(`DefRootView::ActionOpenRepair`, 모델 `@M05E`)가 CMD24/25로 DB 재생성(에뮬 `RE_SD_MEDIA_SERVICE.md` §2·§6, `RE_PLAYBACK_SWITCH.md` §4). 빈/PC-포맷 카드는 DB가 없어 AUTOREPAIR가 뜬다.
- **바이너리 스키마 세부(레코드 포맷)는 미해독** — libmpr 시나리오/`/dev/mmca*` 레이어는 에뮬에서 미검증(디바이스 확인 필요).

## 2. funcMode-21 뷰 객체

- 그리드/인덱스: `ViewIndexPbToInstance` + 위젯 `PAS_ThumbNailIndex`(썸네일 그리드), `PAS_GridListCalendar`/`GEN_Calendar`(날짜별), `GEN_GridList`.
  - `PAS_ThumbNailIndex::setCacheConfigParam(PrmDimension, PrmBool, clusterUseType)` — 캐시 설정(썸네일 치수·클러스터).
  - `setGetCacheInstanceDataCb` / `getCacheInsData(contentID, …, CacheInfo&)` — 셀 이미지는 **캐시 매니저에서** 받는다(파일 직접 아님).
- 단일: `ViewSinglePbToInstance`. 레이아웃 변형:
  - `CMN_M_PLAY_STILL_WITH_FOOTER` / `WITHOUT_INFO` / `STILL_HISTOGRAM`(정지화상),
  - `CMN_M_PLAY_SINGLE_MOVIE_PLAY`(동영상),
  - `CMN_M_PLAY_SELECTED_4_SINGLE_UNABLE_TO_DISPLAY_WITH/WITHOUT_INFO` — **표시 불가(디코드 실패) 케이스** = 매립 프리뷰가 없거나 깨진 RAW/손상 파일에서 쓰이는 자리.

## 3. RAW(.ARW) 처리 — 핵심

### 3.1 썸네일 = 매립 JPEG
- 썸네일 그리드는 `MprIf::PlayThumbnail`(libObj+0x313f0) → `ObjPlayer::MSGID_PLAY_AVI_THUMBNAIL_CMD` → `PbSetupCtrl::MakeMetaDataForCacheInstance(PlayThumbnail)` → 캐시 인스턴스로 전달.
- 캡처 파이프라인이 파일에 **썸네일을 매립**한다: `InfStillEncoder [SeqResizeEnc]`가 `thumbnailAddr/thumbnailSize/thumbnailRectSize.width/height`를 기록(= EXIF/TIFF IFD1 ~160×120 baseline JPEG). ARW도 동일 EXIF 컨테이너를 가지므로 썸네일이 매립된다.
- 따라서 **RAW 썸네일 = 파일 안 매립 JPEG을 디코드**. 재현상 없음.

### 3.2 풀스크린 프리뷰 = 매립 ScreenNail
- 단일 뷰 정지화상 표시는 **ScreenNail**(축소 프리뷰 JPEG)을 쓴다:
  - 렌더러 모드 `BKID_RENDERER_L_PRM_DELIVER_MODE_STILL_PLAY_STILL_SCREENNAIL`, 타입 `STILL_PLAY_TYPE_STILL_SCREENNAIL`.
  - 캡처 시 `InfStillEncoder [SeqResizeEnc]`가 "ScreenNail"을 별도 인코드(`JpgInfo Param [ScreenNail]`, `screenNail.memHandle/offset/size`, DMM Open/Close Unit(ScreenNail)) → 파일에 매립.
  - 공개 ARW 포맷 지식: Sony ARW는 EXIF APP1 안에 작은 썸네일(IFD1) + 큰 매립 프리뷰 JPEG(= ScreenNail, 보통 1616×1080급)을 담는다.
- 즉 **RAW 풀스크린 프리뷰도 매립 ScreenNail JPEG 디코드** — 엔진이 RAW 센서 데이터를 demosaic 재현상하지 않는다. 디코드는 ObjEffect `SequencePinDeliverStillEditBase`(`CheckDecordErr(): Image Delivered / NOT Delivered / Failed to get IMAGE_ATTACH`)가 수행, 결과를 ch51 YUV로 전달.

### 3.3 엔진 RAW 재현상은 별도 기능
- `MprCtrl::IsStillRawDevelopmentSupport()`, `MprIf::PlayStillSingle(..., RawDevelopInfo*)`, `MprIf::PlayStillSingleByAddress(StillDecodeCtrlByAddress, RotateDegree, StillColorSpace)`, `InfDecoder ExecCmd_IMG_RawDevelop` / `ExecCmd_IMAGING_RawDevelop` 는 **RAW를 실제 현상**할 수 있는 경로다.
- 이는 (a) 확대(픽셀 등배) 또는 (b) RAW→JPEG 변환 같은 명시적 동작용. **기본 썸네일/프리뷰 표시는 §3.1·§3.2의 매립 JPEG**을 쓴다. 재현상은 캡처 시 IDT/FOPD 엔진(에뮬 `RE_RAW_DEVELOP.md`: IDT develop 블록 0xF3020400, OPD 0xF3030000, SA NR 프로그램) 또는 그 재생용 축약 경로를 거치며 Sony 전용·고비용.
- 따라서 RAW-only 파일이라도 매립 ScreenNail/썸네일만 있으면 갤러리는 **빠르게** 표시된다(재현상 비용 없음). 매립이 없거나 깨지면 `UNABLE_TO_DISPLAY` 레이아웃.

## 4. 썸네일 생성/캐싱과 비용

- **캐시 주체**: `InfraCacheMgr`(ObjEffect `SendCacheMgrEvent`, `Result from InfraCacheMgr`) + `InfraStillPool`. 그리드 위젯 계열은 `GEN_CacheInsBase`/`GEN_CacheInsImg`(`getCacheInsData`, `getOutCacheInstance`).
- **파이프라인**: `[PreCache] PlayThumbnail` 선인출 → 엔진이 매립 JPEG 디코드(SA JPEG dec, `sa_jpeg_dec_*`, 에뮬 `RE_SA_DSP.md` §6) → **cluster 썸네일**(`updateClstrThumb`/`setClstrThumb`)로 RAM 캐시에 적재 → 그리드가 contentID로 조회.
- **포맷/크기**: 캐시는 디코드된 비트맵(YUV/RGB), 치수는 `setCacheConfigParam(PrmDimension)`로 설정되는 썸네일 셀 크기(실측 필요). cluster = 화면 한 페이지분 썸네일 묶음.
- **RAM 비용(우리 상황 교차)**: a5000은 RAM 약 10MB 여유(참고: `route-b` 메모리 제약, memory RE). 순정 cluster 캐시는 엔진/SA 버퍼를 쓰므로 우리 주입 프로세스가 **순정 캐시를 재사용하긴 어렵다**(엔진 소유·휘발). 수치(캐시 슬롯 수·바이트)는 디바이스 probe 필요.

## 5. route-b 통합 모델 (갤러리)

- **채택: DCIM 직접 디코드(이전 앱 방식)** — 이미 구현됨: `packages/custom-binary-app/platform/a5000-inproc/playback_inproc.cpp`.
  - DCF 트리를 직접 열거(`/android/mnt/sdcard/DCIM`), JPEG/ARW 마커를 lseek 스트리밍으로 걷고 **EXIF APP1만**(≤64KB) 읽어 매립 썸네일(IFD1)·치수·날짜 추출, NanoJPEG로 썸네일만 디코드(6000×4000 원본 미디코드).
  - RAW+JPEG 동시촬영은 JPG 우선·ARW 숨김(dedup). lone ARW는 매립 썸네일 사용, 없으면 placeholder.
  - 순정 미디어 서브시스템/DB 무접촉, 읽기전용(remove 미지원), RAM-바운드, 재부팅/언디플로이 = 순정 복귀 → **벽돌-안전**. 에뮬 PLAY 경로 불안정(EE_STOP/SA 의존)과 벽돌 민감성을 회피.
- **매립 ScreenNail 활용 개선 여지**: 현재 구현은 썸네일(IFD1)만 디코드하고 풀스크린은 그 썸네일을 업스케일한다. 화질 개선하려면 ARW의 큰 매립 프리뷰(ScreenNail, APP1 뒤 또는 TIFF IFD의 큰 JPEG strip)를 파싱해 단일 뷰에서 디코드하면 재현상 없이 선명한 프리뷰 가능(§3.2 근거). — 향후 작업.
- **재현상은 불필요/회피**: RAW 데모자이크 재현상은 Sony 전용 엔진 몫, 우리가 안 함(`minimal-sony-footprint`).

## 6. 디바이스 확인 필요 항목
1. AV 인덱스 DB 바이너리 레코드 스키마(libmpr) — 우리는 DCIM 직접 스캔이라 불필요하지만, 순정 DB 재사용/정합 시 필요.
2. `setCacheConfigParam` 썸네일 셀 치수와 cluster 캐시 슬롯 수/바이트(RAM 비용 수치).
3. 실 a5000 ARW의 매립 ScreenNail 해상도/오프셋(공개 지식상 ~1616×1080; 실파일로 확정) → §5 프리뷰 개선용.
4. a5000이 실제로 기본 재생에서 RAW를 재현상하는 UI(예: RAW 확대) 유무 실측.
